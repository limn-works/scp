Storage-foundation plan (`~/.claude/plans/scp-1491-storage-foundation.md`) Step 3 landed as two commits on `refactor/actor-per-context`: `ab0985c93` (Rust threading) + `1dd5e69c1` (Swift/Kotlin SDK). Follows [[project-adr-049-storage-foundation-step2]] (PyO3) and [[project-adr-049-storage-foundation-step1]] (supervisor core). NAPI (Step 4) deliberately left broken with its single `with_providers` arg-count error.

**What Step 3 did:** UniFFI bridge threads the required 9th `mls_storage` arg into `Supervisor::with_providers`; fail-closed on SQLCipher open (no in-memory fallback); un-swallowed the in-memory storage handle in `bridge_runtime`; added `SqliteKeyMaterial { Raw | Passphrase }` (uniffi::Enum) through to Swift + Kotlin SDKs.

**Non-obvious decisions / gotchas (re-check before Step 4):**

- **`build_event_log_provider` now returns a 3-tuple.** The repo type-param SHIFTED from `ProtocolRepository<EncryptingAdapter<BridgeInMemoryStorage>>` to `ProtocolRepository<Arc<EncryptingAdapter<BridgeInMemoryStorage>>>` (new type aliases `BridgeInMemoryRepo` / `BridgeInMemoryStorageHandle` in bridge_runtime.rs). `BridgeInMemoryStorage` is NOT Clone (holds a bare `tokio::sync::Mutex<HashMap>`), so the ONLY way to share one store between the event-log repo and the `mls_storage` view is to build the repo over an `Arc` and hand the same `Arc` out. `Storage for Arc<T>` (traits.rs:557) and `EncryptedStorage for Arc<T>` (encrypted.rs:42) blankets make this work. `ProtocolRepoVariant::InMemory` in BOTH uniffi and napi had to change to `Arc<BridgeInMemoryRepo>`.
- **NAPI minimal-fixup, NOT full Step-4.** NAPI's local `build_event_log_provider` wrapper discards the 3rd element (`let (event_log, repo, _storage_handle) = ...`); its `new_napi`/`with_persistence_napi` destructures gained `, _storage_handle`; `ProtocolRepoVariant::InMemory` retyped. Result: NAPI's ONLY remaining compile error is the `with_providers` 8-vs-9 arg count (napi/runtime.rs:895) — Step 4.
- **UniFFI uses `Supervisor` (not `ContextManager`) at this HEAD.** `build_supervisor` (uniffi/runtime.rs) calls `Supervisor::with_providers`. Its 2 callers `init_supervisor_with_did` + `init_supervisor_with_relay_transport` return `()` and run on the DEFAULT instance, so the storage-before-supervisor precondition fails closed by logging + early-return (no supervisor attached → ops error) rather than propagating Result. Every constructor populates `mls_storage_backend: Some(...)`, so the `None` arm is defense-in-depth.
- **`with_storage_uniffi` now returns `Result<Self, StorageInitError>`; `Scp::with_storage` returns `Result<Arc<Self>, ScpError>`** (Swift `throws`, Kotlin throws). `StorageInitError::SqliteOpen` → `ScpError::Context` via `From`. `.expect()` on `Result<UniffiBridgeInstance,_>` needs `Self: Debug` (not impl'd) — use `let Ok(bi) = ... else { panic!() }` in tests and avoid `{result:?}` on the whole Result.
- **Swift bindings (`ScpBindings.swift`) are GENERATED but CHECKED IN.** Regenerate after any UniFFI enum change: build host dylib (`cargo build --release --target aarch64-apple-darwin --manifest-path crates/scp-ffi/uniffi/Cargo.toml --features allow_in_memory_custody`) then `cargo run -p scp-ffi-uniffi --bin uniffi-bindgen -- generate --library <dylib> --language swift --out-dir <tmp>` and copy `scp.swift` → `Sources/SCP/Internal/ScpBindings.swift`. The `ScpFFI.h` header is NOT checked in (xcframework build artifact). `swift build`/`swift test` need a binary: create a minimal macОS-only xcframework via `xcodebuild -create-xcframework -library <dylib> -headers <hdrdir-with-ScpFFI.h+modulemap> -output bindings/swift/ScpFFI.xcframework`, then `DYLD_LIBRARY_PATH=$PWD/ScpFFI.xcframework/macos-arm64 swift test`. DELETE the xcframework after (gitignored, but keep tree clean). SwiftFormat needs `--swiftversion 6.2`.
- **Kotlin uniffi bindings (`uniffi.scp.*`) are generated at build time, gitignored.** Run `./scripts/generate-uniffi-kotlin.sh --features=allow_in_memory_custody` (builds the debug dylib + bindgen into `bindings/kotlin/scp-kt/src/main/kotlin/works/limn/scp/internal/uniffi/`). Kotlin throwing fns surface as plain exceptions (no checked-exception syntax) — test fail-closed with `assertFailsWith<uniffi.scp.ScpException>`. `SCP.shutdown` takes `(bridge: CoroutineBridge, timeout: Duration)`; tests rely on `createdInstances` + `@AfterTest` cleanup, do NOT call `shutdown(1u)`.
- **Kotlin `ktlintCheck` has ~231 PRE-EXISTING violations** across CoroutineBridge.kt, ConsequenceRule.kt, conformance tests, etc. — baseline tooling drift, NOT introduced by Step 3 (zero in my files). The plan's Kotlin gate is `:scp-kt:test detekt` (both green), NOT ktlintCheck. Do not try to fix the 231 — out of scope.
