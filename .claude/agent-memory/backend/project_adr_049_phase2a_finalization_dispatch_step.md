ADR-049 Phase 2A finalization, first step landed @ `1bce95bdf` on `refactor/actor-per-context` (parent `17a6f2eb1`, the storage-foundation Step-4 tip). Switched the 3 bootstrap arms of `Supervisor::dispatch_lifecycle_direct` (Create/Import/Restore) from `lifecycle_helpers_legacy::*_legacy` to actor-shape `lifecycle_helpers::{create,import,restore}_context` (each ends in `spawn_actor_for_context`). Bootstrap now spawns a real per-context actor while still dual-writing the `contexts` DashMap.

**Why:** unblocked by storage Step 1 (`build_actor_deps` self-sources everything as 1-arg `&DID`). This is the keystone that makes contexts actor-backed at creation.

**How to apply (receiver ripple — the non-obvious part):** `dispatch_lifecycle_direct`+`dispatch_lifecycle_command` became `self: &Arc<Self>` (needed for `build_actor_deps`). That cascaded to 5 more `Supervisor` methods that call them via `&self`: `create_context`, `join_context`, `leave_context`, `restore_context`, `restore_all_contexts` — all now `self: &Arc<Self>`. Plus `lifecycle_helpers::restore_all_contexts(&Arc<Supervisor>)` and two `recovery.rs` test helpers (`setup_context`/`setup_context_with_members` → `&Arc<Supervisor>`). ALL FFI bridge callers already hold `Arc<Supervisor>`, so zero bridge edits — auto-ref resolves. If a future step changes more supervisor methods to Arc-receiver, expect the same clean ripple.

**owning_did sourcing for build_actor_deps** (only selects the per-identity KeyPackageStore actor, which import/restore never consume): create=`creator_did`; import=lexicographically-min member DID from snapshot roster; restore=min registered local DID else `DID(context_id)` seed.

Future ladder sessions should NOT re-chase these as regressions. See [[project-storage-foundation-ladder]].
