C7 PyO3 outlet-streaming FFI bridge (`crates/scp-ffi/src/outlet_stream.rs`) review-round fixes, branch `feat/outlet-streaming-ffi` (commits a6bafe451 / 665e1838a / be7f76acd atop a96940ecf, NOT pushed). Reference bridge — shape propagates to NAPI/UniFFI/WASM (C8/C9) + 4 SDKs. Complements [[project-outlet-streaming-manifest-frontier]].

**GIL deadlock in poll_next (BLOCKER).** `outlet_stream_poll_next` held the Python GIL across `block_on(receiver.recv())` while the pump's registered PYTHON handler reacquires the GIL (`mcp.rs` `Python::with_gil`) to PRODUCE the awaited chunk → guaranteed deadlock. Fix = `py.allow_threads(|| rt.block_on(...))`. **`allow_threads` requires the closure's return type to be `Ungil`; `PyErr` is NOT `Ungil`** — so the closure returns `Ungil` (`OutletStreamChunk` / `Result<_, ScpPyError>`), and `.map_err(PyErr::from)` runs OUTSIDE. Mirror the discipline at `identity.rs` (identity_rotate_key). Applied to cancel/terminate/grant too (defense-in-depth — all wake the pump). `ScpPyError` is a plain enum (no `Py`), so it IS `Ungil`.

**Live-stream FFI tests need TWO seams, not one.** A member-backed live outlet stream at the bridge boundary is blocked by TWO runtime gates, both `#[cfg(feature="testing")]` on `Supervisor`, dispatched via the actor mailbox: (1) `test_insert_member(ctx, did, "member")` — the §9.8.5 membership gate in `reserve_outlet_stream_economy`; roles are `"admin"`/`"member"` (NOT `"owner"`). (2) NEW `test_grant_member_capability(ctx, did, "outlet_call:*")` — the runtime pump ALSO enforces a role-state capability gate (`has_outlet_invocation_capability`, `invoke.rs`) as defense-in-depth alongside the UCAN; **default roles grant only `messages:*`, so a member with a valid delegated UCAN is STILL `InvokerNotAuthorized`.** The new seam inserts `Capability::OutletCallAll` into `role_state.member_capabilities` via `commit_class_s_keep` whole-state `rest_mut()` (the Class-C `role_state_class_c_mut()` view deliberately hides `member_capabilities_mut` — F2 shrink-hole protection; a persisted GROW is safe). Use a ZERO-cost outlet (`build_outlet_reg` sets no cost) to avoid needing a budget-funding seam. Declare `estimated_chunk_count=Some(1)` or the coerce-to-`u32::MAX` trips SCP-OUTLET-6120. scp-ffi tests need `--features scp-ffi/allow_in_memory_custody,scp-ffi/testing` (testing = scp-core/testing → scp-runtime/testing).

**DEBUGGING GOTCHA: `reserve_error_to_open_rejection` catch-all (`outlets_helpers.rs`) maps EVERY unmatched ContextError to `AdmissionRateLimited{transport.rate-limited}` (SCP-OUTLET-6160).** And `open_stream_session` swallows `invoke_outlet`'s error (`let _ = err`) into the same 6160. So a bare "SCP-OUTLET-6160 transport.rate-limited" open rejection can actually be membership / capability / any error. To diagnose, temporarily `eprintln!` at the catch-all AND at the `invoke_outlet` map_err in `dispatch.rs`.

**grant_credit: bridge signs INTERNALLY (MAJOR).** Old `grant: &[u8]` (caller pre-signs `OutletStreamCredit` + tracks monotonic_seq) is UNAUTHORABLE — needs invoker-key exposure (ADR-006 violation). New surface `grant: u32`; bridge computes `compute_credit_sig_preimage` + signs via custody (`BridgeCustodyStreamSigner`, like cancel — custody NEVER exposes the raw `SigningKey`, so `sign_credit_grant(SigningKey,...)` is UNUSABLE), auto-assigns `monotonic_seq` from a per-`StreamEntry` `AtomicU64` (fetch_add, first grant = seq 0). `StreamEntry` now pins `request_id`/`stream_epoch`/`cost_per_chunk` for the preimage+reserve (must equal the runtime `StreamIdentity` pins — same open-time values). Spec §5.4.5 FFI-bridge-caller-auth clause (05-contexts.md:547) mandates `caller_did` param + bridge-side signing.

**Grant-time escrow reserve (MEDIUM budget hole).** A grant extends the billable credit window, so it MUST debit escrow or the operator bills beyond held funds. New `Supervisor::outlet_stream_reserve_grant` (pub, → `OutletsCommand::ReserveStreamGrantEscrow` → `reserve_stream_grant_escrow` helper) DEBITS `cost_per_chunk × grant` from the invoker's `MemberBudgetTracker` (checked_mul→EscrowOverflow; balance→InsufficientFunds; NO hard-rate/velocity/membership — admission-time only). `outlet_stream_reverse_grant` = pub wrapper over pre-existing `reverse_stream_escrow_via_actor`. Bridge flow: reserve(DEBIT) → sign+`apply_credit_grant(credit, reserved)` → reverse-on-reject. Money-conservation `billed+refund==reserved` across open+grants; the HARD billing backstop is the caveat ceiling `CreditTracker::max_billable = min(credit_window, max_calls)`, NOT `billed≤reserved`. `reserve_stream_grant_escrow` is a runtime-internal `pub fn` → trips check-cross-layer; needs PR-body `[cross-layer: pub-crate-visibility] reserve_stream_grant_escrow` marker (PR_TEXT is read from `$PR_BODY`/`$PR_BODY_FILE` only — empty locally).

**Grant crash-recovery (review round-2, commit 66b3fe424).** The grant budget debit is durable, but the durable crash-recovery record `class_s.stream_reservations[hex(request_id)].reserved_escrow` is set ONCE at open (dispatch.rs:2383, `params.reserved_escrow`) and reconcile (`reconcile_stream_reservations`) refunds THAT on crash. A grant top-up lives only in the EPHEMERAL pump escrow ledger (`SharedSessionState`), which dies on crash → reconcile refunds only the open hold → invoker OVER-charged the cumulative grant. FIX: `reserve_stream_grant_escrow` bumps `record.reserved_escrow += cost×grant` ATOMICALLY with the budget debit. MUST use `commit_class_s_compensating` (NOT `_keep_compensating`): the keep variant's compensation gets a Class-C-only `ClassCMut` and CANNOT reach `class_s.stream_reservations` (Class-S) to un-bump on persist-fail; the compensating (restore) variant snapshots+restores Class-S (un-bumps) AND runs the Class-C compensation (reverses budget). Because the reserve now bumps the record, the apply-reject REVERSE must un-bump it too (else crash→reconcile double-refunds) — new `reverse_stream_grant_escrow`/`ReverseStreamGrantEscrow`/`Supervisor::outlet_stream_reverse_grant` (request_id-keyed) credits budget + un-bumps record atomically (`commit_class_s_keep`, saturating). Zero-escrow-at-open stream (declared estimate 0) has no record → first grant CREATES one (or_insert_with, empty ucan_cid). Settle refunds against the pump LEDGER (open+grants) + clears record; reconcile refunds against the RECORD — so record must track ledger. request_id threaded bridge→supervisor→command→handler→helper.

**Live-poll GIL test was VACUOUS (bug-catcher, 62891223d).** grant_credit has its OWN allow_threads, so granting BEFORE the poll loop let the pump buffer both chunks into the mpsc channel → poll_next read a buffered chunk without the pump running during poll → reverting poll_next's allow_threads still passed. FIX: the FIRST poll_next must run BEFORE any grant (credit_window≥1 admits the first Data chunk with no grant) so it parks on the live pump. Verify a GIL-deadlock guard by reverting ONLY poll_next's allow_threads → must HANG (cargo exit 124).
