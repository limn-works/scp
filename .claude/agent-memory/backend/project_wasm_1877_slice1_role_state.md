WASM convergence slice 1 (#1877): `crates/scp-ffi/wasm/src/manager.rs` `PerContextState` adopts `scp_protocol::context::roles::ContextRoleState`, deleting flat `members: HashMap<String,MemberEntry>` / `ceiling_strings: HashSet<String>` / `suspended_capabilities: HashMap<String,HashSet<String>>` / `creator_did`, and the methods `member_has_capability` / `capability_to_ucan_format` / `build_ceiling_strings`. Branch `wasm/1877-slice1-adopt-context-role-state`.

**Why:** WASM reimplemented role state as a hardcoded role-name match; native uses ContextRoleState. The reimpl skipped role-against-role_definitions validation → #1886 divergence (undefined/out-of-ceiling roles silently accepted on WASM). Adopting the shared type fixes #1886 by construction (system_assign_role validates role exists in role_definitions + mint-time ceiling check).

**How to apply (load-bearing facts for any future WASM↔protocol convergence work):**
- ContextRoleState `ceiling` + `suspended_capabilities` are `pub(crate)` (ADR-049 §9 Class-S). WASM is a different crate → MUST use public methods: `ceiling()`, `set_ceiling()`, `member_has_capability(did,&Capability)`, `system_assign_role(&mut self,did,role,&dyn Clock)` (inherent METHOD form at roles.rs ~1183, not just the free fn), `suspend_capabilities`, `suspend_all`, `restore_capabilities`, `suspended_for`. `members`/`assignments`/`member_capabilities`/`role_definitions`/`context_id`/`creator_did` are public fields.
- VERIFIED EQUAL: `default_ceiling().to_ucan_string_set()` == WASM old `build_ceiling_strings(empty)` default set, exactly (10 strings incl `tool_invoke:*`, `tool:register`, `context:close`). Format-preserving → UCAN wire unaffected. Do NOT change the UCAN ceiling-string form.
- **SEMANTIC GOTCHA (admin live-ceiling vs snapshot):** old WASM admin capability = `in_ceiling(cap)` read of the LIVE `ceiling_strings` at check time. ContextRoleState admin = `member_capabilities` SNAPSHOTTED at assignment time (`builtin_admin(ceiling)`). Tests (`make_bare_per_context_state` builds EMPTY ceiling, then `test_insert_ceiling` adds caps, then expect admin to hold them) + the production `ModifyCeiling` single-phase path rely on live-ceiling. Adopting ContextRoleState REQUIRES re-deriving role_definitions from the new ceiling AND re-running system_assign_role for every member whenever the ceiling changes (set_ceiling + test_insert_ceiling). Otherwise `apply_suspend_all` (iterates ceiling × member_has_capability) and admin checks silently return empty.
- The per-member MLS message `sequence_number` (was `MemberEntry.sequence_number`) is ENCRYPTION state, not role state, has NO home in ContextRoleState → must survive as a NEW `member_sequence_numbers: HashMap<String,u64>` field. Get/increment in publish_broadcast (~5074) + send paths.
- **WIRE FORMAT INVARIANT:** `WasmContextExportSnapshot` (manager.rs ~6893) is the SIGNED export struct (§23.16.8, Ed25519 + HMAC over JCS). Its flat `members: Vec<WasmExportMember>` / `ceiling_strings: Vec<String>` / `suspended_capabilities: HashMap<String,Vec<String>>` fields MUST NOT change. export_context translates role_state→snapshot; import_context translates snapshot→ContextRoleState (build via `new`, then insert members + system_assign_role per member, set_ceiling, suspend) + member_sequence_numbers. canonicalize_snapshot_sets + all snapshot-only tests (snapshot_with_sets ~8335) stay untouched.
- #1886 fix sites: governance ChangeRole/AddMember/TransferAdmin/ResetMember arms (manager.rs 3314/3425/3584/4165) + consequence.rs `apply_assign_role` (~271, currently free-form `role.clone_into` with NO validation — its docstring explicitly admits accepting unknown roles). Route through system_assign_role; map RoleError→ScpWasmError (governance) / →false (consequence actuator returns bool).
- SCOPE GUARDS (next slice, do NOT do): no RoleAssigned durable leaf on WASM ChangeRole; no two-phase governed-ceiling deferral (keep single-phase set_ceiling); no shared-governance-helper extraction. No leaf/event-count changes.
