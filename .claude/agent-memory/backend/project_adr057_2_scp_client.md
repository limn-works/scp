**Why:** prove the participant path (create/join/add/send/receive-decrypt/process-commit/close + event-log leaves) runs single-threaded over shared scp-mls, no actor/tokio. Restore deleted WASM bridge SHAPE (`1a3b41a5e^:crates/scp-ffi/wasm/src/manager.rs` + `crypto/state.rs`) but call shared bodies — one impl, two targets, no parity tax.

**Crate structure:** client.rs (ScpClient: HashMap<ctx,PerContextState> + injected Arc<dyn Signer>/Storage/Clock + pending_joins map for join material); crypto_state.rs (ContextCryptoState = ScpMlsGroup + sender_key_store + recv_sequence_tracker; double-encrypt pipeline = sender-layer encrypt→16B epoch||seq header→MLS encrypt; receive = MLS decrypt→parse header→epoch-poison ceiling→replay tracker→sender decrypt); context.rs (PerContextState: event_log + members + member_sequence_numbers + event_buffer VecDeque; committer-assigned convergent leaf timestamps); signer.rs (Signer trait + LocalSigner — DID identity, WebCrypto custody slots in later); storage.rs (Storage trait + MemoryStorage — IndexedDB later); error.rs (ClientError #[from] MlsError/SenderKeyError/EventLogError).

**KEY scp-mls seams used (all already public, NO new MLS-op seam needed):** create_group/generate_key_package (returns (KeyPackageBundle,SignatureKeyPair,InMemoryMlsProvider))/add_member (KeyPackageIn→AddMemberResult{commit,welcome}, auto-merges)/join_group_from_bytes (wire variant, takes raw bytes — use THIS not join_group which needs &MlsMessageOut you can't deserialize)/encrypt+serialize_ciphertext/decrypt_with_sender_did (returns DecryptedContent Application/Commit/Proposal — perfect receive+classify). Sender layer fully in scp_protocol::crypto::sender_keys::encrypt (build_sender_header/parse_sender_header/encrypt_sender_layer/decrypt_sender_layer) + SenderKey::from_bytes/as_bytes + SenderKeyStore.

**2 TRIVIAL scp-mls seams I ADDED (widening existing logic, both wasm32-safe, tested):**
- `group::key_package_in_did(&KeyPackageIn, ProtocolVersion)->Result<String>`: validate + read unverified leaf BasicCredential → ScpCredential::from_bytes → did. Parallels add_member/decrypt_with_sender_did extraction. Lets driver name joiner from wire KeyPackage, not a supplied DID. (openmls `KeyPackageIn::unverified_credential()` + verified `.leaf_node().credential()` are public.)
- re-export `pub use openmls_basic_credential::SignatureKeyPair` from scp-mls lib.rs (it's in generate_key_package/join_group signatures; consumers shouldn't need a hidden openmls_basic_credential dep).

**Convergence proof (the crux — got it WRONG first):** leaf_hash includes sequence + prev_hash (history-dependent), so a creator's MemberJoined leaf (seq1, prev=created-leaf) and a fresh joiner's MemberJoined (seq0, prev=GENESIS) CANNOT match — per-leaf-at-different-position is protocol-impossible. CORRECT model: joiner REPLAYS the adder's full event stream (AddMemberOutput carries event_log: Vec<Event> + members) via PerContextState::replay_event→append_unsigned_event (chain-validated). Then both hold identical [ContextCreated,MemberJoined,MessageSent] → byte-identical leaves AND equal roots. This is §7.3.1 context-state import, real participant work. Convergent timestamp travels WITH each message: add_member/send_message return committer_timestamp_secs; receiver stamps the SAME value (test gives the two members DIFFERENT local clocks to prove convergence ≠ clock-agreement).

**MISSING SEAM (reported, NOT built — out of scope, pre-existing gap):** no in-tab cross-member sender-key DISTRIBUTION path (driver send emits only double-ciphertext, never the sender key). ADR-057 defers HPKE-sealed distribution over MLS scp_wrapping_key leaf extension to a later slice. MVP test wires it out-of-band (local_sender_key_bytes/install_sender_key = the dumb-pipe hand-off). This is a distribution gap, NOT a missing scp-mls MLS-op seam.
