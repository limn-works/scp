# §5.15.8 Standing-Pair (single-context async) reframe review — spec/standing-pair-not-a-saga-v2 @37cf92e51

Branch reframes standing-pair creation from saga to single-context async create. Bug-catcher findings on the normative machinery:

- **HIGH — did_hi initiator has NO defined Ok-return / steady state.** Single-creator rule: did_hi MUST NOT create, "issues as a request to fetch/await did_lo's Welcome." But `standing_context` Ok-return contract says Ok = "initiator's replica created and Welcome dispatched." did_hi creates nothing and dispatches nothing. Spec never says what did_hi's call returns, when, or what it holds if did_lo never sends a Welcome (did_lo offline/blocked-did_hi/declined). The never-joined steady-state + reaper + get-or-create re-drive are all written exclusively from the *creator's* (self-only group) perspective — none apply to a did_hi awaiter that holds NO group. Gap: did_hi awaiter can hang/leak with no terminal state defined.
- **HIGH — collision-resolution predicate "self-created, un-joined, peerless" can destroy a group did_hi legitimately created as a 2-member group it OWNS… no — but it CAN fail to fire when did_hi's group already advanced.** The real defect: predicate requires did_hi's group be "peerless" (1-leaf). But did_hi (rule-violator) creates a 1-leaf group then `add_member`s did_lo per the create flow → did_hi's group becomes 2-leaf (did_hi + did_lo-as-added-member) and did_hi emitted a Welcome to did_lo. Now did_hi's group is NOT "peerless" → collision clause does NOT fire → did_hi keeps its own group AND also can't cleanly process did_lo's inbound Welcome (already holds group under that id). Two surviving groups, mutual Welcome rejection — exactly the state the rule claims to prevent. "Exactly one group survives" is violated.
- **MED — collision destroy vs. never-joined "equivocates against no peer" both assume no Welcome emitted, but did_hi-as-rule-violator emitted a Welcome to did_lo before collision detected.** did_lo received did_hi's Welcome → did_hi DID publish something a peer observed. Destroying it is no longer "local-only state no peer observed."
- **MED — get-or-create self-only re-drive vs. collision rule interaction undefined.** A self-only-no-Welcome did_hi group: re-drive says "re-run add_member + Welcome-emit." But single-creator rule says did_hi MUST NOT create/add_member. The re-drive paragraph is creator-agnostic and contradicts the did_hi-must-not-create rule for a did_hi-owned self-only group.
- **LOW/NIT — default-deny consent self-consistent** with §5.12.2 (strangers never auto-accept). OK.
- **Authenticity-anchor vs Phase-2E:** consistent (Welcome binding is anchor; joiner can't send until 2E). OK.
