# SCP-OUT-036 cross-context outlet-stream bridge review (commit 9475d6d82, branch feat/outlet-xctx-036-bridge)

`run_cross_context_bridge` in invoke.rs (~4470-4593). Best-effort B→A no-buffer forward (bounded mpsc(1)).

**MEDIUM — no terminal synthesized for A when B's inner_rx closes WITHOUT a terminal chunk.**
The loop's 3 explicit break paths (sig-verify fail→6140-auth, fault probe→6160, schema→6140) each `forward_bridge_terminal` a synthesized terminal to A. The 4th exit — `inner_rx.recv()` returns None because B's dispatch pump dropped its sender without an End/Error — falls straight to `record_cross_context_a_event`, forwarding NOTHING to A. Reachable: B's pump `try_build_signed_chunk` returns None on operator-signer failure and "breaks the pump loop without emitting" (dispatch.rs:2510-2540), incl. the terminal chunk. Result: A's invoker/other-members get a truncated terminal-less stream; A's audit log records `StreamTerminalSummary::default()` = Error(EXECUTION_FAULT) — delivered stream vs recorded terminal DIVERGE; consumers can't detect clean-vs-truncated close. Fix: post-loop, if no terminal delivered to A AND outer_tx still open, forward a CODE_TRANSPORT_FAULT (6160) terminal before recording. Track with explicit `delivered_terminal`/`outer_open` flags (terminal_status default-Error can't distinguish this from a real Error(EXECUTION_FAULT) terminal).
