CRYPTO-22 / #2187, branch `crypto-22-attestation-spec` @26b45229c (spec-only). Replaces §9.7.1 "MLS leaf signature_key IS the DID #active/#agent key" with: ephemeral context-scoped MLS leaf key + a `#active`/`#agent`-signed **KeyPackageAttestation** (LeafNode extension `scp_keypackage_attestation`, type 0xFF03, §9.5.2/§9.18.6/§9.18.2) binding {context_id, did, leaf_signature_key, signing_key_id, issued_at, expires_at} to the DID.

**TOP FINDING (UNSOUND, firm): `context_id` (field 1) is a category error.** The attestation is minted "once at KeyPackage generation" and rides IN the KeyPackage leaf, frozen by the leaf self-signature. But SCP KeyPackages are genuine OFFLINE PRE-KEYS: `scp-mls::group::generate_key_package(credential, clock)` takes NO context_id; the KeyPackage actor (`key_package_actor.rs` handle_generate/handle_publish) pre-generates a pool from `credential` only and publishes per-`owner_did` (NOT per context); `add_member(group, kp)` lets an arbitrary future ADDER consume it into the ADDER's context. The joiner does not know the context at mint time → cannot bind it. Same spec line reaffirms the offline model ("add the identity to groups even when offline"), so the field self-contradicts. LeafNode-extension placement (which makes the leaf immutable-from-KP-gen) is exactly what makes context_id unfulfillable. Also REDUNDANT for the creator/update path: `create_group_with_context` already binds context as a GroupContext extension (0xFF02 `scp_context_params`, §5.13.3) at the group level, which MLS covers. Fix = DROP context_id; minimal correct scope {did, leaf_signature_key, signing_key_id, issued_at, expires_at} is context-independent, mint-time-knowable, uniform across creator/joiner-KP/Update leaves, and sufficient for the ADR's stated goal (admission/attribution binding: "the leaf provably belongs to the DID"). No anti-transplant value is lost — you can't get anti-transplant on an offline KP anyway, and context AUTHORIZATION is UCAN/governance, not this attestation.

**SOUND (rest of design):** (2) LeafNode-extension placement — mirrors 0xFF01 scp_wrapping_key precedent, no circularity (attestation signs the leaf PUBLIC key, available before the self-sig; self-sig then covers the attestation bytes — clean X.509-in-TLS nesting, not circular). (3) field sufficiency minus context_id — binding only leaf_signature_key is enough because leaf self-sig covers the whole leaf and verifier checks attestation.leaf_sig_key == leaf.signature_key. (4) ephemeral-leaf+attestation vs rejected leaf==DID (A raw export breaks HW custody; B async sign blocked by openmls sync Signer wall) — both rejections genuine; `resolve_signing_key` (scp-mls/src/credential.rs:154) VERIFIED zero production callers so "never implemented, reconciling spec to as-built" is accurate.

**MINOR QUESTIONS:** creator's initial leaf is made by `create_group_*` (MlsGroup::new), NOT `generate_key_package` — so spec's "produced once at KeyPackage generation" + "expires_at matches KeyPackage Lifetime.not_after" don't cleanly cover the creator leaf (no KeyPackage there). Attestation-mint hook needs create_group + Update + generate_key_package. ADR cites `crates/scp-mls/src/credential.rs:157` (actual 154, trivial).

**SECOND PASS @20f7a036b (fix commit, CONFIRMED-RESOLVED, clean):** All findings addressed, no new unsound premise. (1) `context_id` FULLY removed — field table now 5 fields {did, leaf_signature_key, signing_key_id, issued_at, expires_at}; §9.5.2/§25.22/ADR-057 all say "context-agnostic"; verification steps 1-6 reference NO context; group-scope binding correctly delegated to 0xFF02 scp_context_params GroupContext ext (weaker+correct group-level claim, not the impossible per-member mint-time claim); context AUTHORIZATION stays in credential UCAN, untouched — no dangling dependency. (2) ALL THREE mint sites now stated explicitly: (a) create_group creator leaf (LeafNode Lifetime, no KeyPackage wrapper), (b) add-time generate_key_package, (c) every PCS Update; issued_at/expires_at reworded to leaf `Lifetime.not_before`/`not_after` (NOT KeyPackage.Lifetime) so it covers the wrapper-less creator leaf; verification step 5 enforces equality to leaf Lifetime. (4) field set minimal AND sufficient — signing_key_id load-bearing (resolves VM + step-4 credential/attestation VM-equality anti-key-confusion); binding only leaf_signature_key suffices because leaf self-sig (by that ephemeral key) covers whole leaf incl. init/HPKE key + Lifetime → attacker can't swap init key without K's private key.
