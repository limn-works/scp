# ADR-062 Slice 11 relay DID resolution — SCPR + Model-A design interrogation @04c666220 (branch feat/adr062-slice11-relay-querier)

Interrogated 4 author decisions. Spec §9.10.12 (SCPR) + §3.10.8 edits are on the BRANCH (commits 7e05ed15e/f4e1e2d08/38d0e2f74), NOT yet on main. ADR-062 IS on main but its 6 SCPR/§9.10.12 refs were ADDED on this branch (co-authored w/ spec — correct flow: spec→ADR→slice).

**Q1 SCPR wire format (vs #482 "no new format"): JUSTIFIED core, QUESTION on extensibility.** #482's premise NEVER-HELD: a relay blob must self-carry (value,signature,seq) so resolver BEP44-verifies from blob alone (relays have no BEP44 slot semantics like DHT); bare-blob publish = unverifiable. Cross-binding byte-reproducibility (hand-rolled BEP44 verify) forces exactly ONE canonical encoding → rules out self-describing codecs. So a format IS required. Raw-frame vs BEP44-bencode-dict defensible: k omitted (derivable), fixed-offset binary EASIER to reproduce than bencode dict (BEP44 already hand-rolled raw in scp-dht/lib.rs:121 `3:seqi..e1:v..`, NO bencode crate). QUESTIONs: (a) spec's "avoid 2nd bencode dialect" rationale imprecise (no crate to import); real reason = byte-repro + k-omission. (b) multi-kind taxonomy (kind2 KeyPackage "reserved", versions, "kinds 3-255 assigning=spec change") is PERMANENT wire commitment leaning on UNFILED future ("tracked as future issue to be filed") — mild No-deferral/premature-generalization tension. Not DOA.

**Q2 Model A (relay opaque, no verify, no single-highest-seq slot): UNSOUND as basis for suppression-resistance CLAIM.** routing_id=SHA-256("scp:did:"||did) is PUBLIC → any unauthenticated party writes any blob there. VERIFIED storage.rs:403-407 `sort_by_key(stored_at)` ASC (oldest-first) + `truncate(limit=16)`; client MAX_DID_RECORD_QUERY_BLOBS=16, composer MAX_RELAY_CANDIDATES=16. ATTACK: pre-plant ≥16 well-framed bad-sig frames (distinct blob_ids trivial) w/ earlier stored_at → relay returns 16 oldest (all decoys) → genuine record TRUNCATED OUT → all candidates fail verify → relay layer yields nothing. Cost: 16 blobs/relay/DID re-planted per 7d TTL, NO relay compromise. Author's shadow-DoS fix (38d0e2f74: return ALL candidates+verify) defeats 1-frame shadow but is DEFEATED BY FLOODING PAST THE CAP — the cap bounding the DoS also bounds the defense. Net: relay layer's INDEPENDENT suppression-resistance ≈ ZERO; it's a LATENCY cache. DHT is the real backstop (BEP44 DHT nodes verify+single-highest-seq, floodproof).

**Q3 relay BEP44-verify of public DID records vs "dumb pipe" tenet: NOT a violation; premise SMUGGLED.** Tenet ("encryption-as-access-control, relays untrusted dumb pipes") scopes CONFIDENTIALITY (can't read MLS), not a ban on validating PUBLIC self-cert data. PRECEDENT VERIFIED: relay/bridge.rs `register()` already BEP44-verifies Ed25519 sig, rejects invalid (registry_register_invalid_signature_fails), derives DID from pubkey. "Untrusted" cuts both ways → resolver ALWAYS re-verifies regardless, so relay-verify = defense-in-depth availability, not trust delegation. §9.10.12's "no relay change permitted" is a MINIMALITY choice, not a tenet requirement.

**Q4 spec internal consistency: NO, two breaks.** (1) DESIGN: §3.10.8 "attacker must suppress ALL relays AND DHT, strictly harder" INCONSISTENT w/ Model-A cheap relay suppression — technically true (still need DHT) but materially misleading; relay term ~free. (2) LIVENESS/phantom: §3.10.8+ADR-062:94 claim resilience RESTORED when both halves land. VERIFIED: READ half (RealMultiRelayQuerier<TransportRelayQuerier>) production-LIVE all 3 bridges; WRITE half production-INERT — sole caller publish_did_record_to_relay is #[cfg(feature=testing)] only (in publish_to_resolver_dht_for), NO production RepublishManager (§3.10.5 6-day cycle zero non-test construction). Prod relays get ZERO DID frames → live querier reads always-empty store. EXACTLY the "empty half falsely claiming restored resilience" ADR:94 forbids. Root: Decision-6 fail-closed prod create + unwired RepublishManager. (Prior inquisitor r2 flagged same write-inertness.)

**SUBTLE Q1↔Q2 LINK:** SCPR omits pubkey k ("derivable from DID string") — but the RELAY has only routing_id=HASH(did), NOT the did_string, so k is NOT derivable relay-side → relay can NEVER BEP44-verify under current framing. The k-omission Q1 touts forecloses Model B. Model B needs carrying pubkey/did to relay (32B) = a real relay-protocol change + cost — the honest reason Model A is attractive, but it costs the security property.

**RECOMMENDATION:** Either (A) Model B for DID records — relay verifies SCPR BEP44 sig on PUBLISH (needs pubkey carried) + single-highest-seq slot per routing_id (mirror BEP44 DHT); only way relays earn §3.10.8's conjunction; amend §9.10.12 "not permitted" upstream first. OR (B) keep Model A, DOWNGRADE §3.10.8 to honest "relay=latency/availability optimization, DHT=sole suppression-resistant layer." Independently: WIRE the write half in prod or relay layer is dead weight; don't claim restored resilience until live. Lean (A).
