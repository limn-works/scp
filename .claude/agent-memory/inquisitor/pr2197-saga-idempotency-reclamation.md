# #2197 spec: saga-open idempotency + bounded seal-phase reclamation

Commit a585ab9f3 (feat/outlet-2197-spec). Spec-only, runtime deferred. Files: 05§5.4.5/§6.2.5, 06§6.2.4, 09§9.18.B, ADR-061 addendum, ADR-049 §3a cross-ref. Fixes streaming-saga orphan-reserve/double-reserve money-safety defect. Three reviewers pre-cleared correctness/crypto/alignment; I interrogated DESIGN PREMISES only.

**Verdict: INTERROGATE FURTHER. 4 SOUND premises, 1 QUESTION (knob accretion), 1 real gap (cross-store atomicity, Q5).**

- Q1 A-side locus: SOUND ON MERIT, not convenience. Prepare-A escrow debit happens at initiator BEFORE PreparingB; B-side dedup (at Prepare-B) is downstream so it structurally CANNOT prevent A's double-reserve nor resume (B only rejects). Locus forced by money mechanics. Strong premise.
- Q2 two anti-replay loci: SOUND + coherence note. A-side index (principal+nonce, resume/tombstone) vs B-side per-target nonce-dedup (cross-node forward replays B must independently reject) genuinely distinct; R6 forbids purging B, tombstones A instead. NONCE now TRIPLE-OVERLOADED (B-dedup wants uniqueness / A-resume wants reuse / signed into receipt preimage) — reconciled ONLY by strict A-before-B short-circuit ("resume never reaches Prepare-B") = load-bearing invariant. DRIFT SURFACE: grace-window coupling "A grace >= max(B nonce-dedup TTL, seal max-duration)" is a manual cross-locus invariant, not mechanically enforced.
- Q3 three timers: idle deadline GENUINELY NEEDED (verified dispatch.rs:3108 — non-parked branch blocks on inner_rx.recv() with credit_stall_armed_at=None; silent executor/wedged forward channel wedges forever, credit-stall never arms). BUT stream_seal_idle_secs strict-greater-than credit-stall + config-rejection rule + deployer-raise obligation + "6136 wins any tie" paragraph all exist ONLY for recorded-code determinism in a measure-zero tie (money outcome identical). Disproportionate machinery for an audit label. QUESTION: consider deriving/clamping the floor (idle = max(cfg, credit_stall+margin)) rather than free-knob+reject. max-duration correctly a governance knob.
- Q4 900s default + min composition: SOUND. effective=min(timeout_ms, cap*1000) means caller can only SHORTEN, operator owns the ceiling — correct for a safety cap. 900s honestly flagged "product call." Note: agentic/LLM streams can exceed 15min; default-configured context force-settles them at 15min with truncated receipt + 6136 (money-safe but caller sees truncation). Validate default against real durations.
- Q5 STRONGEST FINDING (implementability premise the substrate can't honor): spec asserts index tombstone written "in the same critical section that marks the saga journal terminal" YET ALSO "separate expiry-indexed durable store, not the journal sweep." Current SagaJournal trait (saga_journal.rs:292 — append/load_unresolved/mark_resolved, NO cross-store txn, prod impl COMPACTS terminal sagas to ZERO entries §342-347) cannot honor both. Terminal-compacted saga is indistinguishable from never-existed to load_unresolved → "absent ⇒ fresh" recovery (R4) RE-EXECUTES if crash lands between journal-terminal-compaction and index-tombstone-write. Fix: spec should mandate ORDERING (index tombstone durable BEFORE journal terminal compaction) not "same critical section" atomicity across two independent stores. Reconcile in spec BEFORE runtime slice or runtime ships hazard / diverges.
- Q6 root-cause vs symptom: MORE COHERENT, root-cause fix. Completes ADR-049 §3a's deliberately server-owned/off-mailbox seal-phase lifecycle (Drop-while-in-flight does NOT cancel — durable saga must complete regardless of caller). ADR-049 text honestly amended "envelope enumeration NOT exhaustive (corrected by #2197)." (ii) reclamation alone gives money-safety; (i) idempotency separably prevents double-reserve + enables resume. STRONGEST SOUND PREMISE: "seal phase must be bounded server-side because it is deliberately decoupled from the client handle."
