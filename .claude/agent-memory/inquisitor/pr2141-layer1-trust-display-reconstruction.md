# PR #2141 (fix/sdk-coverage-fail-closed-and-parity) — Layer-1 trust interrogation, Round 2

Branch hardens SDK coverage gate + UCAN trust eval. Interrogated the 6 questions posed.

**ROOT CAUSE (the through-line):** the bridge op `ucan_validate(context, token, capability) -> Result<(), UcanError>` is underpowered for Layer-1 trust in TWO ways, and the SDK compensates with heuristics for each:
1. single-capability + stateful nonce side-effect → forces **att[0]-only** validation. Multi-att AND-intersection was BUILT (8909092eb) then REVERTED (205966ced) in THIS PR — forced by nonce single-use: looping ucan_validate per att[i] consumes nonce on att[0] → NonceReused on att[1..] → false verdict. Revert is a CORRECT forced technical decision, not inertia.
2. single collapsed error code (`ucan_error_code` maps ALL ~28 UcanError variants → one `PERM_3001`) + detail only in Display text → forces **Display-string classification** (`_classify_ucan_error` prefix-matches Rust `Display` output to recover which of 11 pipeline steps failed, then `_PASSED_BEFORE` infers which of 6 CapabilityValidation booleans passed).

Incoherence: the classification the SDK reconstructs by parsing Display ALREADY EXISTS structured in `ucan_errors.rs` as grouped match arms (structural/scope/expiry/nonce/capability/revocation ≈ the SDK's exact buckets), deliberately flattened to PERM_3001, then heuristically re-expanded downstream. Comments admit the code-split is "held back pending test updates" = right design known, deferred for test-churn. Both compensations are fail-closed + guarded, so SHIPPABLE, but both are DOA by the project's own "No DOA decisions" tenet (expected to be replaced when "the bridge op exists"). Deferral tracked ONLY in lesson `ucan-validate-needs-real-capability-uri.md` + code comments — NO forward story, NO spec reconciliation.

**Verified SOUND premise:** `validate.rs:512-607` IS strictly sequential + short-circuits (`?` each step: 1 header, 2 sig, 3 chain, 4 issuer, 5 aud, 5a/b keyscope, 6 capmatch, 6b catA, 7 atten, 8 ceiling, 9 nonce, 10 revoke, 11 expiry). So `_PASSED_BEFORE` "step N fails ⟹ 1..N-1 passed" is structurally valid. CAVEAT: signatures-bucket (2-7) and ceiling-bucket (6,8) INTERLEAVE (step 6 ceiling precedes 6b/7 sig) so the many-to-one step→boolean map isn't a clean total order — benign today (optimistic-True reports are semantically defensible) but fragile.

**Per-question verdicts:**
- Q1 Layer-1 abstraction: att[0]-only + fail-closed = SOUND; Display-classification = leaky, root=bridge API. Shippable (guarded by real 737-line source-parsing conformance test `test_ucan_conformance.py`) but flag deferral-without-story.
- Q2 `_PIPELINE_ABSORBED_CODES`: JUSTIFIED. ORTHOGONAL to structured results (governs absorb-vs-propagate, needed either way). Real improvement, guarded by TestPipelineAbsorbedCodesSync.
- Q3 WasmValidateError enum: JUSTIFIED. Doesn't paper over a bug — "context not registered" is a legit runtime condition the single `Result<(),UcanError>` was too narrow to express (was mis-funneled UcanError→PERM_3001→silently absorbed by trust.ts). Enum→CTX-2023 restores NAPI `ensure_registered` parity. "Fix state so fault can't occur" misframes a legit error as a bug.
- Q4 ALIASES gate: JUSTIFIED + correctly scoped after honest-docstring fix (341df72cc). Positive whitelist, fail-closed, negative self-tests, private-symbol filter (adfe9c710). Misses semantic correctness — now HONESTLY documented as human-review invariant (a `broadcastOpenKey` returning null passes). Consistent w/ "mechanical checks = defense-in-depth not primary."
- Q5 lessons: GENUINE, well-abstracted (browser-globals: Node-global + swallowing catch → false all-invalid verdict). COHERENCE FINDING: browser-globals lesson's rule "never swallow into fail-closed value — hides defect behind plausible verdict" is STILL violated by sibling `_extract_first_capability_uri` (trust.py:189 broad `except Exception: return None`) + TS equiv — lesson fixed only the one known trigger (Buffer), class stays open for unknown triggers.
- Q6 closed allowlist: REAL improvement not style. fail-closed-and-LOUD vs fail-closed-and-SILENT: broad absorb would swallow CTX-2023/PERM-3030/future codes into all-false verdict indistinguishable from "legitimately untrusted"; closed allowlist propagates non-pipeline faults as exceptions.

**Coherence finding (cross-SDK):** Python Display-prefixes guarded by Rust-source-parsing conformance test; TS pins Display prefixes via HAND-maintained table (trust.test.ts:283-346) + transitively relies on Python test ("See test_ucan_conformance.py"). No mechanical Rust→TS Display guard, and nothing enforces TS-prefixes==Python-prefixes. Fail-closed to "unknown" so not a security hole, but unequal drift protection for the same fragile mechanism duplicated in 2 SDKs.

Verdict: INTERROGATE FURTHER (ship-permissible; not UNSOUND). Actionables: (1) file a story for the all-att single-nonce bridge op + reconcile spec sketch.md `withinCeiling: Bool` (implies whole-token) vs att[0]-only; (2) consider structured classification codes to retire ~500 lines of Display-parsing machinery; (3) narrow the `except Exception` swallows per the lesson's own rule; (4) add a TS→Rust Display guard or a TS==Python prefix-equality test.
