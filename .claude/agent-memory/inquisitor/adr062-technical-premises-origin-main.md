ADR-062 DRAFT interrogated against origin/main (the earlier abstract-framing draft is superseded; this one CORRECTED the prior "in-mem DHT runtime-selectable" finding by reclassifying it as nullifier). Verdict: **INTERROGATE FURTHER** — core premises SOUND (DHT single-backend, RPITIT→enum), 2 material leaks.

**Why:** technical premise audit; supersedes/refines [[adr062-capability-injection-profiles]].

**How to apply:** on any ADR-062 re-review, check whether the 2 material leaks were closed.

Verdicts (ranked by load-bearing):
1. **Premise 1 (DHT=1 real backend→Mechanism ii): HOLDS.** DhtClient has exactly 2 impls in scp-dht (Pkarr prod / InMemory dev); pkarr "gateways" = param inside the one backend, not a 2nd backend. Spec §3.10 IS dual-layer (relay Layer1 + DHT Layer2) but layers are COMPOSED parallel-first-valid-wins (DualLayerResolver, DidResolver §3.10.10), publish-both is a MUST (§3.10.6) — mandatory-both ≠ runtime selector, so decomposing DHT-cap + relay-querier-cap is correct. **ADJACENT LEAK (prominent):** ADR defers relay querier as Axis-A=0 "fold in when #1729/ADR-025 land" — MIS-ATTRIBUTED (#1729=custody, ADR-025=Apple; neither governs relay resolution). Spec §3.10.12 makes relay PUBLISH/QUERY/DidResolver/parallel-resolution Phase-2 deliverables w/ §3.10.6 MUST. Prod ships NoOpRelayQuerier (resolver.rs:312). Code is behind spec; deferral trigger is wrong.
2. **Premise 4 (G1 prove-absent): LEAK (material).** InMemoryDhtClient is NOT type-gated: mod.rs:93 `#[derive(Debug,Default)] pub struct InMemoryDhtClient` (no cfg), and scp-dht is ALWAYS a dep (provides Pkarr too). So the TYPE compiles into every release rlib. G1 checks FEATURES (allow_in_memory_custody absent → FfiDhtClient::InMemory ARM absent) = reachability-via-sanctioned-arm, NOT binary absence (relies on linker DCE). Custody nullifiers DIFFER — behind scp-platform/testing crate-feature → Slice-4 severs → truly absent. ADR lumps them under one "provably absent (G1)" label (lines 60/106/128). Stray `InMemoryKeyCustody::new()` in release = compile error; stray `InMemoryDhtClient::new()` = compiles fine (E1 bug proof: bridge_instance.rs:358 + set_dht_client:2163 construct it unconditionally today). FIX not in any slice: `#[cfg]`-gate the type in scp-dht, else downgrade claim to "provably unreachable" for DHT.
3. **Premise 5 (coherence constraint = runtime construction-time hard error): LEAK.** 3 selections DON'T converge: persistence at construct (with_persistence :605/:622), DHT via lazy separate setter set_dht_client(&self) :2163 (OnceLock, "None until identity layer set up"), custody elsewhere. No single constructor sees all 3. ADR names "the dev-build constructor that co-compiles both arms" without identifying it. Dev-only stakes (release compile-safe). Risk: MUST with no realizable locus. Name the point or concede it's a late assertion (first-resolve/publish), not "construction time".
4. **Premise 3 (in-mem DHT intrinsic nullifier): LEAK (wording only).** It's CONTEXTUALLY nullifying (fine in coherent all-in-mem where resolver=same map). But "intrinsic-in-any-RELEASE-context" is true (real resolvers exist in the world), fails open/silent (vs in-mem storage fails closed/observable), so nullifier-grade + prove-absent outcome correct. Design unaffected.
5. **Premise 2 (RPITIT forces enum, enum-in-common right): HOLDS.** DhtClient RPITIT confirmed (publish/resolve `impl Future+Send`, mod.rs:45/67). ADR does NOT justify DHT-enum by hot-path (operative rule is pure RPITIT→enum; hot-path ref describes ADR-052's KeyCustody/Storage reasoning). scp-ffi-common ALREADY deps scp-dht (Cargo.toml:40) + both arms in scp-dht → enum-in-common adds NO new dep/coupling. Only quibble: "forces" overstates ("chose not to rewrite; rewrite buys nothing for 2-arm single-crate backend").
6. **Premise 6 (surface-dependent fail-safe): HOLDS.** scp-node config.rs:209 DhtMode{Memory,Production} Default=Memory (don't publish node ADDRESS); client publishes DID DOCS → opposite fail-safe (Production). Distinct-types decision correct.

Corroborations (not defects): scp-ffi/common Cargo.toml:30 `server` feature has UNCONDITIONAL scp-platform/testing (confirms surface-leak + G1 Slice-4 dep). uniffi currently TYPE-ALIAS not enum (bridge.rs:52-55, gates `any(test,allow_in_memory_custody)`); ADR enum arm gates `allow_in_memory_custody` only → plain `cargo test` loses in-mem arm (minor Slice-1 behavior delta).
