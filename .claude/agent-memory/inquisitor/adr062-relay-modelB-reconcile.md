# Model B relay DID-resolution redesign @ /private/tmp/scp-relay-modelb

Successor to [[adr062-slice11-modelA-suppression]] (I recommended Model-B: verify+highest-seq slot, carry pubkey, OR downgrade §3.10.8 to latency-only). They adopted Model B. Core prior defect (§3.10.8 claimed "all relays AND the DHT" resilience Model-A's oldest-first-truncate storage couldn't deliver) is now GENUINELY FIXED: relay single-highest-seq-slot validation makes flooding inert on validating relays; residual for foreign/non-validating relays honestly disclosed. ADR-062 reconcile CLEAN — relay resolution (real MultiRelayQuerier, RelayPublisher, DID-record frame, relay validation, republish.rs:703 sig/seq-drop fix) all scoped OUT to #482; ADR-062 keeps ONLY the InMemoryRelayPublisher-default sever (Slice 11); zero residue claiming ADR builds/restores resilience; publish_raw/query_raw Model-A client path fully removed. This resolves my prior "write half production-inert / phantom-restoration" finding by honest scope-out + NOT claiming restoration.

Verdict INTERROGATE FURTHER (sound direction, 2 medium QUESTIONs, no UNSOUND):

- **Q1 headline (MED, internal-coherence): limit:1 strands the multi-candidate defense.** §3.10.2:824 fixed QUERY to `limit: 1` (was Model-A `limit:16`), but §3.10.4 step-5 (:886) AND §9.10.12 query-contract RETAIN "if more than one valid record is returned (non-validating/foreign relay), resolver takes highest-seq-valid." Against a validating relay limit is irrelevant (1 slot). Against a NON-validating SCP relay (validation is OPTIONAL — permitted), limit:1 returns exactly 1 blob (possibly attacker's planted one) → the retained highest-seq-valid selection is UNREACHABLE for SCP relays (only foreign transports ignoring the limit reach it). limit:N DOMINATES limit:1: costs nothing vs validating relays (still 1 slot), preserves Model-A intra-relay shadow-defeat on non-validating relays. limit:1 discards that defense for negligible bandwidth benefit — the spec kept the SELECTION logic but removed the enabling QUERY (half-revert). Fix: set limit to small N, or scope step-5 explicitly to foreign transports.
- **Q4 (MED, premise-erosion): frame-format rationale weakened to near-false.** Model A rejected storing the canonical BEP44 mutable item partly because "public key k is derivable from DID → SCPR omits it." Model B now CARRIES public_key (32B, for the relay's verify — relay has only the one-way routing_id hash, can't derive key; mirrors BRIDGE_REGISTER §10.12.4 — this part SOUND). But that removes the size/derivability distinction, collapsing the rejection to one argument: "fixed-layout binary, not bencode, is the house discipline." That premise is arguably FALSE — bencode is ALREADY used for the BEP44 signed buffer `bencode(seq,value)` AND the DHT mutable item container. DidRecordV1 now carries the SAME 4 fields (k,seq,sig,value) as the BEP44 mutable item, differing only in encoding. Reusing the mutable item would eliminate a hand-rolled cross-binding format (a determinism footgun the spec repeatedly frets over), make relay+DHT containers byte-identical (they diverge now), reuse existing encode/decode. Reconsider, or fix the "dialect never used" claim.
- **Q3 (LOW): transport-independence preserved for CORRECTNESS** (client always re-verifies against DID-derived key, MUST NOT trust frame public_key, fails closed — nothing requires a validating relay for integrity). But a DhtMode::Disabled node (relay-layer-only resolution, no DHT backstop) has AVAILABILITY under adversarial flood coupled to relay validation — softer than "trust" but stronger than the "optional/availability-only" framing admits; compounded by limit:1 (a Disabled node querying a non-validating relay under flood gets 1 junk blob, can't recover). Disclosed-ish via the Disabled self-DID-regression note but not framed as a validation dependency.

SOUND (no findings):
- **Q5 tenet clarification HONEST, not a rationalized break.** "Relays are untrusted dumb pipes" → "untrusted, not does-zero-validation." Proof it was always overstatement: BRIDGE_REGISTER (§10.12.4) ALREADY had relays doing Ed25519 sig + SHA-256("scp:did:"||did)==routing_id binding checks on the control plane, PRE-DATING this change. Model B extends the SAME primitive from control-plane to a stored public record. Load-bearing invariant (encryption-as-access-control, compromised relay can't breach confidentiality) untouched — validation is on public unencrypted DID records, never encrypted content, never access control, client re-verifies. §10.12.4 note added makes the precedent explicit. Legit clarification aligning tenet to pre-existing reality.
- **Q2 ADR-062 reconcile SOUND.** Relay resolution correctly OUT (→#482), only default-sever IN. E1-analogy imperfect-but-disclosed: E4-WRITE default is LATENT (RepublishManager never constructed in prod) vs E1 LIVE (DidDht default bound at ~10 sites) — ADR states this plainly. Sever is inert prophylaxis for #482, coherent. A2↔A4 regression window widening (relay resolution ADR-slice→#482 ⇒ co-located governance inert until #482) honestly disclosed. NoOpRelayQuerier fail-closed-not-nullifier classification unchanged/correct.
- Dropping Model-A's kind-taxonomy (kind-1 DID / kind-2 KeyPackage reserved) for "each public record type = own minimal frame at own routing_id domain" is an IMPROVEMENT (removes the unfiled-future taxonomy I flagged in Model-A memo; aligns no-DOA). No-magic-tag (version 0x01 byte vs OuterEnvelope msgpack map marker) is weaker discriminant than "SCPR" magic but is only defense-in-depth beneath routing-ID domain separation + binding check. Fine.
