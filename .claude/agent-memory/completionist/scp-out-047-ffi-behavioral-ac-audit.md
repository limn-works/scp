ARCHITECTURAL BLOCKER (the real root cause): FFI-level `BridgeStreamExecutor` (outlet_stream.rs:261-282) is SINGLE-SHOT — handler called once → 1 Data chunk + framework-appended End. The multi-chunk/wedging executors (`FiniteChunkExecutor{data_chunks:10}`, `PrefixThenBlockExecutor{data_chunks:5}`) are runtime `#[cfg(test)]` fixtures with NO FFI-boundary analogue. So AC6's literal ">1 chunk" and AC8's "durable multi-chunk PREFIX truncation" are NOT constructible through the FFI boundary. `insert_test_streaming_saga_entry` seeds ONLY the FFI registry entry, NOT the supervisor's crashed NeedsRepair journal/actor state that the recover driver reads — so an FFI recover→Committed is unreachable without new plumbing.

FEASIBILITY: AC6 IS addable (zero-cost xctx outlet via `establish_xctx_saga_commit_preconditions` pattern + `test_insert_member`/`test_grant_member_capability` + a BLOCKING single-shot Rust handler; assert supervisor journal=Committing right after FFI open returns) — but only with 1 Data chunk, so the ">1 chunk" AC wording needs one-way-flow reconciliation. AC8 needs a NEW `#[cfg(feature="testing")]` bridge-reachable seam to seed a real crashed NeedsRepair saga (durable prefix) into the supervisor so a Rust e2e_bridge test can drive the FFI reconnect driver to Committed and read billed_count via a `CommitBStreamSettle` replay (as the runtime test does). Story amendment likely required either way.
