# ADR-049 Phase-5 actor-migration — reviewer-verdict audit (branch f2d4e7d0f)

Audited the "SOUND/complete/coherent" verdicts. Per-claim outcome:

- **A (crypto: 4 fail-closed commit-broadcast sites EXHAUSTIVE for epoch-advancing broadcasts)** — OVERSTATED. Fail-closed set = {execute_remove_member, execute_rotate_content_keys, recovery_advance_epoch, leave_context} via `keep_broadcast_failure`. But add_member (governance_helpers.rs:1268) + reset_member ×2 (2490/2503) ALSO produce epoch-advancing broadcasts, applied best-effort via `class_c_view()`+`apply_broadcast_failure`; plus issue_mls_update (#2060) returns commit to caller. So "exhaustive for epoch-advancing broadcasts" is false — it's exhaustive only for AUTHORITY-WITHDRAWING ones. No hidden silent-drop hole found: the best-effort bookkeeping IS persisted by the enclosing `execute_governance_action` final `discharge.commit_fail_closed` (supervisor path, gov_helpers.rs:5358). reset_member comment (2475-2489) honestly admits a compromise-key confidentiality residual but classifies Class-M.
- **B (AAD binds ctx/sender/epoch; Zeroizing)** — HOLDS (spot-check). `build_hpke_aad` (access_keys/wire.rs:477) length-prefixes u32|ctx|u32|did|u64 epoch — canonical, no concat ambiguity. Zeroizing wraps dh/plaintext/key bytes (sender_keys/key_protocol.rs:348-376).
- **C (saga replay idempotent; RestoredContexts type-sealed)** — HOLDS. RestoredContexts (supervisor.rs:130): private `ids`, module-private `new`, `for_test` behind `saga-witness-test-mint` feature not implied by `testing`, derives only Debug (no Clone/Default). Replay idempotent by SagaId: `xctx_committed_outputs`/`saga_pending`/`xctx_nonce_dedup` all persisted fail-closed (messaging_helpers.rs:2763-2771); commit_b_settle re-emits verbatim on replay (saga.rs:1509), capture+persist ordered BEFORE non-idempotent ToolInvoked append (1682-1691) to prevent double-append. Genuinely well-engineered.
- **D (OwnedIdentityDid unforgeable; MAX_PENDING_COMMITS fail-closed not remote)** — HOLDS. OwnedIdentityDid (identity_capability.rs:124): private `did`, `issue_for_actor` pub(super) to supervisor only, `reissue` can't change DID; no struct-literal outside module, no Deserialize/From. Handlers can name but not construct. MAX_PENDING_COMMITS=50 (state.rs:100); pending grows only from local commit ops; full→commit_fault→check_commit_fault gates send/gov/lifecycle.
- **E (simplifier: gates all closed-by-construction)** — REFUTED. check-saga-gating-granularity.sh = THEATER (P6 greps test NAMES, never verifies reservation set={caller,target}; empty-body self-test fixtures pass). check-cross-layer.sh = denylist+PR-body escape hatch. handle-affinity + bridge-symmetry = sound positive core but open denylist scope (suffix list; hand-maintained op JSON). black-hat vindicated.
- **F (completionist: enforcement tests real)** — REFUTED for 2/3. pipeline_wiring.rs = 154 source-TEXT presence checks (`fn_body_contains`), zero execution, passes gutted body w/ dead `let _ = fn;`. ffi_conformance.rs = surface-parity only, zero execution. check_ready_coverage.rs = REAL AST check but counts calls (not pairs to params) + ignores receiver.
- **G (new): no-op persist_snapshot coalesce arm is a latent landmine.** actor/mod.rs:523 persist_snapshot is a documented no-op; run loop's ONLY persist calls are this no-op (arm 4 line 323, final drain 332). class_c_view() (class_s.rs:3200 const fn) does NOT persist. NUMEROUS load-bearing comments (add/reset broadcast, messaging send_tracker) credit durability to "the run loop persists on mutated / the actor's persist tick" — which is the no-op. NOT currently exploitable: every authoritative mutation is captured by an enclosing fail-closed persist (execute_governance_action, send_message spending-nonce leaf) and shadow state (send_tracker) isn't authoritative yet. But one refactor (a class_c_view mutation in a handler w/o enclosing fail-closed persist, trusting the comment) = silent data loss. Systematically incorrect durability comments.

Also corroborated already-falsified #1: actor ttl_timer/governance_timeout/persist arms all no-op; timers still supervisor-driven. Many "Phase 2 sub-chunk / not yet wired" deferrals remain at Phase-4/5 branch (webhook target registration, metadata-routing publish, send_tracker authority).
