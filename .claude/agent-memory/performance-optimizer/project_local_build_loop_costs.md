Measured 2026-11-02, Rust 1.98.0, Apple ld-prime. Full write-up and raw rows: `~/.claude/plans/local-speed-2026-11.md` §Reconciled numbers.

- The first-day figures (65.7 s per one-line edit, 461 s cold, hook 199-307 s) were wrong. They were taken at load 21-54, and partly as the first build after a state switch. Steady state at load 4-9: a literal edit rebuilds the scp-runtime lib test in 5.5 s (rustc 5.2 s: expand 1.1, codegen 1.0, dep-graph and cache 1.4, link 0.3). An added await point in a hot async fn takes 11.3 s. A new field on a widely used struct (`ContextHandle`) takes 16.2 s, of which codegen and LLVM are 9.5 s. A cold unit takes 35.7 s.
- What inflates a measurement: changing `RUSTC_BOOTSTRAP` (or any env that a build script tracks) between runs in one target dir recompiles every dependency, 60 s and 228 s CPU, and makes scp-runtime's next build near-cold (rustc 31 s). Switching `cargo rustc` and `cargo test` costs a one-off 16 s. Load stretches wall time 2.5-3x but CPU only 1.1-1.3x, so CPU time separates extra work from load. Run every `-Ztime-passes` probe in its own cloned target, and report CPU beside wall.
- The linker is 0.3 s of a 5.2 s rebuild, so a faster linker saves at most that.
- Stable-toolchain rebuild levers measured on scp-runtime and rejected: `debug = 0` (0.2-0.5 s, within noise), `codegen-units` 16, 64 and 1024 (no gain, or slower), `split-debuginfo = "off"` (no change), proc macros at opt-level 3 (no change in expansion time). The 1.98.0 sysroot's `rust-lld` cannot load `libLLVM.dylib` on aarch64-apple-darwin. Only `-Zthreads=8` moved the field edit (16.5 to 13.7 s), and it needs `RUSTC_BOOTSTRAP`. Don't re-measure these unless the toolchain changes.
- The in-crate `#[cfg(test)]` modules cost 3.2 s of a literal-edit rebuild and 11-13 s of a field edit: the non-test lib rebuilds in 2.8 s and 5.0 s.
- A single named test through `cargo test --lib -- <path> --exact` takes 0.17 s at low load, which is cargo's freshness walk alone. nextest takes 0.48 s.
- Any dev-dependency edge that reaches back to scp-runtime makes the lib-test unit wait until scp-runtime's lib, and every crate on that edge, has compiled. Cargo runs no unit of a target before all of its dev-dependencies. A self dev-dependency (`scp-runtime = { path = ".", features = ["testing"] }`) still costs one non-test build of the lib before the lib test starts: 12-18 s for `cargo test --lib` under load, and in the hook's clippy the whole lib check, because clippy re-lints the lib on every run.
- scp-runtime now has no dev-dependency edge back to itself. Its examples need no scp-runtime feature: they store through `ProtocolRepository::new` over an `EncryptingAdapter`, and `messaging` mints a real KeyPackage. Every scp-runtime test command therefore names `--features testing`, and `src/lib.rs`'s `compile_error!` says so when one does not. Do not re-add an edge to make a bare `-p scp-runtime` command work. Measured after removal: the lib test starts at 1-3 s rather than 13-18 s, and the hook's lib check-test now runs beside the lib check rather than after it.
- `scripts/check-examples-compile.sh` only compiles examples. `messaging` compiles and fails at its first send with `PseudonymRegistryEmpty`, under any feature set (#3204). Run an example before claiming anything about its behavior.
- Since PR #3231 the hook lints only the edited members. `cargo clippy -p scp-runtime --all-targets` takes 9.4-10.6 s in steady state (28-29 s CPU), against 6.0 s for the lib-test rebuild in the same window. The lib check-test unit (about 10 s) is the whole critical path, because clippy's late lint passes re-run over the whole crate on every build. `clippy::future_not_send` alone costs 2.5 s wall, and the nursery group costs 4 s. The old 13-member scope took 20.6 s (115 s CPU).
- A local bridge build for tests uses `--profile ci-bridge`, which is what CI tests, never `--release`. `[profile.ci-bridge]` sets `incremental = true`, and CI's `CARGO_INCREMENTAL=0` overrides it. The napi addon rebuild after a one-line scp-runtime edit took 745 s under release, 269 s under non-incremental ci-bridge, and 72-79 s under incremental ci-bridge. Release and its descendants compile non-incrementally unless a profile says otherwise.
- Tests that are slow at the default dev opt-level usually spend their time in dependency crypto (Argon2 passphrase tests take 18-34 s each, and the protocol oracle tests 180 s). `[profile.dev.package."*"] opt-level = 1` cut the scp-protocol suite's run from 117 s to 43 s and doubled the CPU of a cold dependency build.
- The session scratchpad is shared by every agent in the session. Generic names such as `commit-msg.txt` get overwritten between a write and `git commit -F`, so use a file name that only you would choose.

**Why:** Alec wants each loop step at its physical floor. These facts decide which levers can pay.
**How to apply:** Measure at low load, by edit class (literal, async body, type layout), with CPU beside wall. Look for crate-graph edges on the critical path first, and the size of the crate being edited second.
