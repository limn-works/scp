# §6.2.4 Cross-Context Tool Saga — Wave-14 Abort Rework Review (2026-06-19, HEAD 9d168759c)

Worktree `xctx-saga`, branch chore/fuzz-pin-nightly base. Read-only spec-conformance pass over wave-14 abort rework. VERDICT: **ALIGNED**, zero divergence findings, 1 non-blocking OBSERVATION (pre-existing, out of wave-14 scope).

**The fix.** §6.2.4 caller-side reversal previously keyed on the volatile in-ctx carrier (`PreparedAFields` holding the `#[must_use]` `ToolEconomyTicket`), even though Prepare-A DURABLY persists `caller deduction + xctx_caller_reservations record` BEFORE the carrier reaches the supervisor. Whenever the carrier was lost/stale while the durable record existed → caller over-charged forever under a terminal-`Aborted` the startup-only §17.16.4 sweep never re-drives. Invariant established: **durable record is the source of truth for caller reversal on abort.** 3 HIGH legs fixed.

**Q1 — release on EVERY terminal path: CONFORMS.**
- Live `Abort{Some}` MATCH: carrier `rollback_tool_economy_generation_checked` reverses LOCAL + voids escrow; record consumed (saga.rs:1801-1836).
- Live `Abort{Some}` gen-MISMATCH (HIGH 1): carrier voids escrow only + refuses confused-deputy LOCAL write (`carrier_ran==false`) → **falls through** to gen-agnostic `reverse_caller_reservation_record` (keyed by `record.actor_did`, NOT generation) BEFORE removing record (saga.rs:1820-1831). LOCAL reversed exactly once (match→carrier, mismatch→record); escrow re-void idempotent; record removed once.
- Crash-recovery `Abort{None}`: `reverse_caller_reservation_record` reverses velocity(by-timestamp `rollback_one_at`)/budget(`reverse_spend`)/hard-rate-limit + voids escrow UNCONDITIONALLY (tools_helpers.rs:360-402). NO gen-gate — correct, since a respawn stamps a fresh generation that never matches the pre-crash record (a gate would skip every real refund). Safety rests on record+deductions rehydrated from ONE snapshot into the same `context_id`-routed actor.
- supervisor `prepared_a==None` lost-reply (HIGH 2): the `else` arm previously returned `SettledOrAbsent` blind. Now drives record-based `Abort{None}` via `redrive_caller_local_reversal` and folds outcome into verdict (supervisor.rs:7254-7275). This is the ONLY behavioral change to the live abort path besides gen-mismatch.
- Despawned caller (`lookup` miss) and target-leg are handled: escrow void+consume, report `ReversalOutstanding`, journal stays PreparingB for sweep (supervisor.rs:7229-7253, abort_target_leg best-effort orthogonal 7294-7318).
- Panic/cancellation between Prepare-A persist and abort → journal at PreparingB → startup sweep `redrive_xctx_prepare_in_progress` sends `Abort{None}` to both contexts (supervisor.rs:5619-5649). Covered.

**Q2 — all-or-nothing (terminal-Aborted only when refund confirmed): CONFORMS.** `abort_saga` (supervisor.rs:6987-7052) computes `caller_reversal` FIRST, and if `ReversalOutstanding` RETURNS Ok WITHOUT writing the `Aborting` marker or `mark_resolved(Aborted)` — leaving the journal at PreparingB for the sweep (7023-7043). `mark_resolved(Aborted)` ("fully compensated") never precedes a confirmed reversal. "Confirmed" = the actor `abort` handler replies `Ok(())` ONLY after `persist_state_fail_closed` succeeds (saga.rs:1886-1892); supervisor treats delivered-but-errored `Err((err,None))` as outstanding (7217-7227). So an `Ok` verdict genuinely means the refund durably landed.

**Q3 — prepare_a lost-reply ticket balance (HIGH 3): CONFORMS, does NOT reverse local prematurely.** On `reply.send` failure (receiver gone after persist) the actor recovers the must-use ticket and calls `void_external_and_consume` (voids escrow + marks consumed so the drop-guard doesn't fire) but DELIBERATELY leaves the durable deduction+record (saga.rs:508-524). It does NOT reverse the LOCAL economy here — correct: the only sequel to a lost Prepare-A reply is an abort (Commit-A impossible, supervisor never got the carrier), and that abort's `prepared_a==None` record path (Q2 above) owns the single LOCAL reversal. Reversing here too would double-reverse. Escrow voided at prepare_a + idempotently re-voided by the record path = no leak, no double-reverse.

**Q4 — no spec drift: CONFORMS.** Non-refundable §6.2.0.2 budget unit is NOT touched by any reversal (only velocity/budget-escrow/hard-rate-limit reversed; the outbound interface rate limit consumed at prepare_a step 2 is never decremented) — matches "Initiation consumes budget; no terminal outcome refunds it." NeedsRepair path untouched and distinct: `hold_external_for_repair` HOLDS escrow (tools_helpers.rs:274-288), concurrency slot released, divergence marker emitted (saga.rs:1913+); FSM final-drain at supervisor.rs:5228-5254 holds-for-repair on `reached_needs_repair`, voids otherwise — and for an abort `prepared_a` was already `.take()`n by `abort_xctx_participants` so the drain is a no-op (no double-handling). Wave-14 hunks confined to abort_xctx_participants doc+None-arm (supervisor.rs 7098-7275) + prepare_a/abort handler + gen-mismatch fallthrough (saga.rs) + tests. `recover_saga_entry` PreparingB arm NOT touched.

**OBSERVATION (non-blocking, PRE-EXISTING, out of wave-14 scope).** The startup-sweep `recover_saga_entry` PreparingB arm (supervisor.rs:5422-5447) calls `redrive_xctx_prepare_in_progress` (which on a `lookup` miss SKIPS that context, line 5623, and only warns on send error) then UNCONDITIONALLY `mark_resolved(Aborted)` (5434-5441) — unlike the live `abort_saga` path which wave-14 made conditional on the reversal being confirmed. So if the caller actor is not yet resident when the startup sweep runs (replay ordered before that context's restore), the record's reversal never runs AND the journal goes terminal, the same over-charge class wave-14 closed on the live path. Mitigant: SDKs are expected to call `restore_all_contexts` before `replay_unresolved_sagas`, but that ordering is NOT enforced in-tree (the only in-tree `replay_unresolved_sagas` call is a test; bridges expose both as separate calls). Did NOT flag as a wave-14 divergence because the arm is untouched by this commit; surface as a hardening follow-up — make the PreparingB sweep mirror the live path (leave non-terminal if the record-reversal could not be delivered), or assert restore-before-replay ordering.

LESSON: when a fix makes the LIVE terminal-marker write conditional on a confirmed compensating action, check whether the CRASH-RECOVERY/startup variant of the same transition got the same treatment — they're symmetric and an unconditional mark in the recovery arm reintroduces the same over-charge the live fix closed.
