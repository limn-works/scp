## FINDINGS
1. **MODERATE (artifact-completeness / downstream ADR staleness).** ADR §12 written allow-list (269-274) enumerates only FOUR categories: actor-owned Mutex<PerContextState>, Supervisor::write_lock, OpenMLS storage adapter internals, FFI sync boundaries. The change sanctions sites NOT in that enumeration: `bootstrap_spawn_lock`, the `task_set` JoinSet holder, the production_backend `join_gate` TOCTOU guard, and the test-mock class (oauth/credentials/timeout). All are consistent with the operative RULE (not per-command reads) so ban integrity holds — but per "artifacts are system of record," the ADR §12 allow-list should be expanded to name them, else a reviewer reading only the ADR sees only write_lock sanctioned among runtime guards. Same class as prior 2J downstream-artifact drift. Fix = update ADR §12 allow-list (flows down), not the code.
2. **LOW.** clippy.toml comment says "a `Mutex` acquire costs ~4× an atomic load — see the OpenSSL #30659 evidence in the ADR." OpenSSL #30659's ~4× (67 vs 17 cyc) is a `RWLOCK_read_lock` measurement, not a Mutex figure. ADR itself reuses this evidence for both bans, so the comment inherits ADR framing — but strictly the number is rwlock-read-specific. Imprecise, non-blocking.
3. **OBS (ADR-internal, not the change's fault).** ADR line 265 disallowed-types example still says "Use ArcSwap+write_lock or Mutex<PerContextState>" whereas §12 line 254 + the change's reason correctly describe as-built as "&mut PerContextState" borrow. The CHANGE's wording is more accurate than the ADR's own block. Reconcile when ADR §12 is next touched.

Verdict: ALIGNED with ADR-049 Decision 12. Enforcement integrity intact; only finding is the ADR allow-list needs to catch up to the (correct) broader sanctioned set.
