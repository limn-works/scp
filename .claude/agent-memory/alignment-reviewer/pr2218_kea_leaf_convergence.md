# PR #2218 `fix/rotate-all-author-keys-epoch-advance` @ 84be6115b + 050d0767f — NEEDS DISCUSSION

Implements part of issue #1847 (CLOSED audit: "EventType variants with no durable-append producer" — names KeyEpochAdvance + GovernanceDeadlockRecovery as candidates). `rotate_all_author_keys` on BroadcastContext: `()->Result<()>` → `(timestamp_ms:u64)->Result<Vec<BroadcastKeyEpochAdvance>>`. Two callers (execute_revoke governance-ban, execute_rotate_content_keys) now emit KeyEpochAdvance event-log leaves; execute_reconfigure_governance appends companion GovernanceDeadlockRecovery leaf.

**ALIGNED items (verified):**
- GovernanceDeadlockRecovery is spec-backed, NOT ad-hoc: ADR-031 §10 recovery protocol (phase-6.md:2778 "logged as GovernanceDeadlockRecovery event"), EventType enum (scp-event-log/lib.rs:218 + phase-2.md:807), PRD governance-integration.json, and #1847 itself lists it.
- ADR-049 Decision 7 citation accurate: Decision-7 (ADR-049 §7 "Async provider traits everywhere") makes append_* methods async + keeps combinator closure sync (guard dropped before .await). So async appends structurally cannot run inside the sync `commit_class_s_keep` closure — the code comment's claim is faithful.
- Reconfigure `+= 2` sound: BOTH GovernanceReconfigured + GovernanceDeadlockRecovery are fail-closed (`.await?`), short-circuit before the counter line, so `+= 2` never over-counts.
- KEA counter `1 + kea_success_count` internally correct per governance_logic.rs:148-158 invariant (count only truly-durable leaves; failed best-effort excluded). Arithmetic is right; the problem is upstream.
- rotate_all_author_keys all-or-nothing pre-validate + `advances.sort_unstable_by(author_did)` "for deterministic event-log leaf ordering across replicas" — good.

**HIGH (the finding):** The two GOVERNANCE-triggered KEA emissions are BEST-EFFORT (warn+continue on append failure). Per ADR-011 convergence doctrine (phase-2.md:925-940): canonical Merkle log MUST contain only convergent events; "a derived record is convergent iff its trigger input is convergent"; governance + access actions are in the convergent MLS-commit-ordered stream. KEA's trigger (governance ban RevokeAccess / RotateContentKeys) is convergent → the KEA leaf is a convergent canonical leaf → every honest member MUST append it identically. Best-effort (silent skip on transient failure) means one honest node's log is short a leaf → forks its tree::root → §9.9.3 relay-equivocation detection FALSELY fires on honest divergence (the exact thing the exclusion taxonomy guards). Sibling leaves in the SAME operations are fail-closed (AccessRevoked `.await?`, GovernanceReconfigured, GovernanceDeadlockRecovery) — KEA should be too. The PR's own determinism-sort proves convergence intent (deterministic ORDER) but best-effort undercuts it (non-deterministic PRESENCE). The `1+kea_success_count` counter keeps the LOCAL count honest but thereby locks a checkpoint position differing from a peer who succeeded — masks, not fixes, cross-node divergence. Note: PR copies the per-author-block/MemberBlocked best-effort pattern (line 982 "same pattern as MemberBlocked") — but a per-author UNILATERAL block is plausibly non-convergent (per-author, doesn't write read_exclusion_list per §2033), whereas a GOVERNANCE ban is convergent (all-authors, MLS-ordered). Category error to copy the pattern across.

**MEDIUM (spec tension → artifact-flow):** §2033 (05-contexts.md) frames KeyEpochAdvance as a "relay message" post-persist OBSERVER and names ReadAccessRevoked as THE durable event-log leaf for a ban — does NOT describe a durable canonical KEA leaf. §5.14.10 + ADR-011 EventType enum treat KeyEpochAdvance as a canonical convergent type. Spec is internally ambiguous whether the KEA event-log leaf exists as a convergent canonical leaf. Fix spec first (artifact-flow): decide (a) convergent canonical leaf → fail-closed, or (b) relay notification only → not a counted durable leaf. #1847 frames exactly this ("add where spec requires a CONVERGENT entry, or remove/justify"); §2012/§2019 "mandatory KeyEpochAdvance per author" = mandatory ROTATION (which IS fail-closed inside the persist), not necessarily the leaf.

Verdict: NEEDS DISCUSSION. Mechanics (types, counter arithmetic, Decision-7 citation, GovernanceDeadlockRecovery backing) all aligned; the best-effort-vs-convergent choice for governance-triggered KEA leaves needs resolution, spec-first.
