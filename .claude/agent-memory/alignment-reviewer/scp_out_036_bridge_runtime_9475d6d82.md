**#4b caveat_binding:None — THE FINDING (silent narrowing, comment overclaims).** invoke_outlet_cross_context calls `supervisor.open_outlet_stream(... None, None, None, None ...)` — the 4th None is `caveat_binding: Option<InvocationCaveatBinding>`. In open_outlet_stream (supervisor.rs:11348): `None ⇒ (caveat_post_input_check=None, counter_reservation=None)`. So the cross-ctx bridge SKIPS the entire §7.3.8 post-input hook. `requires_post_input_check` (caveats.rs:447) covers: amount_max_per_call, **input_schema**, allowed_adapters, **allowed_target_dids**, + counter-bearing (max_calls, amount_max_cumulative, rate_window). ECONOMIC ones (amount_*, allowed_adapters) are genuinely MOOT at zero cost (bridge is zero-cost by construction via the gate). But NON-ECONOMIC ones — **input_schema** (validates actual invocation input, only checkable post-input via check_invocation_local — the ONLY call site is this skipped hook), **allowed_target_dids**, and durable cross-invocation counters (rate_window, max_calls-across-invocations CAS) — are silently NOT enforced whenever the invoker's UCAN carries them. The invoke.rs justification comment "the §7.3.8 caveat ceiling is still enforced through params.caveats / params.ucan_cid" OVERCLAIMS: params.caveats only bounds the per-stream chunk-count ceiling (coerce_estimated_chunk_count/max_billable in pump) — it does NOT run input_schema, allowed_target_dids, or the durable counter CAS. open_outlet_stream frames None as "parity with the non-streaming free path," but the free path passes None only when there ARE no caveats; the bridge passes None UNCONDITIONALLY even when the invoker's UCAN has post-input caveats. NOT an AC violation (story silent on caveats) and reconciled §5.4.5 "Cross-context economy" clause addresses only the escrow dimension — so no hard artifact contradiction, but a genuine narrowing vs the same-ctx paid path that the reconciled artifacts don't bless. RECOMMEND: spec owner either (a) state in §5.4.5/§7.3.8 that the best-effort cross-context bridge does not apply post-input caveat checks (making code faithful + fixing the comment), or (b) thread the real InvocationCaveatBinding so input_schema/target-DID/counter caveats enforce across the crossing.
