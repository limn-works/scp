# ADR-049 2J spawn-from-Welcome — Round-5 alignment confirm @ `1e16634ad` (2026-07-02)

Branch `feat/adr049-2j-spawn-from-welcome`, worktree agent-ac30e75f53e358a5e. Round-4 delta `580e8d0ef..HEAD` = supervisor.rs + spawn_from_welcome_tests.rs ONLY (doc NOT touched this commit). Verdict **ALIGNED**, 1 LOW doc-completeness observation.

**Change:** the join entrypoint `Supervisor::spawn_actor_from_welcome`'s post-consume locked region (steps 1-5: ConfirmConsume→install→build state→durability recheck→persist→spawn) wrapped in `tokio::time::timeout(Self::LIFECYCLE_TIMEOUT, Box::pin(async{...}))`; on `Err(Elapsed)` returns `ContextError::TransportTimeout` + idempotent rollback (`destroy_mls_group` + `delete_context`). Motivation = BLACK-2J-07 global-lock DoS: `ConfirmConsume` send blocks on MLS processing of attacker-supplied `welcome_bytes` with NO reply timeout, under the GLOBAL `bootstrap_spawn_lock` → a crafted Welcome would wedge every bootstrap node-wide.

**Consistency w/ peer bootstraps — CONFIRMED.** create/import/restore dispatch arms (supervisor.rs ~2647/2779/2852) + `respawn_from_snapshot` (~4450) ALL do `timeout(LIFECYCLE_TIMEOUT, Box::pin(fut))` under `bootstrap_spawn_lock`, returning `TransportTimeout` on elapse. Join now matches. `LIFECYCLE_TIMEOUT`=30s (const line 1473). ADR line 154 establishes the generic discipline ("Every transport and storage call inside a handler wraps `tokio::time::timeout(30s, ...)`"); §10 embodies it for bootstraps. Not a divergence — the join finally conforms.

**Join is MORE careful than peers (justified, not divergence):** peers delegate to helper futures whose internal `Err`-arm rollback does NOT run on cancellation (future dropped), so create/import/restore can leave crypto residue on a timeout mid-flight (pre-existing property, out of scope). Join INLINES steps + explicit elapse rollback → strictly fail-closed. Correct for its half-keyed-crypto threat model.

**LOAD-BEARING SAFETY INVARIANT — VERIFIED.** Elapse arm's rollback must NEVER fire against a LIVE registered actor. Holds because: in `spawn_actor_with_watchdog` (called via `spawn_actor_with_state` → `Box::pin(...).await`), the last `.await` is `write_lock.lock().await` which is BEFORE `self.actors.insert(...)`; after registration there is NO `.await` before `Ok(handle)` (`spawn_actor_watchdog_task` is a SYNC free fn doing internal `tokio::spawn`). So `tokio::time::Timeout` re-poll after the spawn await resolves runs the inner future to `Ready(Ok(handle))` synchronously — cannot return `Elapsed` post-registration. Either full poll completes (registered+spawned+Ok) OR future dropped at/before the write_lock await (nothing registered). Airtight.

**Finalization OUTSIDE the timeout — deliberate + correct.** `let handle = spawn_outcome?;` then update_context_gauges / start_governance_timeout_task / dispatch_start_ttl_timer run untimed. Design difference vs create (whose finalize_create is INSIDE its timeout): the join CAN'T time finalization because its elapse arm rolls back crypto+snapshot → timing post-registration finalization would risk rollback-against-live-actor. Create tolerates elapse-after-registration only because it does NOT roll back (returns residue). Finalization ops are bounded-local (gauge update, timer-task spawn) — no attacker-supplied MLS/transport, so no residual DoS from leaving them untimed.

**Prechecks stay OUTSIDE the bound — CONFIRMED.** A(live-registry collision)/B(require-real-pseudonym, no `[0u8;32]` sentinel)/C(version+gov-model+ceiling-grammar validate)/D(durable first-writer-wins via load_context, fail-closed on read fault) all run before context_id_bytes/timeout wrap, under `bootstrap_spawn_lock` (acquired at top, lock order bootstrap→write). Nothing consumed/persisted pre-consume → early elapse impossible there.
