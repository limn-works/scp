# Standing-Pair Reframe (§5.15.8) — Black-Hat Findings

Branch `spec/standing-pair-not-a-saga-v2`. Docs-only. Reclassifies standing-pair creation from cross-context saga → single-context async (one MLS group, two members, deterministic `derived_context_id = "standing-"||hex(SHA-256("standing:"||did_lo||":"||did_hi))`).

## What is SOUND (could not break)
- derived_context_id second-preimage: colon-join safe for did:dht (z-base-32) + did:web (%3A-encoded) — method-specific id is self-delimiting/fixed-alphabet. Injectivity-invariant rewrite is honest (retracts old "no security" claim, names human method-admission gate, length-prefix = RECOMMENDED hardening).
- Authorship-keyed collision resolution: creator-credential check is CRYPTO-BOUND (ScpCredential.did==did_lo AND leaf MLS sig key resolves to did_lo DID-doc VM per §9.7.1:587). Replayed-genuine-Welcome stale-destroy closed by init-key single-use gating the destroy. Atomic {consent+confirm-creator+fresh-join+destroy} under per-context actor mutex + generation check closes confused-deputy recreate.
- AlreadyExists oracle (value+timing): non-member gets generic rejection, constant-time-wrt-existence; Implementer-mechanism paragraph makes it mechanically achievable. STRONGEST part.
- Welcome replay: init-key two-anchor (ADR-049 §9).

## FINDINGS (all MEDIUM/LOW — edges the prose over-claims)
- **BLACK-SP-01 MEDIUM**: standing-pair Welcome rides B's PUBLIC invitations routing ID `SHA-256(len||did||"scp-invitations")` (§5.12.3.3:861) UNCONDITIONALLY at step 3 BEFORE consent gate (step 4). Reframe moved side-effect earlier+unconditional vs old saga (deferred publish to Commit). "consent-on-receipt closes the oracle" only closes the SYNCHRONOUS reply arm; pair-SOLICITATION metadata + addressee-DIDs leak to relay observer. Contact graph asserted private (§5.12.6) but formation events aren't. Fix: disclose metadata leg; pseudonymous routing if solicitation must be private.
- **BLACK-SP-02 MEDIUM**: collision-loser re-drive burns victim KeyPackage (disclosed line 1862 as "rate-limited by per-DID cooldown") BUT line 1844 EXEMPTS canonical-did_lo collision path from that cooldown. Cooldown is keyed on initiator at recipient gate — wrong actor/node to bound a drain of the OTHER party's global published pool. §9.3 bounds DID-minting not per-pair re-drive. Fix: per-pair cooldown not exempted, OR did_hi doesn't add_member did_lo when a did_lo Welcome already pending.
- **BLACK-SP-03 LOW/MED**: unobserved-block self-heal claims §3.7.1 post-join sever reaches "same end state." §3.7.1:536 enumerate-and-sever needs Tier-1 severance (rotate sender key/destroy cache/delete access key, §9.16.3). Collision-losing did_hi is Welcome-joined + SEND-GATED (Phase-2E unshipped). Unproven that a send-gated actor-less replica can EXECUTE severance as blocker → self-heal may be Phase-2E-gated. Fix: prove severance reachable in send-gated state or disclose gating.
- **BLACK-SP-04 LOW**: did:web normalization rule (host lowercase, %3A) asserted ONLY inline in §5.15.8 + §5.14.13; NO authoritative §3 definition. Determinism is a security property; divergent normalization → two distinct derived_context_ids → silent convergence failure. Fix: single §3 canonical did:web form, both consumers cite it.
