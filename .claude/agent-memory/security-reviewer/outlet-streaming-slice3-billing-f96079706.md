# Outlet-streaming slice-3 billing (feat/outlet-xctx-streaming-saga @f96079706) — 2026-07-14 — SOUND, 0 BLOCKER/HIGH; 2 obs

**Core economic-integrity guarantee (SOUND):** actual settlement (StreamSettlement) is anchored to `manifest_reference = summary.manifest_billed = frontier.billed_count()` (dispatch.rs:3208/3225/3337/3344) via `anchor_settlement_receipt_to_manifest`, NOT the event's self-reported `chunks_billed`. The frontier is the pump's own O(log n) RFC-6962 fold over chunks that PASSED the gate. Operator emits chunks; pump counts under its own gate+cursor — operator cannot inflate the money-carrying count by forging the event field. Over-bill via forged event is impossible on the streaming path because money follows the frontier.

**Concern 1 (manifest wire-rejection / over-bill):** backstop `verify_outlet_invoked_event_local` (`chunks_billed <= stream_chunk_count`) STILL PRESENT + fires on ALL decoding OutletInvoked events at durable append (event_log.rs:766-780), incl. events routed via new `append_outlet_invoked_verified` (which delegates to append_event). NOT removed. Full frontier equality enforced in-pump before sink.record (dispatch.rs:3286, drop-on-mismatch). Manifest root binds signed chunks; receiver-side root comparison is the non-repudiation anchor (out of this gate's scope, by design).

**Concern 2 (cancel-boundary billing):** SOUND. `apply_stream_chunk_gate` (invoke.rs:2550) drops non-terminal chunks at `sequence >= billing_ceiling` (== cancel_ack_seq); terminal chunks bypass (line 2539). Gate runs on the pump-RESTAMPED outer seq (dispatch.rs:3024-3029, `sequence: next_seq`), same numbering space as `record_cancel(next_emission_seq)`. Billing accrual (`accrue_data_chunk_if_billable`) + cumulative ceiling use same `is_billable_chunk` predicate (`seq <= ceiling`). Since gate drops seq>=ceiling, all forwarded Data have seq<ceiling → billed. No Data at seq>cancel_ack_seq can be billed regardless of operator behavior. Inclusive `<=` predicate reconciles with `>=` gate because §5.4.5:530(3) terminal occupies the cancel_ack_seq slot (no Data there in sealed manifest). Fixes a real over-bill-by-one at the exact boundary.

**Concern 3 (monotonic_seq durable cursor):** SOUND. outlet_stream_credit.rs keyed per-(context,request_id) via sanitize_key_component (rejects `../`, path sep, NUL); distinct request_ids = independent cursors (test-proven) → no cross-stream poisoning. Persist(+1)-before-return = crash-monotonic (strictly-increasing, gaps OK). SDK-side liveness aid only: runtime CreditTracker is authoritative replay-reject (CreditReplay/6110). Tampering cursor DOWN = self-DoS (runtime rejects low seq); tampering UP = own-stream starve/overflow — both in SDK's own trust domain, no cross-party forgery. Pyo3 holds `handle.lock().await` across the whole read-modify-write+sign+apply (fixes prior assign-under-DashMap/apply-under-handle race). Cursor reclaimed by delete_context prefix sweep.

**Concern 4 (cancel_ack_seq leak/trust):** SOUND. Raising it can only shift the billing CEILING; can't add Data not in the sealed manifest (gate already dropped seq>=ceiling) → bounded by signed manifest. Lowering under-bills = operator self-harm (operator is payee).
