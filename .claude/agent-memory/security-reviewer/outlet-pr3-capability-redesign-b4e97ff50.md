# Outlet PR-3 capability redesign audit (feat/outlet-report-pr3, a65a778c9..b4e97ff50) -- 2026-07-10 -- ZERO exploitable findings

Capability enum ToolInvoke/ToolInvokeAll -> OutletQuery/OutletQueryAll/OutletCall/OutletCallAll; UCAN stems tool_invoke -> outlet_call/outlet_query; legacy tool:invoke/tool_invoke/outlet:invoke HARD-REJECTED (SCP-OUT-014). `Capability::new -> Option`. New §7.3.8 InvocationCaveats. Migration across runtime + pyo3/napi/uniffi + 4 SDKs.

**Verified SAFE:**
- **Capability::new (roles.rs:220)**: hard-break checks (outlet:invoke:/outlet_invoke:/tool:invoke:/tool_invoke:/tool:register/tool:interface) run BEFORE any prefix split -> None. `parse_outlet_suffix` = §5.4.2.1 (empty/>128B/non-[a-z0-9_-] -> None). Custom catch-all unreachable for outlet shapes. Multi-colon custom fails-closed (capability_name keeps remainder).
- **filter_map vs ok_or_else split is CORRECT**: authoritative state construction (mint.rs:269 parsed_caps; scp-ffi/common context_params.rs build_context_params ceiling+roles) uses `ok_or_else` HARD-ERROR -> legacy/malformed ceiling entry aborts context creation. Stateless validation helpers (sandbox_check_capability, media_check) use `filter_map` silent-drop but ALWAYS in positive-membership (fail-closed) direction: validate_declaration (app_sandbox.rs:751) denies-if-not-in-ceiling AND denies-if-not-in-role; empty ceiling => all denied. required cap uses `let Some(required)=... else return false` (deny).
- **uniffi ceiling_strings (bridge.rs:9446) filter_map is safe**: bridge_params_to_core->build_context_params (hard-error) runs at 9342 BEFORE the 9446 re-parse, so params.ceiling already only-parseable; filter_map drops nothing. Duplicate parse, consistent.
- **Economy alias drop**: PaidActionType ToolInvoke->OutletCall, CostSchedule per_tool_invoke->per_outlet_call (serde field/variant rename = wire-breaking, intended hard-break). FFI parse_action_type in pyo3/napi/uniffi ALL identically accept only OutletCall/outlet_call (tool_invoke alias dropped). - **caveat_resolver wiring (item 3)**: ALL outlet-invocation sites use TokenNbCaveatResolver (pyo3 outlets.rs:362, napi outlets.rs:60, uniffi 4021+4609 MCP, pyo3 mcp.rs:749). **OBSERVATIONS (non-blocking):**
1. validate_declaration (app_sandbox.rs:773-796) gives OutletCall/OutletCallAll the "All-covers-specific" shortcut but NOT OutletQuery/OutletQueryAll — asymmetric vs roles.rs CapabilityCeiling::contains which handles both. Effect is stricter (fail-closed) but functionally inconsistent: a decl requesting OutletQuery(x) with only OutletQueryAll in ceiling is denied here. Worth aligning.
2. Silent filter_map in stateless helpers means an operator ceiling typo silently narrows rather than erroring (legibility, not bypass) — acceptable since authoritative path (build_context_params) hard-errors.
3. SDK outlet_call()/outlet_query() helpers interpolate outlet_id without client-side suffix-regex validation; authoritative Capability::new rejects bad suffix. Not a bypass.
