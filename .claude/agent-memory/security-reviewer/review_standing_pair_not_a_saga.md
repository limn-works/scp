# Standing-pair "not a saga" reframe — SECURITY-CLEAN (docs-only, @3a161e640, parent a81c15f6e)

Reclassifies standing-pair creation from "cross-context saga" (PR #1793 category error) to single-context async creation (create + add_member + Welcome; consent-on-Welcome-receipt). 4 files: ADR-049 §3/§3a, DEFERRED-commit-11, spec §5.15.4/§5.15.8, §9.4.3 (09-security §287). Classification SETTLED, not relitigated. Verified the 5 security claims survive dropping the saga framing — all hold:

1. CONSENT still enforced (stranger can't force B into a pair). Welcome-receipt gate §5.15.8 step 4 = (a) block list `is_globally_blocked` §3.6/§3.7 + (b) opt-in `AutoAcceptPolicy`/`TrustRequirement` §5.12.6. CRITICAL backstop: §5.12.2 auto-accept is DENY-BY-DEFAULT (opt-in policy agents MAY configure; `shared_context` TrustReq ⇒ "strangers can never trigger auto-accept"; tool/paid contexts NEVER auto-accept, non-overridable). Processing a Welcome = joining an MLS group = a context-join, so the existing join-admission gate applies. No stranger auto-join. SOUND.
2. BLOCK-PRIVACY claim (async consent strictly better). TRUE: no synchronous Rejected ⇒ no 1-bit block/existence oracle; blocked initiator sees offline-indistinguishable silence. Strictly removes the leak the old synchronous Prepare-B `Rejected` carried. §5.15.8 existence-oracle clause AIRTIGHT and UNWEAKENED (verbatim-preserved minus a "Outside replay" preamble that's moot once there's no saga replay): AlreadyExists→Ok ONLY verified-self-membership; non-member gets generic rejection, constant-time wrt existence (explicit timing+value indistinguishability). ADR-049 §3a taxonomy reconciled (AlreadyExists no longer a saga terminal; routed to get-or-create).
3. ANTI-SPAM. Old per-participant-set saga serialization (B admits ≤1 inbound at a time) is GONE — but it only ever bounded CONCURRENT churn; reserve-not-consume + the per-peer cooldown were always the real bounds. Reframe keeps per-peer cooldown (60s default, 1s floor, normative, non-discretionary) on the consent gate. Concurrency bound lost is replaced by: MLS join is idempotent on `derived_context_id` (Entry::Vacant), no journal/no reservation churn, consent-gate-first. Fresh-DID Sybil fleet bounded by §9.3 admissible-DID minting cost (unchanged). NO DoS regression — if anything LESS state churn (no journal, no 2-phase). SOUND.
4. KEYPACKAGE DRAIN. reserve-at-Prepare/consume-at-Commit GONE. Replaced by single-use enforced at B's JOIN via fused-join two-anchor (§2F/ADR-049 §9). Malicious initiator can't drain B's pool: B's KeyPackage is consumed only when B itself processes a Welcome it consented to; initiator A fetches B's *published* KeyPackage but consumption happens B-side at join, gated behind B's consent. An abandoned/rejected Welcome consumes nothing on B. SOUND — actually simpler/stronger than the old reservation dance.
5. §9.4.3 "both defined sagas" rewrite. Removing standing-pair from the secret-bearing-saga list loses NOTHING: standing pair was always `secret_bearing=false` public-metadata-only and now journals nothing at all (MLS secrets live in actor-local crypto-provider state as for any single-context create). §9.4.3 contract for FUTURE secret-bearing sagas intact.

NO dangling live refs: §5.15.4 saga list, §5.15.8, §9.4.3 all scrubbed to "two sagas". DEFERRED-commit-11 refs all explicitly marked superseded/historical-provenance. Residual `CreationReceipt` in phase-2.md/prds/main.json = the UNRELATED single-context create_context two-phase builder receipt (mls_group/sender_key/event_log/published), NOT the standing-pair saga artifact — correctly untouched. Orphaned SagaInput::StandingPairCreate/creation_receipt.rs deletion = acknowledged later code PR.

OBSERVATION (non-blocking, doc-honesty): §5.15.8 "Known limitation" — a Welcome-joined replica can join but CANNOT SEND until Phase 2E spawn-from-Welcome entrypoint. Honest disclosure, pre-existing actor-lane gap (see project memory), not introduced here, no security weight. VERDICT: sound.
