ADR-061 (`.docs/adrs/ADR-061-outlet-invocation-modes.md`) + spec §6.2.5 classify outlet invocation on two orthogonal axes: **delivery** (unary→`output_hash` / streaming→`stream_manifest_hash`) × **envelope** (best-effort / transactional-saga §6.2.4). 4th mode = **streaming saga** = §6.2.4 envelope with committed artifact swapped output_hash→stream_manifest_hash, Commit-triggers-execution slot drives the chunk stream. Motivating case = paid metered LLM outlet (stream tokens, bill exactly-once across mid-stream crash). Streaming saga is PLANNED (slice 3), not built; slice 2 (this worktree) ports same-context streaming primitives.

**Verdict: synthesis is SOUND but ADR under-specifies the load-bearing mechanisms + mis-cites provenance. NEEDS REVISION before slice-3 build.**

Primitives (verified support the model): `scp-protocol/.../outlets/stream.rs::compute_chunk_manifest_root(&[OutletStreamChunk])` = batch RFC-6962 root at close; `scp-runtime/.../outlets/signer.rs::StreamSigner` = object-safe async per-chunk sign seam (custody-backed, ADR-006); `scp-runtime/.../outlets/stream.rs::StreamEscrow` reserve_at_open→accrue_one_chunk(only ≤ cancel-ack-seq)→settle_at_close=(billed, refund=reserved−billed); credit/escrow Class-S via commit_class_s_keep (monotonic).

Key findings:
- **Commit timing (Q1):** ADR's "saga commits once over the bounded Merkle root" conflates TWO instants — the FSM Commit-transition (triggers execution, root does NOT exist yet) vs stream-CLOSE (root computed, receipt signed, escrow settled, both event logs recorded, SagaId-keyed capture finalized, FSM→Committed). Correction: receipt/settle/dual-log/Committed-terminal all move to CLOSE for streaming.
- **Crash-mid-stream (Q2, the deepest gap):** §6.2.4 "replayed Commit re-emits stored output, NEVER re-invokes" — sound mechanism for stream = SEAL-PREFIX-AND-CLOSE-TRUNCATED, never resume/re-invoke (LLMs non-deterministic → resume unsound). Supported by CancelAckTracker billing-ceiling + accrue-only-≤-cancel-ack-seq, but NOT stated in ADR. Must write in.
- **No-buffering + exactly-once coexist (Q2):** NOT a contradiction — write-through (forward to caller mpsc + durably seal per chunk). AC[2] governs caller-forward path only. Ordering (persist-seal vs forward) is a real design point; caller-facing gap handled by §5.4.5 chunk-gap cancel-and-rerun.
- **Class-S composition (Q3): CLEAN.** Saga Prepare escrow reservation = reversible (RAII drop-on-not-commit, pre-Commit). Stream per-chunk credit = Class-S monotonic keep. No conflict: aborts happen pre-Commit (pre-stream); post-Commit failure = NeedsRepair (§6.2.4: economic reservation NOT auto-voided, settled by divergence-marker+operator). refund=unused reservation, NOT an un-consume of spent credit.
- **Receipt swap (Q4): potential DOA.** `SCP-XCTX-RECEIPT-V1:` preimage (§6.2.4 line ~305) fixes `Fixed32(output_hash)` with NO delivery-mode discriminator; §6.2.4 self-verifiability carries JCS output BYTES inline + recompute SHA-256. Streaming can't: root≠SHA-256(bytes), stream has no single JCS blob, verifier needs DIFFERENT algo (recompute Merkle root over chunks). Putting manifest-root in the output_hash slot under same V1 separator = ambiguous verification. MUST decide NOW (own domain separator / delivery-tag in preimage) to avoid DOA, and restate self-verifiability for two-level (per-chunk-sig + manifest-root) construction.
- **Provenance bug:** ADR-061 line 5 cites `ADR-049 §5 ("every outlet call is a stream" ergonomics)` — but ADR-049 §5 is `OwnedIdentityDid: unforgeable by constructor visibility`; the phrase appears NOWHERE in ADR-049. Broken provenance. (§3 cite for "executor can't cross mailbox" IS defensible — §3 = cross-context saga.)
- **Impl completeness note (slice 3):** plan claims signer.rs does "Merkle manifest accumulation" but signer.rs is signing-seam ONLY; only BATCH `compute_chunk_manifest_root(&[...])` exists → close-time root over unbounded stream is O(n) memory unless computed by streaming sealed chunks from durable storage (incremental Merkle accumulator not yet built). "Bounded even for unbounded stream" true for the 32-byte ARTIFACT, not for the current batch computation's working set.
