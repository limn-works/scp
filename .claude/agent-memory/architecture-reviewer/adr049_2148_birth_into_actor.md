# ADR-049 #2148 birth-into-actor PLAN review @ d16d45517 — APPROVED w/ 4 SHOULD-FIX

Dissolve provider per-context state: birth constructors RETURN `OwnedMlsCryptoState` locally instead of insert-into-`contexts`-DashMap-then-`take_crypto_state`. Delete `contexts`/`taken_context_ids`/`broadcast_keys` + buffer methods. Root-cause fix for #2167 cross-map TOCTOU (subsumed).

**METHODOLOGY TRAP (cost me half the review):** base is d16d45517 = origin/main, which CONTAINS PR-7 (b7c51b1f4 IS ancestor). The MAIN checkout `/Users/alec/Developer/limn/scp` was a DETACHED pre-PR-7 HEAD — reading it showed steady-state crypto still on provider, take_crypto_state test-only, seal via with_context. ALL WRONG for this base. **Always read from the task worktree, verify HEAD==base first.** On d16d45517 PR-7 moved seal/open/add_member/remove_member/rotate onto actor PerContextState; provider `contexts` is now purely the transient birth buffer.

**Q1 vacant-guard removal SAFE (the crux):** registry check-then-insert is ATOMIC under `write_lock` (supervisor.rs:3795-3800 spawn_actor_with_watchdog, first-writer-wins). All 3 birth seams register through it; CREATE (supervisor.rs:2450) / IMPORT (2581) / WELCOME (spawn_actor_from_welcome:13379) hold global `bootstrap_spawn_lock`. Birth constructor is now a PURE fn (mints MLS group, no shared write) → loser's owned crypto just dropped, no leak/divergence. Since crypto lives in actor post-PR-7, "one actor per id" ⟹ "one crypto owner per id"; provider Entry::Vacant + H2 taken_context_ids guard (provider.rs:950,963 / install_joined_group:1056) is REDUNDANT defense-in-depth on a soon-deleted buffer AND the SOURCE of the TOCTOU. Deletion moves the invariant to its true home (registry) — NOT a weakening; aligns w/ ADR-058 inv-9 "redundant re-check of soundly-enforced property = negative value."

**Q3 completeness VERIFIED:** provider add_member/add_member_from_bytes/generate_sender_key/init_broadcast_key/create_mls_group(bare)/broadcast_keys = ZERO production callers on d16d45517 (all test helpers: two_party_test_support, invoke.rs:8790, state.rs:3915, supervisor 16441/20999, key_destruction:443, ttl:1625, lifecycle:4301). broadcast_keys is WRITE-ONLY-dead (only self.broadcast_keys insert@1134/remove@1179; no production get). 3 prod seams = CREATE(builder.rs:989+lifecycle_helpers:1780), WELCOME(supervisor:13770 install+13815 take), RESTORE(restore_crypto_state_with_floor_guard:1927 — ALREADY returns Option<OwnedMlsCryptoState>). Plan's 13770/13815/1927 citations are CORRECT on this base.
