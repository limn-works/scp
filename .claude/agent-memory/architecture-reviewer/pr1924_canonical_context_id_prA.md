PR-A of #1924 canonical-context-id reconciliation. A context's canonical identity = its 32-byte digest; id STRING = `hex(digest)`. Defect: runtime resolved id→keying-bytes by HASHING (`state.context_id = SHA-256(handle.id)`), but for a real id `handle.id` is ALREADY `hex(digest)`, so `SHA-256(hex(digest))` is a DOUBLE-HASH that never matches the wire/saga digest. §6.2.4 xctx-tool saga uncommittable in production; masked only by non-hex fixture labels.

**Design (Model A, SOUND):** single chokepoint `state::context_id_to_bytes(id)` — if 64-char all-lowercase-hex ⇒ `hex::decode` to `[u8;32]` digest; else fall back to raw `scp_protocol::context::context_id_bytes` (SHA-256, byte-identical to pre-change). 64-hex guard strict (length 64 AND `0-9a-f`) — `generate_context_id` emits only lowercase, so uppercase 64-char test labels stay on hash fallback. Protocol primitive stays pure SHA-256; runtime layer decodes (right module boundary). Registry value-agnostic (keys by id STRING, not bytes — needs no change). §6.2.4:276 conformance VERIFIED verbatim (spec mandates raw digest on wire, code conforms to spec — artifact-flow correct; Option B "re-spec wire to carry double-hash" correctly rejected as phantom-provenance inversion).
