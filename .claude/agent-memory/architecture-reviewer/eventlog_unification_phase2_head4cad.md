Workspace compiles clean.

**Two completeness items (both NON-blocking — documented/latent, not regressions):**

1. IMPORT PATH adopts exporter's `observed_at` VERBATIM (lifecycle_helpers.rs:1788 export-import, :2232 restore). Restore path = self-recovery (exporter==importer) → benign. Export-import path = cross-member bootstrap from another member's SIGNED snapshot → an importer adopts a (possibly hostile admin) exporter's backdated `observed_at`, so the floor `observed_at+PERIOD` can already be elapsed at import → the imported pending change applies immediately on the next timer tick (apply_pending_* calls is_effective). HOWEVER this is NOT a regression: pre-commit the gate was bare `current >= effective_at` and `effective_at` was ALREADY importable+backdatable, so the import path is no weaker than before — the commit just doesn't EXTEND the floor protection to imports. Codebase precedent for the right fix: import already sanitizes other member-local time fields (`cooldown_until` clamped C3 @1681-1686, anti-spam/velocity `validate_and_sanitize_snapshot` @1639/1653). `observed_at` should be re-pinned to importer `deps.clock.now_secs()` on the export-import (non-self) path for parity. Worth a follow-up; the commit's stated invariant ("never shorter than PERIOD of locally observed time") is literally false on the import path.

2. `FormulaChange::is_effective` (pricing.rs:68) is structurally identical (gates on proposer-controlled `proposed_at + grace_period_secs`, no `observed_at` floor) but has ZERO construction sites outside its own tests → NOT wired into a live governance deferral path → not currently reachable. Latent inconsistency: when FormulaChange gets wired to governance, it needs the same floor. Observation only.

**Freeze residual-risk (governance_helpers.rs:590) decision is SOUND and well-documented:** `freeze_start = max(created_at)` left backdatable on purpose — freeze is a liveness safety valve (auto-resolves a 2-proposal deadlock), NOT an authorization control; backdating only ENDS a deadlock earlier (benign), requires TWO colluding signers, and grants no capability. Correctly NOT given the floor treatment (would force widening the freeze tuple for no auth gain). No-DOA-conformant.
