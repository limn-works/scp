ADR-057 #1980-independent browser relay slice (branch feat/adr057-transport-jssocket @68f986c9a). Reviewed 2026-07-17. SOUND, no blockers.

**Step-2 seed extraction** (scp-mls/src/group.rs `extract_ed25519_seed`): openmls_basic_credential 0.5.0 `SignatureKeyPair` stores ED25519 private as `sk.to_bytes()` = 32-byte RFC-8032 seed (lib.rs:92); sign path `try_from(private)` (lib.rs:55) STRUCTURALLY forces 32 bytes. `private()` accessor is `#[cfg(feature="test-utils")]`-gated → unavailable in shipped builds. Production recovers seed via `rmp_serde::to_vec_named(signer)` → deserialize into local `struct{private:Vec<u8>}`. SOUND: to_vec_named is a name-tagged map so field reorder/add is transparent; a rename/shape-drift makes the required `private` field missing → deserialize ERROR (fail-closed), never silent-wrong. Vec<u8> serde = seq-of-u8 (no serde_bytes upstream), matched exactly. Cross-check test `derive_pseudonym_matches_direct_private_seed_derivation` pins it against the test-utils `private()` accessor (dev-dep enables test-utils, Cargo.toml:65) → drift fails loudly. Zeroize coverage complete: serialized zeroized, extract.private zeroized, seed is Zeroizing, reconstructed SigningKey ZeroizeOnDrop (dalek 2.2.0 + zeroize feature). ≠32 guard fail-closed correct.

**Key separation**: MLS SignatureKeyPair used BOTH to sign MLS AND as HKDF IKM for pseudonym. Safe — scp-crypto::pseudonym derive: HKDF-SHA256(ikm=seed, salt="scp-pseudonym-secret-v1") → HMAC(secret, ctx||domain) → Ed25519 keygen. HKDF one-way ⇒ publishing pseudonym pubkey leaks nothing about signing seed; domain-separated from Ed25519's internal SHA-512. Native precedent derives from DID identity signing key; browser uses MLS per-context key → pseudonyms DIFFER cross-device for same human. Human-ruled (Alec 2026-07-16, planning-session-10 Option A), sound for device-local announce mesh (each member announces own addr, peers record).

**Announce mesh / FS**: epoch-0 announcement undecryptable by later joiners (MLS forward secrecy: join@epoch N can't read <N). Re-announce sealed at CURRENT epoch on add_member (adder), join (joiner), bystander add-receive → all current members incl. new one can decrypt. Pseudonym itself is v1 static (epoch=None), stable across restore (tested); "at new epoch" in comments = announcement SEALED at new epoch, not pseudonym value changing. Sound.

**Zeroed OUTER routing_id**: app-data envelope routing_id = [0u8;32] (create_outer_envelope client.rs:977); real per-peer pseudonym rides the PUBLISH frame (client.rs:988-998); receive resolves via relay-delivered routing_id NOT envelope.routing_id → consistent. is_reserved_pseudonym rejects [0;32], context_routing_id (SHA-256("scp:context-routing:"||cid)), broadcast_routing_id (raw SHA-256(cid)) — domain-separated, non-vacuous. Receive authenticates sender_did from MLS decrypt (Inbound::Application), not payload → forged-announce guard (member_did==sender_did) meaningful. KAT cross_target pins secret/v1/v2 bytes on native+wasm (§25.19 vec 30/31).

**Minor open (non-blocking)**: (1) extract_ed25519_seed ignores signature_scheme — a 32-byte p256 secret would pass len guard; unreachable (SCP_CIPHERSUITE=Ed25519 group.rs:45) but assert scheme==ED25519 = cheap defense-in-depth. (2) rmp_serde growing-buffer realloc may leave transient un-zeroized seed residue in freed heap — unavoidable serialize-to-Vec residue, shared w/ snapshot ProviderSignerDump path. (3) No wasm-target test exercises full group.derive_pseudonym/extract serde path (only raw-seed recipe is cross-target KAT'd; extraction cross-check is native-only) — low risk (bytewise deterministic) but ADR-057's "invariant only if tested" ethos favors a wasm extraction test.
