CRYPTO-22 / #2187, branch `crypto-22-attestation-spec` (26b45229c). SPEC-ONLY. Replaces §9.7.1 "leaf signature_key IS the DID key" (written, never implemented — resolve_signing_key had ZERO prod call sites) with an attestation model: ephemeral MLS leaf key stays as-built; a new `#active`/`#agent`-signed KeyPackageAttestation (LeafNode extension 0xFF03 `scp_keypackage_attestation`, domain `SCP-KEYPACKAGE-ATTESTATION-V1:`, §9.5.2) binds {context_id, did, leaf_signature_key(32B Ed25519), signing_key_id, issued_at, expires_at} to the DID. Verifier resolves DID VM, checks sig. Analog of IdentityLinkAttestation §3.5.2.

**HIGH finding (blocker): context_id (field 1) is unimplementable for the pre-published joiner KeyPackage.** KeyPackages are PER-IDENTITY (§9.7.4 line 650, buffer≥10 per identity) + pre-published to relays for OFFLINE add to WHATEVER context an admin later picks (§23.10) — joiner does NOT know context_id at attestation-mint time (mint is once, at KeyPackage generation, baked into the leaf under the leaf self-sig; can't lazily add post-Welcome). Verifier MUST (line 605) unconditionally rejects "mis-scoped" → joiner can never be added. RULING: DROP context_id → context-agnostic {did, leaf_signature_key, signing_key_id, issued_at, expires_at}. Cost of omitting = ~nil: a published KeyPackage is already MLS's standing "anyone may add me to any group" token; attribution stays correct everywhere (using leaf K requires K's private key = you ARE X); unwanted-membership is handled by join-consent layer not the attestation; context scoping already comes from group_context extensions + inner-envelope per-msg sigs. §5.12 creator-collision (05-contexts line 81) does NOT need context-in-attestation — it uses independent id-agreement (a0) re-derivation + credential.did==did_lo + attestation-binds-leaf-to-did_lo; dropping context_id leaves §5.12 intact. Creator-leaf-only context_id = rejected (adds a branch, buys nothing).

**SOUND:** preimage exactly §9.5.1 (len-prefixed vars, raw 32B Ed25519 — ciphersuite pinned line 322 so 32B fixed is correct; splice-free); domain sep prefix-free vs SCP-ATTESTATION-V1 (diverge at pos 4); impersonation vector CLOSED (attacker can't forge #active/#agent attestation over their key, can't reuse victim attestation — leaf_signature_key mismatch); leaf rotation sound (key-specific binding rejects cross-key, MLS tree eviction handles old leaf, no window); signing_key_id-in-preimage prevents #active↔#agent confusion (mirrors InnerEnvelope field 11).

**LOW:** issued_at has no not-before/future-dated bound + "unexpired" underspecified; verifier should cross-check MLS LeafNode Lifetime vs attestation window (all inert — replay of attestation alone needs the leaf private key). Note: two distinct "leaf keys" — X25519 HPKE init/encryption key (line 649) vs Ed25519 signature_key (the attested one, field 3); spec is explicit but implementers must bind the signature key.
