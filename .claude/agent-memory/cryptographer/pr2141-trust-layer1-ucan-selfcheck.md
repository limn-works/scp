# PR #2141 crypto review (fix/sdk-coverage-fail-closed-and-parity)

VERDICT: cryptographically SOUND. No false-positive-trust path. Findings are correctness/parity/documented-deferral, not exploitable auth bypass.

**Layer-1 UCAN validation (trust.py `evaluate_trust` / trust.ts `evaluateTrust`) is a SELF-CONSISTENCY check, not authorization.** It extracts `att[0].with` from the UNVERIFIED JWT payload and passes it to `ucan_validate(ctx, token, that_uri)`. The bridge does the real crypto verification. Parser-differential (JS JSON.parse vs Rust serde_json, duplicate keys) is NEUTRALIZED: if the two disagree the bridge sees "capability not granted" → fail-closed. All-true verdict ⟺ bridge cryptographically validated the token. Reading unverified payload is safe here.

**Security-critical error-prefix checks are all ANCHORED** (TS `/^\[SCP-PERM-3001\]/`, `/^\[SCP-VALID-/`, `/^\[SCP-CTX-\d+\]/`; Python `startswith`). Real bridge format is `[{code}] {category} error: {message}` with code at position 0 (confirmed wasm error.rs:76 `[{code}] permission error: {message}`, all variants). So message-injection can't fool the trust path. Only `mapBridgeError` (errors.ts:263) uses UNANCHORED `.exec` first-match — but every path throws regardless of class, so impact = error-type mislabel only (LOW/INFO).

**MEDIUM — att[0]-only within_ceiling false positive:** Layer 1 validates ONLY the token's first declared capability. A multi-cap token `att=[{within-ceiling},{exceeds-ceiling}]` yields `within_ceiling=true`. Documented as deferred pending a bridge op that validates all URIs while consuming the nonce once (history: 8909092eb implemented multi-att AND-intersect → 205966ced reverted to att[0]-only). Callers told to call ucanValidate directly for real authz. Deferral tension with CLAUDE.md "no deferral."

**LOW — Python/TS parity divergence on PERM-3000:** Python `except bridge.UcanError` absorbs ALL UcanError except PERM-3030 (incl PERM-3000 → classify→unknown→all-false, fail-closed). TS absorbs ONLY PERM-3001, THROWS PERM-3000. Both fail-safe, but stated goal is parity. Acknowledged in code comments.

**Revocation prefix `_REVOCATION_PREFIXES=("token revoked:",)` is SOUND.** Excluding "revocation unauthorized:"/"revocation failed:" (admin ops) → classify "unknown" → all-false = fail-closed. A revoked token can't yield notRevoked=true (revocation=step10 before expiry=step11; notRevoked only true if failure is at expiry or full pass). Crafted error can't force spurious revoked/not-revoked (messages are Rust-generated, not token-echoed at pos 0).

**base64url decode (trust.ts `__decodeBase64UrlToUtf8`, trust.py `_extract_first_capability_uri`):** normalize -/_ → +//, pad to 4. len%4==1 → invalid padding → decode/JSON throws → null fail-closed. Buffer path lenient, atob path strict; divergence irrelevant (not a crypto boundary). Correct.

**WASM ucan.rs parity fix:** run_validate_ucan now returns `Err(UcanError)`; all failure branches (parse, cap-URI, pipeline, state-lookup, nonce-writeback) route through `scp_ffi_common::ucan_errors::ucan_error_code` (exhaustive) → PERM_3001, matching NAPI/PyO3/UniFFI (was PERM_3000). State-lookup/writeback wrapped as `UcanError::MalformedToken` → conflates infra error with token error (INFO: observability, fail-closed). validate_tool_ucan_wasm Option<code>→&'static str; tool_invoke drops unwrap_or(PERM_3000). Still fail-closed (reject either way).

**check-sdk-coverage.py ALIASES = NO crypto relevance.** Name-existence coverage only (docstring already corrected 341df72cc "not semantic correctness"). Positive whitelist (sound). Domain-prefix gate b0d330398 strengthens (removes bare-name bypass). No security assurance claimed.

## ROUND 4 FINAL (HEAD 7c7af56b6) — nonce-writeback replay invariant PROVEN SOUND
VERDICT: SOUND. No CRITICAL/HIGH/MEDIUM new. R2 trailing-`\n` LOW now FIXED (py uses `_CONTEXT_ID_RE.fullmatch`, raised as ValidationError SCP-VALID-7001 before loop, not absorbed).
- **NONCE LIFECYCLE INVARIANT (the crux): accept ⟹ nonce persisted.** run_validate_ucan (ucan.rs:340-409) is extract-validate-**writeback**. WasmNonceTracker.record (ucan.rs:170) only STAGES `validated_nonce=Some` — it does NOT persist. Persistence happens ONLY at WRITEBACK (ucan.rs:403-405) via `mgr.ucan_record_nonce(ctx, token.payload.nnc)`, which sits BEFORE the terminal `Ok(())`. Any writeback failure → `Err(WasmValidateError::Context)` → `[SCP-CTX-2023]` → trust.ts/py RE-THROW (not absorbed). So Ok is returned IFF writeback succeeded ⇒ **no accept-without-consume window** ⇒ no replay hole. validate_ucan's `?` (ucan.rs:398) short-circuits BEFORE writeback when steps 10/11 fail even if nonce was staged at step 9 ⇒ rejected token never persists its nonce.
- Q1 answer: CTX-2023 writeback-failure path does NOT consume the nonce, and that is CORRECT fail-closed — the presentation is REJECTED, so leaving the nonce un-consumed lets a legit retry succeed. Reject ⟹ not-persisted also holds (no DoS on retry).
- Q2 answer: writeback failure leaves nonce un-persisted = "usable" but BENIGN — only enables a retry of the same full validation; the token was never accepted, so no replay. No exploitable state.
- Q3 answer (att[0]-only): REPORTING gap in evaluate_trust/evaluateLayer1 facade, NOT a soundness hole in the authz gate. The REAL invocation gate `validate_tool_ucan_wasm` (ucan.rs:606) builds the SPECIFIC `scp:ctx:{ctx}/tool_invoke:{tool_id}` required_capability and runs step-6 cap_match + step-8 ceiling on THAT — so a multi-att token's out-of-ceiling att[1] can be REPORTED within_ceiling=true but can NEVER be EXERCISED outside the ceiling. Facade contract explicitly says "does NOT answer 'does this token authorize action X'; call ucanValidate directly." Now tracked SCP-302. Stays MEDIUM as a fail-OPEN *report* over-claim, not an authz bypass.
