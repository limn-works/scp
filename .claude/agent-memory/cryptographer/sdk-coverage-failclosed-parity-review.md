**UCAN prefix anchoring (trust.ts:457,461):** `/^\[SCP-PERM-\d+\]/` is CORRECT by construction. NAPI error format is `[{code}] permission error: {message}` (napi/src/error.rs:69) — the `[SCP-PERM-NNNN]` is ALWAYS at byte 0. Anchored `^` is strictly more correct than unanchored: an inner message containing a `[SCP-PERM-...]` substring (e.g. quoted) cannot false-positive. SCP-PERM-3030 (handle-affinity) re-raise checked BEFORE classification (461 before 462) — correct ordering. Inner `__classifyUcanError` uses `startsWith` throughout — consistent anchoring. Non-UCAN errors re-thrown (fail-closed). `__PASSED_BEFORE[unknown]` = empty set → all 6 fields false. Sound.

**test-guard.ts (NEW, fail-closed):** Replaced old `assertTestHookAllowed` (fail-OPEN: threw only on NODE_ENV==="production", so unset/staging/garbage all PASSED) with `assertTestEnvironment` (fail-CLOSED: throws UNLESS NODE_ENV in {test,development} or BUN_TEST non-empty). Strict security improvement. `Object.hasOwn` blocks prototype-pollution (Object.prototype.NODE_ENV). Frozen at module load via IIFE — runtime process.env mutation can't flip. bun sets BUN_TEST="1" in test runner, undefined otherwise. `BUN_TEST=0` (length 1) PASSES guard = test env — but this is NOT a meaningful new attack vector: an attacker who can set env vars in the victim process already has code-exec and doesn't need this seam; the two gated mutators (__setBridgeForTests, __constructScpWithNativeForTests) only matter against supply-chain deep-import, where the attacker controls neither env. LOW defense-in-depth note: BUN_TEST is broad; NODE_ENV-only would be marginally tighter, but bun-test compatibility requires it. Acceptable.
