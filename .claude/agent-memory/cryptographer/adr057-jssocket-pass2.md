ADR-057 in-browser relay transport (scp-mls + scp-client). PASS-2 review verdict: crypto-adjacent fix changes are SOUND.

- **Self-echo drop** (scp-mls encrypt.rs `classify_process_message_error` L47-54): maps ONLY `ValidationError::CannotDecryptOwnMessage` → `MlsError::CannotDecryptOwnMessage`; every other ProcessMessageError → DecryptionFailed. All 4 decrypt entry points route through it (L195/270/378/757). openmls raises it strictly on sender_leaf==own_leaf (leaf indices unique per member; a forged own-leaf frame just gets dropped = relay-drop-equivalent, no new attacker suppression power). Client receive loop drops it via early `return Ok(ReceiveOutput::default())` (client.rs L1260) BEFORE persist/tracker/ratchet — fully inert. SOUND.
- **S2 per-channel replay floors** (crypto_state.rs): `recv_sequence_tracker` (App) + `recv_announcement_tracker` (Announcement), both keyed by sender_did, selected by RecvChannel (L823/856). Split relaxes only the cross-channel ordering constraint (was wrongly dropping legit lower-seq announcements). Cross-channel byte-replay backstopped by MLS generation-number replay (message keys deleted, reused generation rejected); sender-key AEAD prevents forging a 2nd frame at same (epoch,seq). Announcement floor in-memory-only / not snapshotted (snapshot.rs L467-469) is safe: pseudonyms are static per (did,context), no rotation → replay idempotent. SOUND, no cross-channel bypass.
- **C1 ED25519 assertion** (group.rs `extract_ed25519_seed` L141-154): `signer.signature_scheme() != SCP_CIPHERSUITE.signature_algorithm()` before interpreting bytes; public accessor (no test-utils gate); expected derived from ciphersuite constant not hardcoded; fail-closed typed error; combined w/ 32-byte length guard. Correct + complete.
- **C2 wasm serde test** (pseudonym_derivation_cross_target_kat.rs L157 `mls_group_derive_pseudonym_serde_path_is_stable_cross_target`, #[wasm_bindgen_test]): drives real `derive_pseudonym`→`extract_ed25519_seed` serde path on wasm32; asserts determinism + context-separation + restore-stability. MINOR gap: uses RANDOM key (create_group), so a wrong-but-deterministic seed extraction on wasm would still pass — no independent byte ground truth on wasm (test-utils `private()` is native-only, cross-checked at group.rs:1352). Residual risk low: same-target msgpack round-trip is length-safe by construction (wire lengths explicit, not native usize), and golden recipe bytes are checked on wasm by the sibling test L142.
- **Reciprocal announce** (client.rs L1390): fires on learned_new_peer, calls announce_pseudonym→encrypt_and_fanout→`next_sequence` (single monotonic per-member counter, context.rs L160). Fresh unique seq → no (epoch,seq) AEAD nonce reuse. Payload = public member_did+pseudonym only, double-encrypted → no key leak. Cascade converges (first-time-only guard). NIT: next_sequence uses saturating_add — sticks at u64::MAX → nonce reuse; pre-existing, unreachable (2^64), mirror rotate_sender_key's checked_add would be cleaner.
