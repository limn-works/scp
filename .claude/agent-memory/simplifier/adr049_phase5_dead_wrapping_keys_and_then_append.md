Phase-5 holistic review (worktree @ f2d4e7d0f) of the COMPLETE actor refactor found **genuinely-dead scar tissue** (not Send-discipline-forced) — verified by grep of real call sites across `crates/` + `bindings/`, excluding `#[cfg(test)]` regions:

1. **Entire per-identity wrapping-key custody surface on `Supervisor` is TEST-ONLY.** `wrapping_keys: DashMap<DID, ArcSwap<WrappingKeyPair>>` field + public async `set_wrapping_keys` (the ONLY writer) + `wrapping_public_key_for` + `wrapping_secret_key_for` + `SupervisorHandle::my_wrapping_public_key` + `WrappingKeyPair` state type. ZERO production callers anywhere — every call site is in the test region (supervisor.rs >13072, handle.rs tests). Doc self-admits: "first caller lands in Phase 2 with the actor wiring + capability thread" (supervisor.rs:2086/2112) and "Until Phase 2 wires that capability through ActorDeps…". It is Phase 5; the caller never landed. The writer being test-only means the field is never populated in prod. This is dead *security-key-custody* surface → violates No-deferral/No-stubs/Completeness tenets. Resolution: wire the Phase-2 capability caller NOW or delete the surface. (MEDIUM-HIGH.)

2. **`commit_class_s_then_append` + `AppendOutcomeError` are PROVABLY-DEAD.** Built as the canonical combinator for the Commit-B tool-invoke path (spec §6.2.4). When Commit-B was actually implemented (`commit_b_first_settle`/`commit_b_settle_finalize` in actor/handlers/saga.rs) the author found then_append STRUCTURALLY cannot serve it and wrote **FLAG-COMMIT-B** (saga.rs:1574-1600) explaining why: (a) then_append's persist-fail arm KEEPS the Class-S mutation but Commit-B must RESTORE (keeping the capture → next reserve reports AlreadyCommitted → ToolInvoked append skipped forever); (b) then_append drops the owned `append_input` on its early `?`, and `CrossContextToolInvocationPrepared` is deliberately non-Clone (§9.4.3), so the staged slot can't be recovered. Production uses a two-combinator decomposition (`commit_class_s_restore` + `commit_class_s_keep`) instead. So then_append has zero prod callers, never can, `#[allow(dead_code)]` reason string is now FALSE ("no production caller until the handler-migration PR" — the migration happened and rejected it). Delete the combinator + `AppendOutcomeError` type + its 6 unit tests (class_s.rs ~6698-6965). Sibling `commit_class_s_compensating` (restore-S+compensate-C) also has ZERO prod callers — speculative. The other 3 combinators (keep/restore/keep_compensating) ARE load-bearing (83 / 27 / 1 prod callers). So the Class-S family is over-built by 2 of 5.

Also: economy_helpers.rs carries ~9 `#[allow(dead_code)]` that are all STALE (functions have live prod callers, e.g. void_paid_action has 8 real .await sites) — 43 such allows across scp-runtime; mechanical sweep warranted. See [[adr049-d7-broadcast-split-convergent]] (that split IS minimal/clean — keep_broadcast_failure dedup landed, 26/25/22 callers). Enforcement-gate suite audited clean/convergent (low 1-6-commit churn; block-in-place is monotonic-decrease ratchet → 0) — NOT the reframe-the-approach class.
