ADR-057 T1 (dissolve scp-primitives → scp-clock/scp-crypto/scp-did; extract scp-did) added `scripts/check-no-shim-reexports.sh`, wired into ci.yml protocol-deps job.

**Verdict: sound, bounded, convergent — NOT the non-convergent BLOCKER class.**

**Why it earns its keep (passes the "should this exist?" test):** a back-compat `pub use scp_did::DID` shim in a non-facade crate is a *valid* dependency edge — it does NOT break rustc acyclicity, the wasm-fence compile job, or check-protocol-deps.sh. So the no-shim policy rule has zero type-system enforcement; this gate is the only thing catching that real gap. It is defense-in-depth for a genuine hole, not redundant re-checking of a type-guaranteed property.

**Why it's convergent (not denylist-chasing):** closed *positive* crate set `{scp_clock,scp_crypto,scp_did,scp_mls}`; ONE word-boundary regex `pub use (::)?scp_x\b` catches all 3 canonical forms (whole-crate / `::Item` path / `as`-rename). Evolution across its ~4 touch-commits was correctness/robustness (recursive `find` for nested `crates/scp-ffi/*/src`, `cd` to repo root, comment-line filter) — NOT adding forbidden spellings. Regex + crate-set unchanged.

**Comment-filter proportionality:** the `case "$trimmed" in //*) continue` filter is a single bounded false-positive reducer (skips `//`,`///`,`//!` lines narrating the deleted shim). It is the OPPOSITE direction from AST-gate creep — reduces FPs, not chases bypasses. Currently guards zero real occurrences (only tree match is the sanctioned scp-core facade `pub use scp_mls::{`), but defensible against a plausible ADR-narrating comment. Header honestly scopes out block-comments/`pub type`/`package=` laundering as "audit-policed, not gated," citing the load-bearing rustc/fence/protocol-deps checks.

**T1c (extract scp-dht transport crate, HEAD 6932d2fbf) extended the SAME gate cleanly:** closed crate set grew `{clock,crypto,did,mls}` → `{clock,crypto,did,dht,mls}` (5th entry: `scp_dht` + owning_dir case), regex/structure untouched. Same convergent pattern held — NOT a blocker. That change set was also clean: all 3 IdentityError DHT variants (DhtPublishFailed/DhtResolveFailed/Bep44SignatureInvalid) still independently produced (From<DhtError> impl is not their sole producer, so no dead variants); mainline/reqwest fully removed from scp-identity; moved dht_client/mod.rs+pkarr_client.rs are 93-94% renames (only IdentityError→DhtError repointing, no new indirection); ~30 import sites unified to `scp_dht::` (improved on the prior two-spelling `scp_identity::DhtClient` vs `scp_identity::dht_client::DhtClient`). Two LOW nits: scp-dht declares `z-base-32`+`tracing` unconditionally but both only used behind `production-dht` feature (non-minimal under default features); `DidDht::bep44_signable` pub assoc fn is now a pointless pass-through (all external callers bypass it for `scp_dht::bep44_signable`).

**T1c review-fix commit (427a6c3f8, final state) fixed both prior LOW nits:** z-base-32/tracing are now `optional=true` behind `production-dht`; the `DidDht::bep44_signable` pub pass-through was deleted. Two NEW residual LOW nits at final state: (1) dht.rs `bep44_signable_format_is_correct` test is now an exact duplicate of scp-dht/src/lib.rs's own test (both assert `scp_dht::bep44_signable(b"test",42)==b"3:seqi42e1:v4:test"`) — scp-dht owns fn+test; delete the dht.rs copy (also needlessly `async`); coder self-flagged this. (2) dht.rs keeps a private `fn verify_bep44_signature` wrapper doing `scp_dht::verify_bep44_signature(...).map_err(IdentityError::from)`, called once at dht.rs:973 — redundant since `?` auto-converts via `From<DhtError> for IdentityError` (sibling resolution.rs/resolver.rs already call the scp_dht fn directly with `?`); inline it. Neither is a blocker. Gate still bounded (crate set + regex unchanged from prior commit). Doc-prose split T1c(landed)/T1c-b(next) is content-clean; minor label asymmetry (landed slice is bare "T1c" not "T1c-a" though its sibling is "T1c-b").
