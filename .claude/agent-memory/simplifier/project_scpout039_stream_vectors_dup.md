SCP-OUT-039 (C12) outlet-streaming conformance vectors (branch feat/outlet-streaming-ffi). Reviewed the 6 replay files + spec §25.21.

Verdict: NO over-engineering / non-convergence BLOCKER. Vectors are bounded-by-construction (fixed 7-vector set, `deny_unknown_fields` positive typed schema = the sanctioned closed-contract shape, see [[sanctioned-bounded-tripwire-shape]]). Real finding = REPETITION. The two scp-testing integration files (`outlet_stream_conformance.rs` raw dispatch vs `outlet_stream_vectors_through_open_path.rs` supervisor path) are ~985 lines each but differ in only ~183 lines — ~800 identical. Additionally `REFERENCE_OPERATOR_SEED`, `ReceiverSequenceTracker`, `sample_provenance`, `payload_from_vector`/`to_chunk_payload` are copied VERBATIM across 5 files.

**Why:** Separate `[[test]]` binaries can't auto-share sibling modules, so copy-paste was the path of least resistance.
**How to apply:** Consolidation IS available — scp-ffi + napi + uniffi already dev-depend on scp-testing under `allow_in_memory_custody` (the exact feature the live tests need). Recommend a `scp_testing::outlet_stream_vectors` lib module (feature-gated) exposing the typed schema + tracker + seed + payload converter, imported by all 5. Only `scp-client-wasm/src/lib.rs` stays separate (ADR-034 forbids depending on scp-core/tokio). The FFI files use untyped serde_json accessors ("no serde derive dep") — putting the typed schema in the lib upgrades them to `deny_unknown_fields` for free.
