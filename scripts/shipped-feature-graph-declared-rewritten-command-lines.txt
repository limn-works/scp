# Declared rewritten command lines of the G1 prove-absence gate
# (scripts/check-shipped-feature-graph.sh, assert_shipping_invocations_are_gated,
# half 3). One row per command line of a SHIPPING_FILES file — a line a
# Dockerfile RUN, CMD, ENTRYPOINT, SHELL, or HEALTHCHECK instruction, or a
# workflow `run:`, `shell:`, or `with:` key, hands to a process — that carries a
# token the shell or GitHub's expression evaluator rewrites before the process
# reads it. Each row is the line as join_continued_lines and
# normalize_shipping_lines render it: comments dropped, backslash continuations
# joined with one space, leading and trailing whitespace removed, internal
# whitespace collapsed to one space. The gate FAILS on a command line with a
# rewritten token this file does not carry, and FAILS on a row no shipping file
# carries, so an edit to any row's source line changes this file in the same
# pull request.
#
# A `#` line is a grouping comment the gate drops before comparing. Each group
# states the reason the expansion selects no cargo feature. Two reasons recur
# and are named once here:
#
#   (R1) The line's command word is a literal program or shell builtin that is
#        not cargo and not a program that passes its arguments to cargo (echo,
#        cp, mkdir, cat, git, gh, gpg, security, codesign, find, zip, shasum,
#        sha256sum, npm, node, python, gradlew, apt-get, a PowerShell cmdlet),
#        and the expansion is one of its arguments, a redirection target, or the
#        text of a heredoc it reads on stdin. The expansion becomes argv of that
#        program, and cargo never receives it.
#   (R2) The line is a shell assignment, a shell keyword line (`if`, `for`,
#        `[`), a heredoc body line, or a line of a PowerShell, Node, or Python
#        script the step runs with a non-bash `shell:`. It runs no cargo.
#
# The cargo lines carry two expansions with their own reasons. `${{ matrix.target
# }}` and `"$target"` follow `--target`, an option that takes exactly one value.
# When the expansion produces a token that begins with `-`, cargo exits with
# `"--target" takes a target architecture as an argument` and builds nothing;
# any other token names a triple rustc has to know. Neither path selects a
# feature, and run_gate resolves every triple at once with `--target all`, so
# the triple's value changes no verdict. `"$pkg"` follows `-p` inside the
# `for pkg in scp-core scp-ffi scp-ffi-napi scp-ffi-uniffi; do` loop, and
# packages_built_by_shipping_lines reads the four names from that `for` line,
# so each package the expansion names is one the gate resolves. The `cargo test`
# line compiles no shipped artifact and is declared under
# DECLARED_SHIPPING_FEATURE_FLAG_LINES in the gate for that reason.
#
# Action inputs under `with:` are declared because the gate cannot know which
# action passes an input to cargo: `PyO3/maturin-action` passes `args` to
# maturin, which passes `--features` to cargo. The inputs below name a toolchain
# target, a cache key or path, an artifact name or glob, or a manylinux tag;
# the `maturin-action` step's `args` input carries no expansion, so it is a line
# the gate's two token readers classify in full.
#
