# Declared lines of the G1 prove-absence gate
# (scripts/check-shipped-feature-graph.sh, assert_shipping_invocations_are_gated,
# half 3). One row per line of a SHIPPING_FILES file that reaches a process —
# a line a Dockerfile RUN, CMD, ENTRYPOINT, SHELL, HEALTHCHECK, ENV, or ARG
# instruction, or a workflow `run:`, `shell:`, `with:`, `env:`, `uses:`,
# `container:`, `services:`, or `working-directory:` key, hands to one, plus
# every line the workflow reader cannot parse as a mapping key at all, plus
# every workflow line whose key sits outside those seven, because a `${{ … }}`
# expression substitutes such a key's value into a command string — whose
# effect on the build the gate cannot resolve for one of four reasons:
#
#   (i) The line carries a token the command interpreter the file selects, or
#       GitHub's expression evaluator, may rewrite before the process reads it.
#       shell_rewrites_token decides that by whitelist: a token consisting only
#       of the characters cargo's own grammar uses (`A-Z a-z 0-9 - _ . / : , =
#       +`) reaches the process as written, and every other token needs a row
#       here. The whitelist is what closes the test across interpreters, because
#       a workflow step chooses its interpreter with `shell:` and a Dockerfile
#       chooses it with `SHELL`, so cmd's `%FLAGS%` and a later interpreter's
#       operators are outside the set without anyone enumerating them.
#
#   (ii) The line's command word is neither `cargo` nor `maturin`, the two
#       programs whose argv the flag reader, the package reader, and
#       assert_wheel_feature_selection_is_gated parse. `COPY . .` puts every
#       file of this repository into the image, so `RUN ./build-release.sh`
#       runs code this gate never reads, and that script can spell `--features
#       scp-node/testing` where no reader looks. Every token of that line sits
#       inside the whitelist, so reason (i) reports nothing about it.
#
#   (iii) The line assigns an environment variable. rustc reads RUSTFLAGS out of
#       its environment and never out of argv, and cargo reads
#       CARGO_BUILD_RUSTFLAGS, CARGO_ENCODED_RUSTFLAGS, and every other
#       CARGO_<SECTION>_<KEY> config variable the same way, so `--cfg
#       feature="testing"` in one of them compiles a nullifier that `cargo tree
#       -e features` prints no feature edge for.
#
#   (iv) The line carries an option token this gate's readers do not parse and
#       whose effect on what rustc compiles nobody has checked. `cargo --config
#       <KEY=VALUE|PATH>` sets `build.rustflags`, and cargo puts what it finds
#       there on the argv of every rustc the build runs, so `--cfg
#       feature="testing"` in that file compiles InMemoryKeyCustody,
#       InMemoryDeviceAttestation, and InMemoryPreRotationCustody into scp-relay
#       and scp-node with no feature edge for `cargo tree` to print. `-Z` names
#       an unstable cargo feature and a bare `--` hands every later token to a
#       second program. The gate decides this by whitelist:
#       CARGO_LONG_OPTIONS_THE_READERS_RESOLVE and the two short-option lists
#       beside it name every option a reader parses or a human has checked
#       against the cargo book as changing neither the features cargo resolves,
#       nor the flags and cfgs rustc receives, nor which manifest cargo reads.
#
# Each row is the line as join_continued_lines, join_continued_tagged_lines, and
# normalize_shipping_lines render it: comments dropped, backslash continuations
# joined with one space, leading and trailing whitespace removed, internal
# whitespace collapsed to one space. The gate FAILS on a line this file does not
# carry, and FAILS on a row no shipping file carries, so an edit to any row's
# source line changes this file in the same pull request.
#
# A `#` line is a grouping comment the gate drops before comparing. Each group
# states the reason its lines select no cargo feature and change nothing rustc
# compiles. Eight reasons recur and are named once here:
#
#   (R1) The line's command word is a literal program or shell builtin that is
#        not cargo and not a program that passes its arguments to cargo (echo,
#        cp, mkdir, cat, git, gh, gpg, security, codesign, find, zip, shasum,
#        sha256sum, npm, node, python, gradlew, apt-get, sudo, cd, mkdir, lipo,
#        xcodebuild, bun, swift, gpgconf, sleep, a PowerShell cmdlet), and the
#        expansion, when the line carries one, is one of its arguments, a
#        redirection target, or the text of a heredoc it reads on stdin. The
#        expansion becomes argv of that program, and cargo never receives it.
#        This reason answers (i) for a line carrying an expansion and (ii) for
#        every line whose command word is not cargo or maturin, so a line
#        carrying no expansion at all still needs its row.
#   (R2) The line is a shell assignment, a shell keyword line (`if`, `for`,
#        `[`, `while`, `do`, `done`, a `)` that closes an array assignment), a
#        heredoc body line, or a line of a PowerShell, Node, or Python script the
#        step runs with a non-bash `shell:`. It runs no cargo.
#   (R3) The line is a YAML key whose value is the block that follows it, so the
#        line's own text after the key is a block indicator (`|`, `>-`) or
#        nothing. The runner hands the block's lines to a process and this line
#        to none, and every line of the block is read separately.
#   (R4) The line assigns an environment variable, which is reason (iii). The
#        row states what the assignment does and why it changes nothing rustc
#        compiles, and a value edit changes the row.
#   (R5) The workflow reader parses no block-mapping key from the line, so it
#        tags the line `unread` rather than proving the line reaches no process.
#        A sequence scalar and a block-scalar body under a key the reader passes
#        over arrive here. The row names the key that owns the line and what the
#        runner does with its value.
#   (R6) The line hands cargo, maturin, or an action an option token outside the
#        whitelist of options this gate's readers parse, which is reason (iv).
#        The row names the option and states what its value does to the build.
#   (R7) The line is a `uses:` step, so the runner executes the action it names
#        and that action's own `action.yml` runs commands no reader here opens,
#        which is reason (ii) for a program the workflow grammar rather than a
#        shell selects. The row names what the action runs.
#   (R8) The workflow reader parses a block-mapping key the runner reads itself
#        and hands to no process, so it tags the line `value`. The runner still
#        substitutes a `value`'s text into a command string wherever a
#        `${{ … }}` expression names that value, and the shell then splits the
#        substituted text on whitespace, so a `value` line carrying an option
#        token (reason (iv)) or a character outside cargo's grammar (reason (i))
#        needs a row. The row names the key, states what the runner does with
#        the value, and states which expression context can name it.
#
# The cargo lines carry two expansions with their own reasons. `${{ matrix.target
# }}` and `"$target"` follow `--target`. GitHub substitutes an expression's text
# into the command string and the shell then splits that string on whitespace,
# so an expansion is not one token: the matrix value
# `x86_64-unknown-linux-gnu --config=ci-flags.toml` reaches cargo as a triple
# AND a second option, and an earlier revision of this file justified these rows
# on the ground that `--target` takes exactly one value, which word splitting
# falsifies. What holds instead is mechanical: workflow_lines_tagged tags every
# matrix value line of these files `value`, so each one passes through condition
# (i) — no character outside cargo's grammar — and condition (iv) — no option
# token outside the whitelist — or carries a row here. A value that passes both
# splits into words of which the first names a triple rustc has to know and
# every later one is a positional argument `cargo build` rejects with
# `unexpected argument`, so no split of it selects a feature or reaches rustc.
# `"$target"` takes its four values from the `for target in
# aarch64-linux-android armv7-linux-androideabi x86_64-linux-android
# i686-linux-android; do` line of build-matrix.yml, which spells each triple
# literally and which this file declares, so that expansion is one token by the
# same argument. run_gate resolves every triple at once with `--target
# all`, so the triple's value changes no verdict. `"$pkg"` follows `-p` inside the
# `for pkg in scp-core scp-ffi scp-ffi-napi scp-ffi-uniffi; do` loop, and
# packages_built_by_shipping_lines reads the four names from that `for` line,
# so each package the expansion names is one the gate resolves. The `cargo test`
# line compiles no shipped artifact and is declared under
# DECLARED_SHIPPING_FEATURE_FLAG_LINES in the gate for that reason.
#
# Action inputs under `with:` are declared because the gate cannot know which
# action passes an input to cargo: `PyO3/maturin-action` passes `args` to
# maturin, which passes `--features` to cargo. The inputs below name a toolchain
# target, a cache key or path, an artifact name or glob, or a manylinux tag;
# the `maturin-action` step's `args` input carries no expansion, so it is a line
# the gate's two token readers classify in full.
