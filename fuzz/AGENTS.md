# fuzz/

`fuzz/README.md` gives the procedure for running, adding, and triaging targets, and the I1–I10 security-invariant table. These rules are the ones an agent breaks.

- **Standalone crate.** `fuzz/` has its own `[workspace]` block and is not a workspace member. Never add it to the root `Cargo.toml` members; a root `cargo clippy --workspace` does not cover it.
- **Run every command from inside `fuzz/`.** `fuzz/rust-toolchain.toml` names the `nightly` channel. rustup applies the toolchain file of the directory a command runs in, so from the repository root it resolves stable and cargo-fuzz refuses to run. A `RUSTUP_TOOLCHAIN` in the environment overrides the file even inside `fuzz/`, and `build.rs` then fails the build and names the variable; unset it.
- **Parser targets take raw bytes plus a dictionary.** A target that parses untrusted wire bytes (Tier 1–2) takes `&[u8]`. Wrapping those bytes in an `Arbitrary` type makes libFuzzer mutate the `Arbitrary` encoding instead of the parser input, and coverage guidance stops working. Use `Arbitrary` types from `fuzz/src/lib.rs` only when raw bytes cannot reach the code path (Tier 3–4: a cryptographically valid structure, or a differential property).
- **Pass `-dict=` and a sufficient `-max_len`.** Without its dictionary a MessagePack target spends nearly all its time on bytes rejected at the first fixmap byte. The default `-max_len` of 4096 is too small for envelope targets; Tier 1 needs `-max_len=1048576`. Take bounds from the `MAX_*` constants in `serde_util.rs`.
- **Every target file starts with `#![allow(clippy::unwrap_used, clippy::panic, clippy::expect_used)]`,** because `fuzz_target!` detects crashes through panics. Targets call production `pub` functions only and contain no `unsafe`; wrap unsafe code in the production crate. A target that copies a private production function instead of calling it drifts silently (`.docs/lessons/fuzz-replica-production-type-drift.md`).
- **Name the trust boundary and the invariants.** Each target states which boundary it covers (B1 relay wire protocol, B2 post-MLS plaintext, B3 resolution and discovery) and which invariants it asserts; every target asserts at least I1, no panic on any untrusted input.
- **Keep dictionaries and seeds current.** When a target type gains, loses, or renames a serde field, update its dictionary in the same change; the `fuzz-build` CI check catches compilation breakage but not a stale dictionary. When a parsed enum gains a variant, add a seed to `fuzz/corpus/<target>/`. When a production API change breaks a target, fix the target; never skip it.
- **Never weaken an invariant assertion** (remove an `assert!`, or turn a `panic!` into a `return`) without human approval.
- **Minimize before you commit a crash input.** `fuzz/artifacts/` is gitignored; run `cargo fuzz tmin <target> <artifact>` and move the minimized file into `fuzz/corpus/<target>/`.
