# Lesson: Consolidate hash_pair() into a single canonical location

## Context

The RFC 6962 interior node hash function `hash_pair(left, right) = SHA-256(0x01 || left || right)` is duplicated in three production files:

- `crates/scp-core/src/event_log/tree.rs:362`
- `crates/scp-core/src/event_log/proof.rs:328`
- `crates/scp-core/src/event_log/pruning.rs:448`

Similarly, `compute_event_canonical_hash()` and `event_type_tag()` are duplicated in 6+ locations (production + test code).

## Problem

If any copy of `hash_pair` drifts -- e.g., the domain separator byte `0x01` is changed in one file but not the others -- proof verification silently breaks. Proofs generated by one module will not verify in another. This is a silent, total failure: no error is raised, proofs simply return `false`.

## Fix

Export `hash_pair` as `pub(crate)` from `tree.rs` (the canonical Merkle tree module) and import it in `proof.rs` and `pruning.rs`. Do the same for `compute_event_canonical_hash` and `event_type_tag`.

## When this applies

Any time you add a new module that needs to compute Merkle interior node hashes or event canonical hashes, import from the canonical location. Never copy the function.

## Discovered

SCP-126 cryptographic review (2026-02-27). The third copy was added in `pruning.rs`.
