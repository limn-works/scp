# ADR-062: Capability Injection — Real Backends and Test-Harness-Only Nullifiers

**Status:** Proposed (2026-07-14).

**Relates to / upstream basis:** The umbrella spec section **§17.17 — "Capability Selection Is Mandatory, Fails Closed, and Never Defaults"** (normative IDs **SCP-CAPSEL-8000/8001/8002** mandatory / fails-closed / never-default; **SCP-CAPSEL-8010/8011/8012** durability-only-vs-nullifier classification, incl. §17.17.2's "classification is mandatory before a capability ships"; **§17.17.3 / SCP-CAPSEL-8013** in-memory-DHT nullifier). Honest framing: §17.17 was authored alongside this ADR and §17.17.2 names ADR-062 as its realization — it is not an independently-pre-existing authority. Its force rests on its own argument (esp. §17.17.3's durability-vs-nullifier reasoning), not on age; this ADR realizes it and adds no exception to it. **Pre-rotation custody is OUT OF SCOPE of this ADR.** Production pre-rotation custody realization is punted to a later e2e-collab stage; its design is a PROPOSAL in **RFC #2130** (pre-rotation recovery custody), and **ADR-054 (Pre-Rotation Key Custody — Substrate Isolation) is Proposed**, not Accepted. Only the recovery-authority-residence RULE it authored is canonical, in spec **§9.7.4.1 item 3a**. This ADR does not realize, schedule, or depend on the pre-rotation *backend*; the real pre-rotation backend it does not build is the tracked gap (RFC #2130 / #1729 / #1777). The `InMemoryPreRotationCustody` nullifier weld, however, is **severed here** (§Decision 6) — re-gated test-harness-only and absent from every shipped binary, with production creation failing closed. Also relates to: ADR-052 + `.docs/standards/construction.md` (M1–M5; **M2** required-or-fail-safe-defaulted, **M3** fail-loud-never-silent-no-op — this ADR updates M2's `DhtMode` reasoning, §Non-goals); ADR-048 (multi-instance FFI); ADR-049 (no `dyn`/lock on the lock-free-**read** hot path only); ADR-006 (in-memory adapters); ADR-025 (device-attestation backend — separate, unstarted; §Decision 3); ADR-055/-057 (browser thin-client; WASM removed). Spec §9.12 (Migration & Recovery), §17.6/§17.7 (storage/BlobStore), §3.9/§3.10.3/§3.10.5/§3.10.6/§3.10.7/§3.10.8/§3.10.10/§3.10.12 (DHT resolution + Anti-Segmentation MUST + dual-layer suppression resilience + relay resolution).

**Motivating defects:** #627 (CLOSED, unmet — `production-dht` never enabled for PyO3/NAPI), #1518 (`ConcreteDidMethod` locks the shared FFI layer to `InMemoryDhtClient`), #1880 (rotation/migration publish through a fresh non-shared client that never reaches/invalidates the resolver). **#1733 (eliminate `scp_platform::testing` imports from production paths + CI enforcement) is FOLDED** for the capabilities this ADR fixes (custody/attestation/DHT/storage) and closed-as-folded at Slice 6 (§Folding #1733); its `InMemoryPreRotationCustody` row is carried to RFC #2130 (pre-rotation out of scope). **Pre-rotation custody (E5) is OUT OF SCOPE** — its realization is a proposal in RFC #2130 (#1729 / #1777); this ADR fixes only capabilities that have a real backend today (DHT → Pkarr; custody → File/Sqlite/callback; storage → Sqlite/filesystem; credentials → a durable store; attestation → declined per spec §9:187).

## Context

SCP's provider capabilities each carry a "which implementation?" choice; a 2026-07 audit found several resolved to an **insecure in-memory arm reachable on the shipped path or offered as a runtime backend option**. Findings, descending severity:

- **E1 (HIGH) — DHT.** PyO3/NAPI ship `InMemoryDhtClient`; UniFFI ships real `PkarrDhtClient`. `production-dht` is on `uniffi/Cargo.toml` but not `scp-ffi/Cargo.toml`/`napi/Cargo.toml`. **Root cause is structural, not a wiring miss:** `scp-identity/src/dht.rs:222` declares `pub struct DidDht<D: DhtClient = InMemoryDhtClient, C = SystemClock>` — a **default type parameter that silently binds the nullifier** — with `impl Default for DidDht<InMemoryDhtClient>` (`:264`) and `pub fn new()` (`:270`) both hardcoding `InMemoryDhtClient::new()`. Every `DidDht::new()`/`::default()` call (chokepoints `bridge_instance.rs:358`, `server.rs:35`, and ~10 uniffi/resolver sites) therefore gets in-memory DHT for free. This is the E1 bug's origin (SCP-CAPSEL-8002 violation: the runtime defaults a backend). #1880: rotation/migration mint a fresh non-shared client (`identity.rs:203-204`, `napi/identity.rs:246`, uniffi `make_dht_with_signer`).
- **E2 (HIGH) — credentials.** `InMemoryCredentialStore` ("Not suitable for production," `credentials.rs:502-506`, `impl Default :556`) wired on shipped NAPI+PyO3 as a **hardcoded concrete type** (`napi/runtime.rs:313`). The `impl Default` is a **LIVE SCP-CAPSEL-8000/8011 violation** (a default selection) shipping now — see §Decision 5.
- **E3 (MED) — blob storage.** `BlobStorageBackend::InMemory` un-`cfg`'d (`storage.rs:480`), `impl Default → in_memory()` (`:561`) — a **LIVE SCP-CAPSEL-8011 violation** (durability-only arm as default). §Decision 5.
- **E4 (MED) — relay querier.** `NoOpRelayQuerier` (`resolver.rs:309`) is the shipped relay-resolution arm; no real `MultiRelayQuerier` exists yet (§3.10.12 is unimplemented). §Decision 5 classifies it.
- **E5 (HIGH) — pre-rotation custody (nullifier SEVERED here; real backend out of scope).** `pre_rotation_custody: Arc<scp_platform::testing::InMemoryPreRotationCustody>` is an **ungated concrete field** minted on **every** shipped create-path — the shared lowering `scp-identity/src/config.rs:334` (`create_inner`, which all create paths funnel through) constructs it for **every** custody kind (File/Sqlite/callback), and the `scp-node` self-identity paths do the same. The pre-rotation key is SCP's recovery backstop (§9.7.4.1, §9.12); holding it in shared process memory violates §9.7.4.1 §3/§3a. **The in-memory *nullifier* is severed in this ADR** (Slice 6) — `InMemoryPreRotationCustody` becomes test-harness-only (`#[cfg(feature = "testing")]`, folded into `testing` exactly like the custody/attestation nullifiers) and is absent from every shipped path. What is out of scope is the *real production backend*, punted to a later e2e-collab stage (RFC #2130 / #1729 / #1777). Because no real backend exists to fall back to, **all production identity creation fails closed with a typed error** ("no production pre-rotation custody backend available") until #1729 — File/Sqlite/callback custody and node self-host alike, since they all pass through the `config.rs:334` lowering — and it does **not** fall back to the nullifier. Per the standing rule (PR #2132 "no dev/test-only stand-in may mask a missing production implementation"; sdk-common.md §Stub-and-Placeholder; spec §17.17), G1 allowlists ZERO nullifiers, no exceptions — a test-only nullifier masking a missing backend is exactly the anti-pattern this work eliminates.
- **F1 (HIGH, the "other weld") — the `server` feature path.** `scp-ffi-common` `server = […, "scp-platform/testing"]` (`common/Cargo.toml:30`) is **unconditional**, and `server.rs` non-test code references `InMemoryKeyCustody`/`InMemoryStorage`, `IdentitySource<InMemoryKeyCustody>` phantoms (`:322`,`:435`), and `InMemoryDhtClient::new()` (`:455`). Same weld as E5 for the node-hosting artifact. `server.rs`+`common/Cargo.toml` are enumerated in Slice 0 (storage path/feature) and Slice 1 (the `:455` DHT constructor, compile-forced by the D-A retype) and Slice 6 (the custody phantoms `:322`/`:435`).

**Root cause (the pattern).** The FFI security switch that should select *primitives* is defined in terms of *use-cases*: `allow_in_memory_custody` (`scp-ffi:27`, `napi:15`, `uniffi:32` — already drifted) is a **runtime backend selector** that makes `FfiKeyCustody::InMemory`, in-memory attestation, and in-memory DHT runtime-selectable, and NAPI exposes a public `custody = "in_memory"` config value (`napi/src/scp.rs:379`) — treating an insecure nullifier as a legitimate menu option. E1's `DidDht` default type parameter is the same disease at the type level (the type system *defaults* to the nullifier).

## Ecosystem convention (why this design)

Three-axis primary-source survey:
- **Axis 1 — test doubles are compile-time/test-code, not runtime options.** In-memory fakes live in a `*-test-util` dev-dep crate or a `testing`/`test-util` feature kept out of default/`full`, constructed in test code, absent from a normal build (idiomatic Rust).
- **Axis 2 — insecure custody/verifiers are never runtime-selectable; in-memory *storage* is a legitimate pluggable option.** `rustls` quarantines dangerous config behind a `danger` module; `webauthn-rs` gates insecure verification behind `danger-*`; OWASP "secure by default." Conversely **OpenMLS ships `MemoryStorage`** as a first-class pluggable provider — losing state is durability-only, not a nullification. This is §17.17's durability-vs-nullifier line.
- **Axis 3 — recovery custody is a pluggable backend menu.** Signal SVR, Apple ADP, passkey PRF expose recovery as a menu (HSM, cloud-HSM, device enclave, offline). This informs the *pre-rotation* design — which is out of scope of this ADR and proposed in RFC #2130 (ADR-054, `Proposed`); it is included here only for context on the capability's shape, not as work this ADR does.

## The split (execution units)

- **Unit 1 (module + DHT E1): Slice 0 (module structure) + Slice 1 (DHT E1, incl. the `DidDht` default-type-param removal + node `DhtMode` reconciliation).** Fixes the original E1 shipped-in-memory-DHT bug at its structural root.
- **Unit 2 (nullifier severance): Slice 6.** Sever **all four** in-memory nullifiers — custody, attestation, DHT, and pre-rotation — to test-harness-only (`#[cfg(feature = "testing")]`) + delete the `allow_in_memory_custody` switch + G1 ⊆-allowlist (ZERO nullifier exceptions) + #1733 close. Custody/attestation/DHT have real backends today (File/Sqlite/callback, declined-per-§9:187, Pkarr); pre-rotation has **no** real backend yet (RFC #2130 / #1729), so severing its nullifier makes production identity creation **fail closed with a typed error** rather than fall back to the nullifier. Only the pre-rotation *backend* is out of scope, not the nullifier severance.
- **Unit 3 (live SCP-CAPSEL fixes + completeness): E2/E3/E4 (Slices 9–11).** Their selection-boundary fixes (delete `impl Default`) are live SCP-CAPSEL violations, storied now (§17.17.2 forbids leaving a capability unclassified/unfixed).
- **Out of scope (RFC #2130): pre-rotation custody realization** — the seam, per-profile floors, §5 ceremony, and hardware backends are a proposal in RFC #2130 (#1729/#1777), not this ADR.

## Decision

**Principle.** Every capability whose in-memory arm is a **security nullifier** is fixed by (1) shipping **real production backend(s)** behind a proper dispatch seam and (2) demoting the in-memory nullifier to a **test-harness-only** double — never runtime-selectable, provably absent from shipped artifacts (G1). A **durability-only** in-memory arm stays a **legitimate explicit runtime option** in an honest module, never `Default`/fallback (§17.17 SCP-CAPSEL-8011). **The `allow_in_memory_*` runtime nullifier switch is deleted; the `DidDht` nullifier-default type parameter is deleted.**

### 0. Honest module structure + durability-only storage stays a runtime option (foundational)

Split `scp-platform`'s `pub mod testing` by truth: move `InMemoryStorage`/`InMemoryPush` to `scp-platform/src/in_memory/` behind `in-memory-storage`/`in-memory-push` features (compiled-available; the latter pulls `dep:uuid`), selected explicitly via `StorageConfig` (never default/fallback). Leave the nullifier doubles (`InMemoryKeyCustody`, `InMemoryDeviceAttestation`, `InMemoryPreRotationCustody`) in the `testing`-named module behind `testing`. Delete `pub use testing as software` (`lib.rs:52`). Delete `BridgeInMemoryStorage` (`bridge_runtime.rs:166`+`Handle:275`+`Repo:285`+`build_event_log_provider:315` third tuple element + the `common/src/lib.rs` re-export + the three bridge `runtime.rs` incl. `scp-ffi/src/runtime.rs:1112` + the `uniffi/Cargo.toml:63` comment); bridges use `EncryptingAdapter<scp_platform::in_memory::InMemoryStorage>` (the `EncryptingAdapter<S>` handle is generic, so the shape is preserved). **F1 storage half:** re-point `scp-ffi-common`'s `server` feature `scp-platform/testing` edge to `scp-platform/in-memory-storage` and switch `server.rs`'s non-test storage construction to the `in_memory` path (custody/DHT phantoms are Slices 1/6).

> **Module-naming note.** `in_memory/` houses only the durability-only types; nullifier doubles stay in `testing/`. The durability-vs-nullifier split is *not* inferable from module names alone — the classification lives in §17.17.2 + the table above; the module boundary encodes only "shippable vs test-only," the property G1 greps.

### 1. DHT (E1) — remove the nullifier default, ship real Pkarr, demote in-memory DHT to test-harness-only

**Structural root fix (D-A):** in `scp-identity/src/dht.rs`, **remove the `= InMemoryDhtClient` default type parameter** → `pub struct DidDht<D: DhtClient, C: Clock = SystemClock>` (the `Clock` default stays — `SystemClock` is not a nullifier), and **delete `impl Default for DidDht<InMemoryDhtClient>` and the `pub fn new()` constructor** that hardcode the nullifier. Every caller now constructs with an *explicit* `DhtClient` — `PkarrDhtClient` on production paths, `InMemoryDhtClient` only in `#[cfg(test)]`/`testing` code. This makes E1 **structural**: no silent in-memory DHT default is expressible (SCP-CAPSEL-8002 satisfied by construction). Blast radius (Story 001): `scp-identity/src/{dht.rs,config.rs}` + `Cargo.toml`; `scp-node/src/{self_host.rs,lib.rs,config.rs,Cargo.toml}`; `scp-runtime/src/discovery/{dht_context.rs,did_capabilities.rs}` + `Cargo.toml`; `scp-testing` helpers + `Cargo.toml`; `scp-ffi/common/src/{server.rs,resolvers.rs}`; uniffi `bridge.rs` (`:3912`,`:8063`,`:9010`,`:9130`,`:16714` etc.); every test using `DidDht::new()`.

`production-dht` unconditional on `scp-ffi`/`napi`/`scp-ffi-common`. Shared `enum FfiDhtClient` in scp-ffi-common: `Pkarr(PkarrDhtClient)` compiled unconditionally + `InMemory(InMemoryDhtClient)` `#[cfg(feature = "testing")]`. Retype `bridge_instance.rs:358` + `server.rs:35` onto `FfiDhtClient`; the D-A change compile-forces converting **`server.rs:455`'s `InMemoryDhtClient::new()`** here (moved out of Slice 6). Delete the throwaway clients so rotation/migration use the shared per-instance client (closes #1518/#1880, re-satisfies #627). `ClientDhtConfig { gateways }` + `DhtInitError`; **fail-closed** — unsatisfiable production DHT returns a typed error, never in-memory (M3).

> **scp-dht/testing (cross-crate, coherent with G1).** `InMemoryDhtClient` (`dht_client/mod.rs:93`) is an ungated `pub struct` in a crate that is a **normal dependency**, and `#[cfg(test)]` does not cross crates. Gate the type behind a **new `scp-dht/testing` feature**. `scp-dht` **stays a normal dependency**; each bridge/consumer's own `testing` feature carries `scp-dht/testing` **as a normal feature edge** (so a build that enables `scp-ffi-common/testing` compiles the `feature = "testing"` half of `FfiDhtClient::InMemory`), AND each consumer that constructs `InMemoryDhtClient` in its own tests lists `scp-dht/testing` in its `[dev-dependencies]` (per-crate `cargo test -p X` resolves features per-crate: `scp-node`, `scp-runtime`, `scp-testing`). The invariant is: `scp-dht/testing` MUST NOT appear in any **default / non-testing** feature list — only in `testing` features and dev-dependencies. G1 then checks the shipped (non-`testing`) graph and finds it absent. This is the concrete form of G1's soundness invariant (below): every bridge `testing` feature transitively pulls the checked features, so shipped-graph absence ⇒ type absence.

> **"Baseline" vs "select explicitly."** DHT is Axis-A=1 (one real backend), so there is no runtime *backend* choice — only backend *parameters* (`gateways`) are caller-supplied. §17.17's mandatory-selection rule binds capabilities with ≥2 real backends; a single-real-backend capability is "selected" by being the only compiled arm. Note this is *now* enforced structurally by the D-A default-removal (the caller must name a `DhtClient`), so even the single-backend case is never silently defaulted.

### 2. Key custody — real backends already ship; demote the in-memory arm to test-harness-only

`FfiKeyCustody` (`custody.rs:35`) already ships `File(FileKeyCustody)` (§17.8) + `Callback`, `SqliteKeyCustody` available; the `InMemory` variant is `#[cfg(feature="allow_in_memory_custody")]` — switch-gated, not welded. Demotion is clean: re-gate to `#[cfg(feature = "testing")]`; **remove the public `custody="in_memory"` config value** + seed-import path (`napi/src/scp.rs:379`). No real-backend work needed. (Slice 6.)

### 3. Device attestation — declines the capability (spec §9:187), not "Axis A = 0"

`InMemoryDeviceAttestation` is the only impl and is switch-gated. The authority for shipping *without* device attestation is the spec: **§9 (~:187) states the absence of a device-attestation backend is an expected, conformant state** — a deliberate scoped decline. Demote to `#[cfg(feature = "testing")]`; with the feature off, the operation returns a **typed `Err`** (the secure behavior at `bridge.rs:3622`), never a silent attest-valid no-op. A real backend is ADR-025's separate, unstarted work. (Slice 6.)

### 4. Pre-rotation custody (E5) — OUT OF SCOPE (RFC #2130)

**This ADR does not realize pre-rotation custody.** Production pre-rotation custody is punted to a later e2e-collab stage; its design (the `PreRotationCustodyProvider` seam, the per-profile KMS/HSM and encrypted-offline floors, the §5/§6 ceremony, the hardware-PRF-wrap composition, and the ADR-054 §4 hardware-wrap amendment) is a **proposal in RFC #2130** (pre-rotation recovery custody, tracked by #1729 / #1777), with ADR-054 as its `Proposed` design record. Only the recovery-authority-residence **RULE** is canonical, in spec **§9.7.4.1 item 3a**.

**The in-memory nullifier is severed here; only the real backend is deferred.** Per the standing rule (PR #2132; **CLAUDE.md builder tenet "No dev/test-only stand-ins in production"** + **`.docs/standards/sdk-common.md` §Stub and Placeholder Policy**: "no dev/test-only stand-in may mask a missing production implementation; the prove-absence gate allowlists durability-only features and ZERO nullifiers, no exceptions"; spec §17.17), a test-only nullifier standing in for a missing production backend is *precisely* the anti-pattern this work exists to eliminate — so G1 grants **no** nullifier allowlist exception, not even a "documented, tracked, legible" one. Slice 6 therefore re-gates `InMemoryPreRotationCustody` to `#[cfg(feature = "testing")]` (folded into `testing`, exactly like the custody/attestation nullifiers) and severs it from every shipped path.

**Production create paths fail closed (Option B).** Verified finding: the core create signatures (`crates/scp-identity/src/dht.rs:2073` `create`, `:1100` `create_with_agent_key`, and the internal builder) **require** a `PreRotationCustody` impl and always commit a `PreRotationCommitment` — there is **no non-committing create path** today (the tolerance at `:2608` is on the verify/migration side, not creation; and `scp-identity/src/config.rs:334` itself mints an `InMemoryPreRotationCustody`). Because the `config.rs:334` lowering mints `InMemoryPreRotationCustody` for **every** custody kind, once the nullifier is test-only the ~15+ production weld sites won't compile against it — they MUST return a **typed error** (a new `IdentityError` variant / SCP-IDENT code: *"no production pre-rotation custody backend available; pre-rotation recovery custody is not yet implemented — see #1729 / RFC #2130"*). **All production identity creation** — File/Sqlite/callback custody *and* `scp-node` self-host, every path through `config.rs:334`, not merely the callback bridges — returns this error until #1729 lands a real backend. This is acceptable (pre-release, tracked) and is the honest fail-closed state — never a silent fallback to the nullifier. **Node self-provisioning of its own identity is itself a separate defect under correction (issue #2135, "node is not a participant").** So the fact that `scp-node` self-host create now fails closed is honest and consistent — the node should not be minting its own participant identity in the first place — not a regrettable side effect of this severance. **Pre-severance / migration note:** any identity created *before* this severance holds a valid-but-non-durable pre-rotation commitment backed by a process-local in-memory key that is lost on restart (so it can never actually complete a §9.12 migration); this is moot pre-release, as there are no persisted production identities to migrate. **Whether identity creation should ever proceed *without* a pre-rotation commitment (ephemeral / opt-out non-committing identities) is Discussion #1553's decision, made alongside #1729 — not this slice.** This ADR does not invent a non-committing create path.

### 5. Credentials (E2), blob (E3), relay querier (E4) — classified + storied now (live SCP-CAPSEL fixes)

These are **not** "later slices, not yet storied" (that would be the deferral this ADR forbids). Each is classified (table above) and gets a real story (Slices 9–11), authored now:

- **E2 credentials (Slice 9).** `BridgeCredentialStore` is RPITIT → an `enum FfiCredentialStore { Durable(..), #[cfg(feature = "testing")] InMemory }`; **delete `impl Default` (`credentials.rs:556`) — a LIVE SCP-CAPSEL-8000/8011 violation, not deferrable** — and require an explicit selection with a real durable backend. (Classified durability-only: RAM-only tokens are re-obtainable by re-auth; the selection-boundary fix is the security-relevant part.)
- **E3 blob (Slice 10).** **Delete `impl Default for BlobStorageBackend` (`storage.rs:561`) — a LIVE SCP-CAPSEL-8011 violation** — and require the arm at relay/node init. `InMemoryBlobStore` stays durability-only, explicit-only (§17.7 ships Sqlite/redb/Postgres/S3).
- **E4 relay querier (Slice 11).** Classified (resolved from spec + code): `NoOpRelayQuerier` **fails CLOSED, so it is NOT an SCP-CAPSEL nullifier** — its `query` returns `Ok(None)` (`resolver.rs:309`), the `DualLayerResolver` falls back to DHT-only, and when both layers find nothing it returns honest not-found `Ok(None)`, never a fabricated document (§3.10.4 "MUST NOT fabricate"). DHT-only resolution is spec-permitted for *correctness* (§3.10.6 makes dual-layer *resolution* a SHOULD, dual-layer *publish* the MUST — so every conformant identity is on the DHT); authenticity/reachability/freshness are preserved. What `NoOpRelayQuerier` reduces is the §3.10.8 dual-layer **suppression resilience** — a defense-in-depth availability property (it lowers a suppression attack from "all relays AND the DHT" to "the DHT alone," but the outcome of a successful suppression is a fail-closed not-found, never a false answer). So E4 is a **completeness / defense-in-depth gap**, not a nullifier: `NoOpRelayQuerier` **ships honestly as the DHT-only interim** (it need not be gated/absent at Slice 6, and G1-green Slices 6–11 is sound), and the remediation is **implement the real `MultiRelayQuerier` per §3.10.12** to restore the dual-layer defense-in-depth. This dissolves the SCP-CAPSEL-8012-vs-shipped tension the earlier draft manufactured by mis-labeling it a nullifier.

### 6. Delete the runtime nullifier switch; sever `testing` from shipped graphs; G1 (depends on Slice 1)

Sever **all four** in-memory nullifiers — custody, attestation, DHT, and pre-rotation — to test-harness-only: **delete `allow_in_memory_custody` entirely** (feature defs, every `#[cfg]` site, scp-runtime doc-prose, CLAUDE.md clippy string, `ci.yml`/`release.yml` strings); re-gate `FfiKeyCustody::InMemory`, `InMemoryDeviceAttestation`, **and `InMemoryPreRotationCustody`** to `#[cfg(feature = "testing")]` (all folded into the `testing` feature — pre-rotation gets **no** standalone allowlisted feature); remove the public `custody = "in_memory"` config; sever the `scp-platform/testing` edges (`scp-ffi/Cargo.toml:51`, `napi/Cargo.toml:55`, F1 `scp-ffi-common` `server`) and `dep:scp-testing` into each bridge's `testing` feature / dev-deps. **Pre-rotation fail-closed (§Decision 4):** the ~15+ production weld sites that construct `Arc<InMemoryPreRotationCustody>` (bridges + `scp-identity/src/config.rs:334`) no longer compile against the now-test-only type; they return a **typed `IdentityError`** ("no production pre-rotation custody backend available … #1729 / RFC #2130") — never a fallback to the nullifier. **F1 custody retype:** `server.rs`'s `IdentitySource<InMemoryKeyCustody>` phantoms (`:322`,`:435`) → `FileKeyCustody`, drop the `testing` use (the `:455` DHT constructor was already converted in Slice 1). Add **G1** asserting `in-memory-custody`, `in-memory-attestation`, `in-memory-pre-rotation` (i.e. the whole `scp-platform/testing` feature), `scp-dht/testing`, `scp-testing`, and the `scp-core/testing → scp-protocol/testing → scp-did/testing` did:key chain **all absent** — **the allowlist permits durability-only features only; ZERO nullifiers, no exceptions.**

### Dispatch mechanism (per trait object-safety)
RPITIT traits — **not object-safe** — dispatch via a no-`Default` **enum** whose in-memory arm is `#[cfg(feature = "testing")]`: `scp_dht::DhtClient`, `KeyCustody`, `Storage`, `BridgeCredentialStore`. (`PreRotationCustody` is also RPITIT and would follow the same enum shape, but its realization is out of scope — RFC #2130.) Object-safe async-trait traits (`ContextPersistence`) → required non-`Option` `Arc<dyn Trait>`. ADR-049's ban is the lock-free-read hot path only; these are write/setup paths.

> **Single activation path (A5).** Every nullifier in-memory enum arm is gated by `#[cfg(feature = "testing")]` **only** — not `#[cfg(any(test, feature = "testing"))]`. A bare `test` cfg is a *second* activation path that (a) does not cross crates (an integration or downstream test would not compile the arm) and (b) is invisible to G1's feature-graph check. Gating solely on the `testing` feature gives one uniform activation path, so **feature-absence ≡ type-absence** holds for G1, and the arm compiles for every consumer that enables `…/testing` (via the normal-edge dev-dep wiring, §Decision 1). In-crate unit tests that need the arm run with `--features testing` (already the workspace test/clippy invocation).

### Switch-dissolution corollary
With no runtime nullifier gate there is no `allow_in_memory_*` feature to name, `# DANGER`-mark, single-source, or split 2-vs-5. The remaining honest cargo features are positive: durability-only `in-memory-storage`/`in-memory-push`, and the pre-existing `testing` test-harness feature.

## Enforcement
- **G1 — prove-absence gate (`scripts/check-shipped-feature-graph.sh`), a SOLE closed whitelist.** For each shipped artifact, mirror its exact build invocation, derive the **complete resolved feature set** from the artifact's own build config (never a hand-list), and assert **`resolved-feature-set(artifact) ⊆ an explicit per-artifact permitted-prod-features allowlist`**. Anything in the resolved set that is not on the allowlist — *named or not, present or future* — FAILS. This is the **sole mechanism**; there is no denylist of specific testing-feature names. (A denylist of `scp-platform/testing`/`scp-dht/testing`/`scp-testing` is **fail-open** — a fourth nullifier feature, or the transitive `scp-protocol/Cargo.toml:47` `testing = ["scp-did/testing", …]` did:key edge, bypasses it. The three names may appear only as a script comment/example, never as the check.) Run per artifact **including `--features server`** (F1 backstop). **The allowlist permits durability-only features only (`in-memory-storage`/`in-memory-push`) — ZERO nullifiers, no exceptions.** There is *no* allowlisted nullifier edge, not even a "documented/tracked/legible" one: per the standing rule (PR #2132; CLAUDE.md builder tenet "No dev/test-only stand-ins in production" + `.docs/standards/sdk-common.md` §Stub and Placeholder Policy; spec §17.17), a dev/test-only nullifier masking a missing production backend is the forbidden anti-pattern, so an allowlisted nullifier would defeat the gate's whole purpose. The pre-rotation nullifier is instead severed to test-harness-only and its shipped create-path fails closed (§Decision 4/6). **Soundness invariant (stated + machine-checked):** every bridge/consumer `testing` feature transitively pulls the checked test-harness features (so a `testing` feature can never define nullifier code reachable without them); combined with the ⊆-allowlist this makes shipped-graph feature-absence equivalent to nullifier-type absence. G1 tightens per slice (DHT allowlist tightened at Slice 1; custody/attestation/pre-rotation all absent from Slice 6 onward).
- **Semantic capability-matrix dimension** (`check-sdk-coverage.py`): record each binding's shipped backend per capability (DHT → Pkarr; custody → File/Sqlite/Callback). Slice 6 fixes the **4 stale `allow_in_memory_custody` device-attestation strings** in `sdk-capability-matrix.json` (`:119/:120/:131/:132`). The pre-rotation matrix row is RFC #2130's when that work executes.
- **Not added:** no runtime nullifier switch; no `# DANGER` convention; no source/AST gate re-checking a type-system property.

## Consequences
- **No *classified-and-gated* nullifier is reachable in a shipped artifact** — not by default (the `DidDht` default type param is gone), fallback, or runtime config. This is precise about what each mechanism buys: G1 proves the *gated* nullifiers (behind `…/testing`) absent from the shipped feature graph; it does not, and cannot, prove that *every* capability has been classified — **classification-completeness is §17.17.2's mandate** (every capability's dev arm classified before it ships), enforced by the classification table above + review, not by G1. Together they close the loop: the table classifies all seven capabilities; the nullifiers among them are gated; G1 proves the gated ones absent. **E2 credentials, E3 blob, E4 relay-querier are classified + storied (Slices 9–11)** — E2/E3 in-memory arms (durability-only) ship until their slices land, but their live `impl Default` SCP-CAPSEL violations are the storied fixes, not hidden residue; E4 (`NoOpRelayQuerier`) is not a nullifier and ships honestly as the DHT-only interim (§Decision 5). G1 tightens per slice.
- **Pre-rotation in-memory nullifier is SEVERED here; production creation fails closed.** The `InMemoryPreRotationCustody` nullifier is re-gated `#[cfg(feature = "testing")]` and is absent from every shipped artifact (G1 allowlists zero nullifiers). Because there is no real backend to fall back to, **all production identity creation** — every custody kind (File/Sqlite/callback) plus `scp-node` self-host, all funneling through the `config.rs:334` lowering — returns a typed error until #1729 / RFC #2130 lands one — the honest fail-closed state, never a silent nullifier. (Node self-provisioning failing closed is consistent with #2135, "node is not a participant," under separate correction — the node should not self-mint an identity anyway.) Only the *real backend* is out of scope; the nullifier is gone now. (Whether creation may proceed with no pre-rotation commitment at all is #1553, decided with #1729.)
- **In-memory storage stays usable** as an explicit honest runtime option (OpenMLS parity).
- **did:key / `scp-testing` chain severed by construction** — and G1's ⊆-allowlist (not a 3-name denylist) closes the `scp-protocol/Cargo.toml:47 → scp-did/testing` bypass.
- **Binary size/build time:** unconditional `production-dht` adds mainline+reqwest (rustls, pure Rust); a bare-production release job must exist so the graph is G1-checked.
- **No migration burden** (pre-release).

## Alternatives considered
- **Nullifiers runtime-selectable behind a well-named switch — REJECTED** (Axis 2: insecure custody/verifier/resolver is never a runtime option).
- **Keep `DidDht<D = InMemoryDhtClient>` default type param + fix only the FFI wiring — REJECTED** (the default binds the nullifier for every `::new()`/`::default()` caller; the E1 bug recurs the next time someone writes `DidDht::new()`. Remove the default; make it structural — D-A).
- **Node keeps a runtime `DhtMode::Memory` in-memory DHT path — REJECTED (D-B, §Non-goals).** In-memory DHT is a §17.17.3 nullifier on *resolve* (fail-open); the node's legit no-publish need is served by a fail-closed `DhtMode::Disabled`.
- **Document pre-rotation in-memory as a "backend-pending residue" + weaken SCP-CAPSEL-8012 — REJECTED and reverted.**
- **`Arc<dyn>` for the RPITIT seams — rejected** (not object-safe; the enum shape is used for `DhtClient`/`KeyCustody`/`Storage`/`BridgeCredentialStore`).
- **In-memory *storage* test-harness-only too — rejected** (durability-only; removing it loses a legitimate dev option for no security gain).
- **G1 as a denylist of named testing features — REJECTED (3-reviewer converge)** (fail-open; a 4th nullifier feature or the `scp-protocol/testing`→`scp-did/testing` edge bypasses it; only a closed ⊆-allowlist is sound).
- **E2/E3/E4 "scheduled but not storied" — REJECTED** (deferral dressed as a decision; §17.17.2 forbids an unclassified/unfixed shipped capability; E2/E3 `impl Default` are live violations).
- **Allowlist the pre-rotation nullifier as a "documented, tracked, legible" exception — REJECTED (maintainer ruling + PR #2132).** A dev/test-only nullifier masking a missing production backend is exactly the anti-pattern this work eliminates; G1 allowlists ZERO nullifiers, no exceptions. The nullifier is severed and creation fails closed instead.
- **Fake a pre-rotation commitment with the nullifier, or fall back to it silently — REJECTED.** Falling back to `InMemoryPreRotationCustody` when no real backend is configured is the silent-nullifier hazard; production fails closed with a typed error (§Decision 4).
- **Invent a non-committing production create path (Option A) — REJECTED / out of scope.** No non-committing create path exists today (verified: creation always commits, dht.rs:2073); building one — i.e. whether identities may exist without a pre-rotation commitment — is Discussion #1553, decided alongside #1729, not this slice.
- **Build the real pre-rotation backend in this ADR — deferred (RFC #2130 / #1729).** The *backend* is a separately-scoped e2e-collab stage not being executed now (a real external constraint). The *nullifier severance* is done here; only the backend is deferred. The §3a residence *rule* stays canonical in spec §9.7.4.1 item 3a.

**Node DHT reconciliation (D-B) — supersedes construction.md M2's `DhtMode::Memory` framing.** In-memory DHT is a §17.17.3 nullifier on *resolve* (`build_memory_did_method` builds a `DidDht<InMemoryDhtClient>` used for both publish *and* resolve, so a Memory-mode node resolves peers via a local map — silently nothing). It is therefore **not a shipped runtime option**: `DhtMode::Memory` becomes **test-harness-only** (gated behind `feature = "testing"`), and the node's legitimate no-DHT need is served by a new **`DhtMode::Disabled`**.

**`Disabled` is DHT-*layer*-off, not resolution-off (A2).** A `Disabled` node does not publish to, nor resolve via, the DHT layer; DID resolution composes the **relay layer only** (the `DualLayerResolver` still runs, with its DHT arm turned off). The DHT arm, when off, contributes `Ok(None)` (fail-closed — it never returns a silent in-memory answer). `DhtMode::Production` (real Pkarr, publish+resolve) is unchanged. This keeps M2's *publish* fail-safe (Disabled discloses no address) while fixing the *resolve* nullifier M2 never reasoned about.

**A2↔A4 sequencing (stated, not hand-waved).** The relay resolution layer is `NoOpRelayQuerier` (returns `Ok(None)`) until **Slice 11** builds the real `MultiRelayQuerier` (§3.10.12). Therefore, between Slice 1 and Slice 11, a `Disabled` node has **no working resolution path** — DHT arm off + relay arm NoOp ⇒ every resolve returns honest not-found `Ok(None)` (fail-closed, never a false or in-memory answer). **Honest disclosure of the trade-off (not a clean win).** The flip from the old `DhtMode::Memory` default to the new `DhtMode::Disabled` default is strictly *more honest only for **external** DIDs* — which never resolved under `Memory` either, since `Memory`'s in-memory map is process-local and never held a peer's document. For the node's **own** DID the flip is a **functional regression**: under `Memory`, a node published its own DID document into the local in-memory map, so **self-DID resolution worked** — a co-located single node could resolve its own DID, which is exactly what co-located governance vote-signature verification consumes (`scp-node/src/self_host.rs`, `colocated_document_vm_key_resolver`). Under `Disabled`, the DHT arm returns `Ok(None)` for **everything, including the node's own DID**, until Slice 11's relay-resolution layer lands. So **self-DID resolution regresses**: co-located single-node governance is **inert between Slice 1 and Slice 11** — every governance vote-signature verification fail-closes to not-found. Name it plainly: a typed fail-closed not-found for the node's own DID replaces a working in-memory self-resolution — that **is** a self-DID resolution regression for the co-located case, **disclosed here rather than papered over**. It is a time-boxed consequence remedied by **Slice 11's relay-resolution layer** (after which a `Disabled` node resolves both its own and peers' DIDs via the relay), and it is consistent with the fail-closed principle: a typed not-found is honest — it does not fabricate a document — and the sequencing *decision* (Slice 1 vs Slice 11) is itself unchanged and sound; only its earlier "not a regression" framing was wrong. Once Slice 11 lands, a `Disabled` node resolves peers via the relay layer. **The node/host_site default flips from `DhtMode::Memory` to `DhtMode::Disabled`** (`config.rs:391`, `self_host.rs:976`) — the fail-safe no-publish value, now fail-closed on resolve. construction.md M2's "`DhtMode::Memory` (no publish) is the fail-safe" text (sites `:53`,`:63`,`:165`,`:194`, incl. `HostSiteConfig`) is updated to name `Disabled` as the fail-safe no-publish value and `Memory` as test-harness-only (Slice 1 edits construction.md; the M2 *disclosure* reasoning is unchanged — `Disabled` discloses nothing).
