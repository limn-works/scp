**Status:** Proposed (2026-07-14).

**Relates to / upstream basis:** The umbrella spec section **§17.17 — "Capability Selection Is Mandatory, Fails Closed, and Never Defaults"** (normative IDs **SCP-CAPSEL-8000/8001/8002** mandatory / fails-closed / never-default; **SCP-CAPSEL-8010/8011/8012** durability-only-vs-nullifier classification, incl. §17.17.2's "classification is mandatory before a capability ships"; **§17.17.3 / SCP-CAPSEL-8013** in-memory-DHT nullifier). Honest framing: §17.17 was authored alongside this ADR and §17.17.2 names ADR-062 as its realization — it is not an independently-pre-existing authority. Its force rests on its own argument (esp. §17.17.3's durability-vs-nullifier reasoning), not on age; this ADR realizes it and adds no exception to it. **ADR-054 (Pre-Rotation Key Custody — Substrate Isolation) is ACCEPTED (2026-07-14)**; it is the design authority for the pre-rotation seam, the per-profile backend floors, and the §5 selection ceremony this ADR schedules, and its normative rule lives spec-first as **§9.7.4.1 item 3a (recovery-authority residence)**. Also relates to: ADR-052 + `.docs/standards/construction.md` (M1–M5; **M2** required-or-fail-safe-defaulted, **M3** fail-loud-never-silent-no-op — this ADR updates M2's `DhtMode` reasoning, §Non-goals); ADR-048 (multi-instance FFI); ADR-049 (no `dyn`/lock on the lock-free-**read** hot path only); ADR-006 (in-memory adapters); ADR-025 (device-attestation backend — separate, unstarted; §Decision 3); ADR-055/-057 (browser thin-client; WASM removed). Spec §9.7.4.1 (Pre-Rotation Key Custody: item 3a / §4 / §5 / §6), §9.12 (Migration & Recovery), §17.6/§17.7 (storage/BlobStore), §3.9/§3.10.3/§3.10.5/§3.10.6/§3.10.7/§3.10.8/§3.10.10/§3.10.12 (DHT resolution + Anti-Segmentation MUST + dual-layer suppression resilience + relay resolution).

**Motivating defects:** #627 (CLOSED, unmet — `production-dht` never enabled for PyO3/NAPI), #1518 (`ConcreteDidMethod` locks the shared FFI layer to `InMemoryDhtClient`), #1880 (rotation/migration publish through a fresh non-shared client that never reaches/invalidates the resolver). **#1733 (eliminate `scp_platform::testing` imports from production paths + CI enforcement) is FOLDED** and closed-as-folded at Slice 6 (§Folding #1733). ## Context

SCP's provider capabilities each carry a "which implementation?" choice; a 2026-07 audit found several resolved to an **insecure in-memory arm reachable on the shipped path or offered as a runtime backend option**. Findings, descending severity:

- **E1 (HIGH) — DHT.** PyO3/NAPI ship `InMemoryDhtClient`; UniFFI ships real `PkarrDhtClient`. `production-dht` is on `uniffi/Cargo.toml` but not `scp-ffi/Cargo.toml`/`napi/Cargo.toml`. **Root cause is structural, not a wiring miss:** `scp-identity/src/dht.rs:222` declares `pub struct DidDht<D: DhtClient = InMemoryDhtClient, C = SystemClock>` — a **default type parameter that silently binds the nullifier** — with `impl Default for DidDht<InMemoryDhtClient>` (`:264`) and `pub fn new()` (`:270`) both hardcoding `InMemoryDhtClient::new()`. Every `DidDht::new()`/`::default()` call (chokepoints `bridge_instance.rs:358`, `server.rs:35`, and ~10 uniffi/resolver sites) therefore gets in-memory DHT for free. This is the E1 bug's origin (SCP-CAPSEL-8002 violation: the runtime defaults a backend). #1880: rotation/migration mint a fresh non-shared client (`identity.rs:203-204`, `napi/identity.rs:246`, uniffi `make_dht_with_signer`).
- **E2 (HIGH) — credentials.** `InMemoryCredentialStore` ("Not suitable for production," `credentials.rs:502-506`, `impl Default :556`) wired on shipped NAPI+PyO3 as a **hardcoded concrete type** (`napi/runtime.rs:313`). The `impl Default` is a **LIVE SCP-CAPSEL-8000/8011 violation** (a default selection) shipping now — see §Decision 5.
- **E3 (MED) — blob storage.** `BlobStorageBackend::InMemory` un-`cfg`'d (`storage.rs:480`), `impl Default → in_memory()` (`:561`) — a **LIVE SCP-CAPSEL-8011 violation** (durability-only arm as default). §Decision 5.
- **E4 (MED) — relay querier.** `NoOpRelayQuerier` (`resolver.rs:309`) is the shipped relay-resolution arm; no real `MultiRelayQuerier` exists yet (§3.10.12 is unimplemented). §Decision 5 classifies it.
- **E5 (HIGH) — pre-rotation custody.** `pre_rotation_custody: Arc<scp_platform::testing::InMemoryPreRotationCustody>` is an **ungated concrete field constructed on ~12 shipped create-path sites** (enumerated in §Decision 4). The pre-rotation key is SCP's recovery backstop (§9.7.4.1, §9.12); holding it in shared process memory violates §9.7.4.1 §3/§3a. Fixed by building the real per-profile backends per accepted ADR-054.
- **F1 (HIGH, the "other weld") — the `server` feature path.** `scp-ffi-common` `server = […, "scp-platform/testing"]` (`common/Cargo.toml:30`) is **unconditional**, and `server.rs` non-test code references `InMemoryKeyCustody`/`InMemoryStorage`, `IdentitySource<InMemoryKeyCustody>` phantoms (`:322`,`:435`), and `InMemoryDhtClient::new()` (`:455`). Same weld as E5 for the node-hosting artifact. `server.rs`+`common/Cargo.toml` are enumerated in Slice 0 (storage path/feature) and Slice 1 (the `:455` DHT constructor, compile-forced by the D-A retype) and Slice 6 (the custody phantoms `:322`/`:435`).

**Root cause (the pattern).** The FFI security switch that should select *primitives* is defined in terms of *use-cases*: `allow_in_memory_custody` (`scp-ffi:27`, `napi:15`, `uniffi:32` — already drifted) is a **runtime backend selector** that makes `FfiKeyCustody::InMemory`, in-memory attestation, and in-memory DHT runtime-selectable, and NAPI exposes a public `custody = "in_memory"` config value (`napi/src/scp.rs:379`) — treating an insecure nullifier as a legitimate menu option. E1's `DidDht` default type parameter is the same disease at the type level (the type system *defaults* to the nullifier).

## Ecosystem convention (why this design)

Three-axis primary-source survey:
- **Axis 1 — test doubles are compile-time/test-code, not runtime options.** In-memory fakes live in a `*-test-util` dev-dep crate or a `testing`/`test-util` feature kept out of default/`full`, constructed in test code, absent from a normal build (idiomatic Rust).
- **Axis 2 — insecure custody/verifiers are never runtime-selectable; in-memory *storage* is a legitimate pluggable option.** `rustls` quarantines dangerous config behind a `danger` module; `webauthn-rs` gates insecure verification behind `danger-*`; OWASP "secure by default." Conversely **OpenMLS ships `MemoryStorage`** as a first-class pluggable provider — losing state is durability-only, not a nullification. This is §17.17's durability-vs-nullifier line.
- **Axis 3 — recovery custody is a pluggable backend menu.** Signal SVR, Apple ADP, passkey PRF expose recovery as a menu (HSM, cloud-HSM, device enclave, offline). ADR-054 specifies this menu for pre-rotation and — post-acceptance — resolves the per-profile *floors* (server = independent-principal KMS/HSM; interactive = user-passphrase encrypted-offline + hardware).

## The split (execution units)

- **Unit 1 (clean, executable now, no upstream wait): Slice 0 (module structure) + Slice 1 (DHT E1, incl. the `DidDht` default-type-param removal).** Fixes the original E1 shipped-in-memory-DHT bug at its structural root. Depends on nothing unsettled.
- **Unit 2 (built on accepted ADR-054): pre-rotation backends per profile + §5 ceremony + §6 re-selection (Slices 2–5, 7–8 native) + nullifier severance (Slice 6).**
- **Unit 3 (live SCP-CAPSEL fixes + completeness): E2/E3/E4 (Slices 9–11).** Their selection-boundary fixes (delete `impl Default`) are live SCP-CAPSEL violations, not deferrable; sequenced after Unit 1/2 by gate but storied now (§17.17.2 forbids leaving a capability unclassified/unfixed).

## Decision

**Principle.** Every capability whose in-memory arm is a **security nullifier** is fixed by (1) shipping **real production backend(s)** behind a proper dispatch seam and (2) demoting the in-memory nullifier to a **test-harness-only** double — never runtime-selectable, provably absent from shipped artifacts (G1). A **durability-only** in-memory arm stays a **legitimate explicit runtime option** in an honest module, never `Default`/fallback (§17.17 SCP-CAPSEL-8011). **The `allow_in_memory_*` runtime nullifier switch is deleted; the `DidDht` nullifier-default type parameter is deleted.**

### 0. Honest module structure + durability-only storage stays a runtime option (foundational)

Split `scp-platform`'s `pub mod testing` by truth: move `InMemoryStorage`/`InMemoryPush` to `scp-platform/src/in_memory/` behind `in-memory-storage`/`in-memory-push` features (compiled-available; the latter pulls `dep:uuid`), selected explicitly via `StorageConfig` (never default/fallback). Leave the nullifier doubles (`InMemoryKeyCustody`, `InMemoryDeviceAttestation`, `InMemoryPreRotationCustody`) in the `testing`-named module behind `testing`. Delete `pub use testing as software` (`lib.rs:52`). Delete `BridgeInMemoryStorage` (`bridge_runtime.rs:166`+`Handle:275`+`Repo:285`+`build_event_log_provider:315` third tuple element + the `common/src/lib.rs` re-export + the three bridge `runtime.rs` incl. `scp-ffi/src/runtime.rs:1112` + the `uniffi/Cargo.toml:63` comment); bridges use `EncryptingAdapter<scp_platform::in_memory::InMemoryStorage>` (the `EncryptingAdapter<S>` handle is generic, so the shape is preserved). **F1 storage half:** re-point `scp-ffi-common`'s `server` feature `scp-platform/testing` edge to `scp-platform/in-memory-storage` and switch `server.rs`'s non-test storage construction to the `in_memory` path (custody/DHT phantoms are Slices 1/6).

> **Module-naming note.** `in_memory/` houses only the durability-only types; nullifier doubles stay in `testing/`. The durability-vs-nullifier split is *not* inferable from module names alone — the classification lives in §17.17.2 + the table above; the module boundary encodes only "shippable vs test-only," the property G1 greps.

### 1. DHT (E1) — remove the nullifier default, ship real Pkarr, demote in-memory DHT to test-harness-only

**Structural root fix (D-A):** in `scp-identity/src/dht.rs`, **remove the `= InMemoryDhtClient` default type parameter** → `pub struct DidDht<D: DhtClient, C: Clock = SystemClock>` (the `Clock` default stays — `SystemClock` is not a nullifier), and **delete `impl Default for DidDht<InMemoryDhtClient>` and the `pub fn new()` constructor** that hardcode the nullifier. Every caller now constructs with an *explicit* `DhtClient` — `PkarrDhtClient` on production paths, `InMemoryDhtClient` only in `#[cfg(test)]`/`testing` code. This makes E1 **structural**: no silent in-memory DHT default is expressible (SCP-CAPSEL-8002 satisfied by construction). Blast radius (Story 001): `scp-identity/src/{dht.rs,config.rs}` + `Cargo.toml`; `scp-node/src/{self_host.rs,lib.rs,config.rs,Cargo.toml}`; `scp-runtime/src/discovery/{dht_context.rs,did_capabilities.rs}` + `Cargo.toml`; `scp-testing` helpers + `Cargo.toml`; `scp-ffi/common/src/{server.rs,resolvers.rs}`; uniffi `bridge.rs` (`:3912`,`:8063`,`:9010`,`:9130`,`:16714` etc.); every test using `DidDht::new()`.

`production-dht` unconditional on `scp-ffi`/`napi`/`scp-ffi-common`. Shared `enum FfiDhtClient` in scp-ffi-common: `Pkarr(PkarrDhtClient)` compiled unconditionally + `InMemory(InMemoryDhtClient)` `#[cfg(any(test, feature = "testing"))]`. Retype `bridge_instance.rs:358` + `server.rs:35` onto `FfiDhtClient`; the D-A change compile-forces converting **`server.rs:455`'s `InMemoryDhtClient::new()`** here (moved out of Slice 6). Delete the throwaway clients so rotation/migration use the shared per-instance client (closes #1518/#1880, re-satisfies #627). `ClientDhtConfig { gateways }` + `DhtInitError`; **fail-closed** — unsatisfiable production DHT returns a typed error, never in-memory (M3).

> **scp-dht/testing (cross-crate, coherent with G1).** `InMemoryDhtClient` (`dht_client/mod.rs:93`) is an ungated `pub struct` in a crate that is a **normal dependency**, and `#[cfg(test)]` does not cross crates. Gate the type behind a **new `scp-dht/testing` feature**. `scp-dht` **stays a normal dependency**; each bridge/consumer's own `testing` feature carries `scp-dht/testing` **as a normal feature edge** (so a build that enables `scp-ffi-common/testing` compiles the `feature = "testing"` half of `FfiDhtClient::InMemory`), AND each consumer that constructs `InMemoryDhtClient` in its own tests lists `scp-dht/testing` in its `[dev-dependencies]` (per-crate `cargo test -p X` resolves features per-crate: `scp-node`, `scp-runtime`, `scp-testing`). The invariant is: `scp-dht/testing` MUST NOT appear in any **default / non-testing** feature list — only in `testing` features and dev-dependencies. G1 then checks the shipped (non-`testing`) graph and finds it absent. This is the concrete form of G1's soundness invariant (below): every bridge `testing` feature transitively pulls the checked features, so shipped-graph absence ⇒ type absence.

> **"Baseline" vs "select explicitly."** DHT is Axis-A=1 (one real backend), so there is no runtime *backend* choice — only backend *parameters* (`gateways`) are caller-supplied. §17.17's mandatory-selection rule binds capabilities with ≥2 real backends; a single-real-backend capability is "selected" by being the only compiled arm. Note this is *now* enforced structurally by the D-A default-removal (the caller must name a `DhtClient`), so even the single-backend case is never silently defaulted.

### 2. Key custody — real backends already ship; demote the in-memory arm to test-harness-only

`FfiKeyCustody` (`custody.rs:35`) already ships `File(FileKeyCustody)` (§17.8) + `Callback`, `SqliteKeyCustody` available; the `InMemory` variant is `#[cfg(feature="allow_in_memory_custody")]` — switch-gated, not welded. Demotion is clean: re-gate to `#[cfg(any(test, feature="testing"))]`; **remove the public `custody="in_memory"` config value** + seed-import path (`napi/src/scp.rs:379`). No real-backend work needed. (Slice 6.)

### 3. Device attestation — declines the capability (spec §9:187), not "Axis A = 0"

`InMemoryDeviceAttestation` is the only impl and is switch-gated. The authority for shipping *without* device attestation is the spec: **§9 (~:187) states the absence of a device-attestation backend is an expected, conformant state** — a deliberate scoped decline. Demote to `#[cfg(any(test, feature="testing"))]`; with the feature off, the operation returns a **typed `Err`** (the secure behavior at `bridge.rs:3622`), never a silent attest-valid no-op. A real backend is ADR-025's separate, unstarted work. (Slice 6.)

### 4. Pre-rotation custody (E5) — build the real per-profile backends now, per accepted ADR-054

ADR-054 is **Accepted**; §9.7.4.1 item 3a is the governing normative rule. This ADR **cites** ADR-054's resolved decisions (does not re-decide them) and **schedules** the realization as explicit stories/gates.

**Seam (RPITIT → enum, mirroring `FfiKeyCustody`).** `PreRotationCustody` is RPITIT (`traits.rs:759/772/782`) → not object-safe → the seam is an **`enum FfiPreRotationCustody`**, NOT `Arc<dyn>` and NOT a bare `Arc<CallbackPreRotationCustody>` (which cannot hold the KMS/offline/test arms). **Arms land with their backends (no front-loaded stubs):**

- **Slice 2** introduces the enum with only `Callback(CallbackPreRotationCustody)` + `#[cfg(any(test, feature = "testing"))] InMemory(InMemoryPreRotationCustody)`.
- **Slice 3** extends it with `IndependentPrincipal(KmsPreRotationCustody)` **and its backend**.
- **Slice 4** extends it with `EncryptedOffline(EncryptedOfflinePreRotationCustody)` **and its backend**.

Add `PreRotationCustody` to the Dispatch-mechanism list (below). **Retype all ~12 welded create-path sites** onto `FfiPreRotationCustody`: `scp-ffi/src/identity.rs:987`, `runtime.rs:1984`; `napi/src/identity.rs:1130`, `runtime.rs:1385`, `napi/src/scp.rs:456/587/729`; `uniffi/src/bridge.rs:2467/9016/9136/9219/16716/20825/22590`. **Two of these are `identity_create_with_custody` sites** (napi `scp.rs`, uniffi `bridge.rs:9136`) carrying the live comment "in-memory custody used here, production callback = follow-up"; these MUST bind to the **`Callback` arm** (caller-supplied custody backs pre-rotation too) — a blanket "0 InMemory references" AC MUST NOT be satisfiable by routing `with_custody` through the fail-closed/`EncryptedOffline` path, which would silently drop the caller-custody semantic.

**Per-profile floors (ADR-054 OQ2, spec §9.7.4.1 item 3a(a)/(b)) — cited:**
- **Non-interactive server (Python/TS/`scp-node`):** floor = **independent-principal KMS/HSM/cloud-vault** (`KmsPreRotationCustody`); the operational principal holds no read/use/decrypt/**assume/delegate** grant over the recovery authority or any KEK/role in its wrapping/derivation chain. **No configured independent-principal substrate ⇒ identity creation MUST fail closed** (§3a(a)).
- **Interactive client:** floor = **encrypted-offline with a user-supplied per-recovery passphrase never persisted server-reachably** (§3a(b)) + a **minimum-strength check** (below), **plus** hardware/enclave/cloud backends where the platform offers them.
- **Full §4 menu per profile** offered where ADR-054's per-backend §3-soundness table marks each sound; the SDK MUST NOT offer a non-conforming backend as a standalone floor where the table marks it unsound.

**Minimum-strength check (concrete).** The user-supplied interactive passphrase MUST provide **≥ 128 bits of guessing entropy against the published Argon2id parameters** (memory=64 MiB, iter=3, parallelism=4). Implementations MUST reject inputs below this floor using a real strength estimator (e.g. a zxcvbn-class estimator with a guess-count threshold equivalent to ≥ 2^128 offline guesses given the Argon2id cost), not a length heuristic.

**§5 selection ceremony + §6 re-selection (full scope, scheduled).** §5: present custody options ordered by security, **filtered to §3a-conforming for the active profile**; the non-interactive-server branch replaces the plural prompt with selection of an operator-configured independent-principal backend and **fails closed if none configured**. §6: the post-migration key re-enters §3a-conforming custody (re-run §5). **§5 plural-MUST:** on the interactive profile the floor is "≥1 §3a-conforming backend," so a single-option menu is conformant only when the platform offers exactly one; where more exist they MUST all be presented — the native-hardware stories (Slices 7/8) + the Python/TS FIDO2 stories (Slices 12/13, D-C) make the menu genuinely plural where a higher-security method is reachable.

**Conformance = the ADR-054 PAIR — BOTH tests (not just part 1).** ADR-054 §Strengthened-conformance-test requires **both**: (1) **negative-reachability adversary test** — hand the harness the full operational surface (every operational `KeyCustody` handle/key, every artifact + remote resource readable/assumable by the operational principal, followed transitively through every wrapping/derivation link) plus the published ciphertext, assert it **cannot** reconstruct the 32-byte seed; **and** (2) **principal-distinctness structural assertion** — assert the recovery-authority residence-id is distinct from the operational principal, and that the operational grant set excludes read/use/decrypt/**assume/delegate** over *every* secret/KEK/role in the derivation chain (not just the terminal KEK). Part 2 guards against part 1's false-PASS (a harness cannot exhaustively enumerate every assumable IAM role; the structural check catches a missed one). Both MUST pass. For Shamir, part 2 asserts fewer than 3 shares are operationally reachable. **Zeroize the derived AES/KEK key**, not only the seed bytes.

**`InMemoryPreRotationCustody` reconciliation (ADR-054 forward note).** It stays compiled-available (test-harness) but is **never runtime-selected as a server floor**: present-in-binary ≠ runtime-selectable; selecting it on the server profile **fails closed at runtime** (§3a(a)). The `traits.rs` doc-comment "default in production … until backends wired in" is a §3a violation and MUST be **deleted** in the realization (Slice 2 AC).

### 5. Credentials (E2), blob (E3), relay querier (E4) — classified + storied now (live SCP-CAPSEL fixes)

These are **not** "later slices, not yet storied" (that would be the deferral this ADR forbids). Each is classified (table above) and gets a real story (Slices 9–11), sequenced after Unit 1/2 by gate but authored now:

- **E2 credentials (Slice 9).** `BridgeCredentialStore` is RPITIT → an `enum FfiCredentialStore { Durable(..), #[cfg(any(test, feature="testing"))] InMemory }`; **delete `impl Default` (`credentials.rs:556`) — a LIVE SCP-CAPSEL-8000/8011 violation, not deferrable** — and require an explicit selection with a real durable backend. (Classified durability-only: RAM-only tokens are re-obtainable by re-auth; the selection-boundary fix is the security-relevant part.)
- **E3 blob (Slice 10).** **Delete `impl Default for BlobStorageBackend` (`storage.rs:561`) — a LIVE SCP-CAPSEL-8011 violation** — and require the arm at relay/node init. `InMemoryBlobStore` stays durability-only, explicit-only (§17.7 ships Sqlite/redb/Postgres/S3).
- **E4 relay querier (Slice 11).** Classified a **nullifier of the §3.10.8 dual-layer suppression resilience**: `NoOpRelayQuerier` yields DHT-only resolution — correct per the §3.10.6 SHOULD, but it fails *open* (silently contributes no relay result), weakening the both-layers suppression defense. Remediation = **implement the real `MultiRelayQuerier` per §3.10.12** (the relay-resolution layer; a genuine code-behind-spec gap). Until then `NoOpRelayQuerier` is the honest interim and MUST be so documented; it is not silently left unclassified.

**Why the pre-rotation (E5) work is sequenced first** (both E2 and E5 are HIGH welded): E5 nullifies the identity *recovery backstop* — unrecoverable, a spec MUST (§9.7.4.1 §3a); E2 nullifies *bridge-token durability* — a bounded availability loss (re-auth recovers). The ordering is a severity judgment governing *gate sequencing*, not a reason to omit the E2/E3/E4 stories.

### 6. Delete the runtime nullifier switch; sever `testing` from shipped graphs; G1 (depends on 1–5)

Once no shipped path constructs a nullifier: **delete `allow_in_memory_custody` entirely** (feature defs, every `#[cfg]` site, scp-runtime doc-prose, CLAUDE.md clippy string, `ci.yml`/`release.yml` strings). Sever the unconditional `scp-platform/testing` edges (`scp-ffi/Cargo.toml:51`, `napi/Cargo.toml:55`, F1 `scp-ffi-common` `server`) and `dep:scp-testing` into each bridge's `testing` feature / dev-deps. **F1 custody retype:** `server.rs`'s `IdentitySource<InMemoryKeyCustody>` phantoms (`:322`,`:435`) → `FileKeyCustody`, drop the `testing` use (the `:455` DHT constructor was already converted in Slice 1). Add **G1**.

### Dispatch mechanism (per trait object-safety)
RPITIT traits — **not object-safe** — dispatch via a no-`Default` **enum** whose in-memory arm is `#[cfg(any(test, feature="testing"))]`: `scp_dht::DhtClient`, `KeyCustody`, **`PreRotationCustody`** (`traits.rs:759/772/782`), `Storage`, `BridgeCredentialStore`. Object-safe async-trait traits (`ContextPersistence`) → required non-`Option` `Arc<dyn Trait>`. ADR-049's ban is the lock-free-read hot path only; these are write/setup paths.

### Switch-dissolution corollary
With no runtime nullifier gate there is no `allow_in_memory_*` feature to name, `# DANGER`-mark, single-source, or split 2-vs-5. The remaining honest cargo features are positive: durability-only `in-memory-storage`/`in-memory-push`, and the pre-existing `testing` test-harness feature.

## Enforcement
- **G1 — prove-absence gate (`scripts/check-shipped-feature-graph.sh`), a SOLE closed whitelist.** For each shipped artifact, mirror its exact build invocation, derive the **complete resolved feature set** from the artifact's own build config (never a hand-list), and assert **`resolved-feature-set(artifact) ⊆ an explicit per-artifact permitted-prod-features allowlist`**. Anything in the resolved set that is not on the allowlist — *named or not, present or future* — FAILS. This is the **sole mechanism**; there is no denylist of specific testing-feature names. (A denylist of `scp-platform/testing`/`scp-dht/testing`/`scp-testing` is **fail-open** — a fourth nullifier feature, or the transitive `scp-protocol/Cargo.toml:47` `testing = ["scp-did/testing", …]` did:key edge, bypasses it. The three names may appear only as a script comment/example, never as the check.) Run per artifact **including `--features server`** (F1 backstop). Durability-only `in-memory-storage`/`in-memory-push` are on the allowlist; the `testing`/nullifier features are not. **Soundness invariant (stated + machine-checked):** every bridge/consumer `testing` feature transitively pulls the checked test-harness features (so a `testing` feature can never define nullifier code reachable without them); combined with the ⊆-allowlist this makes shipped-graph feature-absence equivalent to nullifier-type absence. G1 tightens per slice (DHT allowlist tightened at Slice 1; custody/attestation/pre-rotation at Slice 6).
- **Semantic capability-matrix dimension** (`check-sdk-coverage.py`): record each binding's shipped backend per capability (DHT → Pkarr; custody → File/Sqlite/Callback; **pre-rotation → the real per-profile provider**). Slice 2 **adds the pre-rotation-provider row**; Slice 6 fixes the **4 stale `allow_in_memory_custody` device-attestation strings** in `sdk-capability-matrix.json` (`:119/:120/:131/:132`). The matrix is in those slices' `files[]` + grep ACs (`.json` included).
- **Not added:** no runtime nullifier switch; no `# DANGER` convention; no source/AST gate re-checking a type-system property.

## Consequences
- **No *custody / attestation / pre-rotation / DHT* nullifier is reachable in a shipped artifact** — not by default (the `DidDht` default type param is gone), fallback, or runtime config. **E2 credentials, E3 blob, E4 relay-querier are classified + storied (Slices 9–11)**; their in-memory arms ship until those slices land, but their live `impl Default` SCP-CAPSEL violations (E2/E3) are the storied fixes, not hidden residue; G1 tightens per slice.
- **The recovery backstop gets real §3a substrate isolation** (§4): operational-custody compromise no longer yields the pre-rotation key; the server profile fails closed without an independent-principal substrate; callback-custody migration becomes reachable.
- **In-memory storage stays usable** as an explicit honest runtime option (OpenMLS parity).
- **did:key / `scp-testing` chain severed by construction** — and G1's ⊆-allowlist (not a 3-name denylist) closes the `scp-protocol/Cargo.toml:47 → scp-did/testing` bypass.
- **At-rest caveat (ADR-054):** the encrypted-offline ciphertext is adversary-visible; its confidentiality rests on passphrase/KEK residence, not the store.
- **Binary size/build time:** unconditional `production-dht` adds mainline+reqwest (rustls, pure Rust); a bare-production release job must exist so the graph is G1-checked.
- **No migration burden** (pre-release).

## Alternatives considered
- **Nullifiers runtime-selectable behind a well-named switch — REJECTED** (Axis 2: insecure custody/verifier/resolver is never a runtime option).
- **Keep `DidDht<D = InMemoryDhtClient>` default type param + fix only the FFI wiring — REJECTED** (the default binds the nullifier for every `::new()`/`::default()` caller; the E1 bug recurs the next time someone writes `DidDht::new()`. Remove the default; make it structural — D-A).
- **Node keeps a runtime `DhtMode::Memory` in-memory DHT path — REJECTED (D-B, §Non-goals).** In-memory DHT is a §17.17.3 nullifier on *resolve* (fail-open); the node's legit no-publish need is served by a fail-closed `DhtMode::Disabled`.
- **Document pre-rotation in-memory as a "backend-pending residue" + weaken SCP-CAPSEL-8012 — REJECTED and reverted.**
- **`Arc<dyn>` for the RPITIT seams / `FfiPreRotationCustody = Arc<CallbackPreRotationCustody>` — rejected** (not object-safe; the bare adapter cannot hold the KMS/offline/test arms).
- **In-memory *storage* test-harness-only too — rejected** (durability-only; removing it loses a legitimate dev option for no security gain).
- **G1 as a denylist of named testing features — REJECTED (3-reviewer converge)** (fail-open; a 4th nullifier feature or the `scp-protocol/testing`→`scp-did/testing` edge bypasses it; only a closed ⊆-allowlist is sound).
- **E2/E3/E4 "scheduled but not storied" — REJECTED** (deferral dressed as a decision; §17.17.2 forbids an unclassified/unfixed shipped capability; E2/E3 `impl Default` are live violations).
- **Defer the pre-rotation menu / §5 ceremony / native + Python/TS hardware backends to "future work" — REJECTED** (completeness is baseline; scheduled as stories/gates).

## Non-goals / boundaries
WASM excluded (ADR-055/-057). No production device-attestation backend (ADR-025). No `dyn` rewrite of RPITIT traits. No runtime nullifier switch.

**Node DHT reconciliation (D-B) — supersedes construction.md M2's `DhtMode::Memory` framing.** In-memory DHT is a §17.17.3 nullifier on *resolve* (fail-open: `build_memory_did_method` builds a `DidDht<InMemoryDhtClient>` used for both publish *and* resolve, so a Memory-mode node resolves peers via a local map — silently nothing). It is therefore **not a shipped runtime option**: `DhtMode::Memory` becomes **test-harness-only** (gated), and the node's legitimate no-DHT-publish need is served by a new **fail-closed `DhtMode::Disabled`** — resolve returns a typed `Err` (DHT resolution unavailable), never a silent in-memory no-op. This keeps M2's *publish* fail-safe (Disabled publishes nothing) while fixing the *resolve* nullifier M2 never reasoned about. `DhtMode::Production` (real Pkarr, publish+resolve) is unchanged. construction.md M2's "`DhtMode::Memory` (no publish) is the fail-safe" text is updated to name `Disabled` as the fail-safe no-publish value (Slice 1 edits construction.md). *(A "resolve via real DHT but do not self-publish" node mode does not exist today — Memory never resolved externally — so nothing is lost; if such a mode is later wanted it is a new explicit capability, out of scope.)*
