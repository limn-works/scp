# ADR-049: Outlet Redesign — Rename, Classification, Caveats, Structured Errors, Streaming

**Status:** Proposed
**Date:** 2026-04-19
**Phase:** Phase 7 (outlet redesign)
**Supersedes (partial):** ADR-010 (Tool Registration & Execution), ADR-015 (MCP Boundary), ADR-020 (Tool Invocation Error Model), ADR-041 (Participation Consequences for Tool Misbehavior — outlet-facing portions only)
**Related:** ADR-043 (Protocol Constants Reclassification — `max_chain_depth` u8), ADR-044 (Attestation Two-Class Model), ADR-045 (Fuzzing Infrastructure)
**Deferred research:** [GitHub discussion #1698](https://github.com/limn-works/scp/discussions/1698)

## Context

Four largely-independent forces converged on the outlet surface at the same time:

1. **Terminology.** The protocol called these functions "tools" everywhere — UCAN stems `tool:invoke:*`, Rust types `ToolRegistration` / `ToolCost`, event variants `ToolInvoked`, canonical hash domain separator `SCP-TOOL-REGISTRATION-V1:`, spec prose, SDK surfaces. "Tool" is agent-centric vocabulary inherited from the MCP / function-calling-LLM world, where the tool is an instrument an agent wields. SCP's security boundary is the *context*, not the agent (§5.1). The right word for a stateless function the context exposes, which the context governs, is **outlet** — a socket on the context, not a hammer in an agent's hand. Pre-1.0 is the right time to fix terminology; post-1.0 is too late.

2. **Classification.** Every outlet invocation was treated identically for economic, rate-limiting, caching, and cross-context amplification purposes. In practice, read-only queries (look up a record, answer a derived question, serve cached state) and side-effecting actions (send a message, mint a token, post a payment) have opposite security and economic profiles. Reads are idempotent, free, cacheable, and fan out widely; actions are non-idempotent, billable, non-cacheable, and must be chain-amplification-bounded. Collapsing them into one kind forced every policy knob to be a compromise between the two.

3. **Caveats on UCAN delegations.** The UCAN `nb` field was used only for protocol-defined fields; applications had no structured way to delegate a capability *with* per-call constraints (a spending cap, a time window, an adapter allowlist, an input-schema narrowing). The absence was filled by ad-hoc conventions in each SDK that did not round-trip through delegation attenuation. An application that wanted to mint a daily $50 cap on a payment-outlet capability had no protocol-level way to do it.

4. **Error envelope + streaming.** Invocation errors were returned as `Result<Value, String>` with an ad-hoc mapping from half a dozen internal error variants to the string. Seven distinct internal variants collapsed to a single `PermissionDenied` at the FFI boundary (a real bug, tracked in the original audit). Invocations were always one-shot — a large LLM response waited until it was fully complete before crossing any layer, breaking on any timeout shorter than the full generation.

Seven parallel reviewers (alignment, architecture, api-design, cryptographer, security, simplifier, black-hat) reviewed the initial redesign PRD and spec additions. They identified approximately 20 BLOCKERs and 40 MAJORs. User chose to **strip scope** rather than push back on the review findings. Deferrals went into [discussion #1698](https://github.com/limn-works/scp/discussions/1698); the remaining work folds the BLOCKERs into the PRD + spec.

## Decision

### 1. Rename `tool` → `outlet` everywhere (hard break, no aliases)

The rename is total:

- Rust types: `ToolRegistration` → `OutletRegistration`, `ToolCost` → `OutletCost`, `ToolInvoked` → `OutletInvoked`, etc.
- UCAN stems: `tool:invoke:*` → split into `outlet_query:*` and `outlet_call:*` (see §2 below); wire form uses underscore, SDK-facing display form uses colon per §5.4.2.1 parser.
- Capability URIs in ceilings: `tool:invoke:*` → `outlet:query:*` / `outlet:call:*`.
- Canonical hash separator: `SCP-TOOL-REGISTRATION-V1:` → `SCP-OUTLET-REGISTRATION-V2:` (new suffix reflects new preimage, not just a namespace change — see §5 below).
- Event variants: `ToolInvoked` etc. → `OutletInvoked` etc.; event log discriminants renumbered into a new band so any stale pre-rename event logs fail verification rather than silently replaying under the wrong vocabulary.
- Context templates: `scp:template/tool-interface` → `scp:template/outlet-interface` (template ID is part of context metadata; a renamed template ID means pre-rename templates hash differently and are not silently honored — deliberate hard break, same rationale as the rest of the rename).
- Error code prefix: **retained** as `SCP-TOOL-` within the 6100-6199 sub-block. Rationale: `scripts/check-error-codes.sh` indexes prefixes in a closed set; adding a new top-level prefix requires coordinated changes across every language SDK's error surface and every CI gate. Sub-block allocation within the existing prefix is the forward-compatible path. The slug (`slug` field on `OutletError`) carries the `outlet.` semantic prefix; the code carries the legacy `SCP-TOOL-` prefix.
- MCP boundary: `scp-mcp` translates lexically at the boundary (§8.5.1). Inside SCP everything is an outlet; externally, MCP clients see `tools/list` and `tools/call` preserved on the wire.

No deprecation aliases. No transitional period. Pre-rename callers are broken; pre-rename event logs fail verification; pre-rename UCAN tokens are rejected.

### 2. Introduce `OutletKind { Query, Action }` with structural classification

Every outlet registers with a kind. The kind is structural, not advisory:

- **Query** — read-only, idempotent, semantically cacheable. `cost == None || cost.amount == 0` enforced at registration (`QueryCostViolation` on violation); `cost.cost_formula` must be absent. Invoked through a `ReadOnlyInvocation` handle that denies writes to context state (messages, roles, registry, event log, governance, economy); any write attempt returns `QueryViolation` and emits an operator-attributable integrity-failure signal.
- **Action** — may mutate. No structural floor. Invoked through a `MutableInvocation` handle. The existing cost, rate, and amplification rules apply.
- Default is `Action` (fail-safe — an undeclared kind cannot accidentally be treated as read-only).

UCAN stems split: `outlet_query:{id}` authorizes Query invocations only; `outlet_call:{id}` authorizes Action invocations only; attenuation cannot cross classes. The `outlet_invoke:*` stem used in intermediate rename stories is deleted (hard break).

Chain amplification (§6.2.0.3): a Query-originated call cannot transitively invoke an Action outlet. `origin_kind` is bound to the UCAN `nb` field of the signed delegation chain — it is not a runtime claim; forging it requires forging the signed delegation. The check is evaluated at every hop target.

Chain depth (§6.2.0.4): partitioned by kind — Query uses the full `max_chain_depth` budget, Action uses `max(1, max_chain_depth / 2)`.

Rate tiers (§6.2.0.2): Query per-interface 600/min, per-caller 100/min (an order of magnitude higher than Action, reflecting the idempotent read contract); Action 60/min and 10/min (original defaults).

Session amplification (§6.2.1): sessions inherit the `origin_kind` of the first call that opened them; no session upgrade path.

### 3. Scoped UCAN invocation caveats — structured typed fields only

Caveats live in the UCAN `nb` field as an `InvocationCaveats` struct (§7.3.8) with 12 typed, optional fields: `amount_max_per_call`, `amount_max_cumulative`, `valid_from`, `valid_until`, `hours_of_day`, `days_of_week`, `max_calls`, `rate_window`, `input_schema`, `allowed_adapters`, `allowed_target_dids`, `origin_kind`. Mint-time limits enforce ≤ 8 populated fields (excluding `origin_kind`, which is a structural attenuation invariant and does not count against the user-facing ≤ 8 cap), ≤ 4 KiB serialized `input_schema`, ≤ 8 nesting depth, ≤ 16 list entries.

`narrow()` attenuation is per-field:

- Numeric bounds tighten (`<=` or `>=` depending on direction).
- Bitmasks subset (`child & parent == child`).
- Lists subset.
- `input_schema` uses conservative JSON Schema narrowing with a whitelist of keywords (`enum`, `const`, `minimum`, `maximum`, `minLength`, `maxLength`, `pattern`, `required`, `additionalProperties: false`) and per-keyword rules; the `pattern` keyword requires **lexical equality** because regex containment is undecidable (PSPACE-complete in general, undecidable for extended dialects).
- `hours_of_day` enforces a 24-bit mask-width assertion at mint and narrow (bits 24..31 must be zero) to prevent ambient-data smuggling and validator-implementation differentials.

Runtime enforcement wires caveats into three points of the 11-step UCAN validation pipeline (§7.2.1): step 7b (attenuation) calls `narrow()` on every delegation edge; step 11b (time-box) checks `valid_from` / `valid_until` / `hours_of_day` / `days_of_week`; a post-input check validates `input_schema`, `amount_max_per_call` against the estimated invocation cost, `allowed_adapters` against the negotiated adapter, `allowed_target_dids` for cross-context, and consults the `CaveatCounterStore` for `max_calls` / `amount_max_cumulative` / `rate_window`. Failures surface as Authorization-class errors with class-specific slugs.

Caveats compose with `SpendingCapability` (§19.5), `MemberBudgetTracker` (§19.3), `InboundPolicy`, and `OutboundPolicy` (§6.2) under logical AND — additive deny-surfaces, never widening.

Revocation is whole-token (§7.2.1 step 10). No per-caveat revocation; if an operator needs to narrow, they revoke and re-issue.

### 4. Structured `OutletError` envelope replacing lossy boolean/string path

`OutletError` carries (wire tags shown):

- `code: String` (tag 1) — `SCP-TOOL-{6100..6199}`; sub-block allocation within 8 classes.
- `slug: String` (tag 2) — kebab-case, class-scoped finer distinction. Multiple slugs may share one code (e.g., `SCP-TOOL-6110` with slugs `authorization.expired`, `authorization.revoked`, `authorization.missing`).
- `class: OutletErrorClass` (tag 3) — eight root classes: Protocol, Authorization, Input, Execution, Output, Economic, Transport, Governance.
- `message: String` (tag 4) — human-readable prose, max 1 KiB, **PII-constrained** (MUST NOT include emails, DIDs of non-self members, raw input values, SQL, stack traces, file paths; SDKs SHOULD apply a redaction lint).
- `retry: RetryPolicy` (tag 5) — `Never | Immediate | After(Duration) | WithBackoff { min, max }`.
- `detail: Option<Value>` (tag 6) — **typed per-class schema**, not free-form. Each class has a specified detail shape; a non-matching detail is a wire-layer rejection at the receiving SDK. Prevents covert-channel use.
- `source_chain: Vec<ContextHop>` (tag 8) — ordered cross-context hop trail; each `context_id` is pseudonymized via `HMAC(hop_salt, context_id)` where `hop_salt` is a per-context-pair salt established at interface acceptance. Hop index 0 (caller's own context) is NOT pseudonymized.

Tags 7, 9, 10 are **reserved for forward-compatible evolution**. They were drafted (`related_code`, `i18n_key`, `trace_id`) and dropped before merge: cross-reference is served by `source_chain.wrapped_code`; localization is SDK-layer; telemetry `trace_id` is transport-layer with its own conventions. Future tags MUST use 11+ and round-trip through `_unknown_fields`.

**Query oracle collapse.** Authorization errors that would reveal whether a specific `outlet_id` exists are collapsed to `SCP-TOOL-6110` with slug `authorization.denied` when the caller holds neither `outlet_query:{id}` nor `outlet_call:{id}`. Without the collapse, a caller who holds no capability could enumerate the outlet registry by probing error codes — a practical oracle against private outlets.

**Cross-context wrapping preserves the original code.** Source-chain hops append with `wrapped_code` of the previous hop; the outermost caller sees the innermost reason and the trail of boundaries traversed. Opposite of HTTP gateway remapping.

**SDK sealed hierarchies.** Each SDK renders `OutletErrorClass` as a sealed type — Python subclass tree, TypeScript tagged-union with runtime `instanceof` preserved across napi-rs FFI, Swift `enum` with associated values, Kotlin sealed class with data-class children. Conformance fixtures round-trip through all four bridges.

### 5. Streaming-native invocation (every call is a stream)

Every invocation is a stream per §5.4.5. `OutletResponse` is deleted. The wire types are `OutletStreamOpen`, `OutletStreamChunk` (with `sig: Ed25519Signature`), `OutletStreamCredit`, and a tagged `ChunkPayload` union (Data / Progress / End / Error). The variant discriminator field is named `@type` (leading `@`) so that under RFC 8785 JCS sort order it precedes every body-field key in every variant — a canonical-hashed chunk is classified before any body field is read. (The draft used `"type"`, but under JCS `type` sorts AFTER all lowercase-letter body keys; `@type` is the minimal change that actually delivers the "classify first" property.)

- **Per-chunk operator signature** over `SHA-256("SCP-OUTLET-CHUNK-SIG-V1:" || len_be32(context_id) || context_id || len_be32(outlet_id) || outlet_id || request_id || sequence_be || caveats_binding || SHA-256(canonical_jcs(payload)))` closes the equivocation gap where an operator could stream different sequences to different members and commit a manifest of only one. Binding `context_id`, `outlet_id`, and `caveats_binding` into the preimage closes the cross-outlet, cross-context, and cross-caveat-set replay surface. Matches §5.4.5 byte-for-byte.
- **`caveats_binding`** over `SHA-256("SCP-OUTLET-CAVEAT-BIND-V1:" || len_be32(ucan_cid) || ucan_cid || request_id || len_be32(invoker_did) || invoker_did || estimated_chunk_count_be || len_be32(canonical_jcs(effective_caveats)) || canonical_jcs(effective_caveats))` commits the open to the exact caveat set validated at check time AND pins the binding to (a) the specific token, (b) this stream instance, (c) the invoker identity, (d) the invoker-declared billable-chunk ceiling, and (e) the narrowed caveats (including `origin_kind`). The final variable-length `canonical_jcs(effective_caveats)` field is explicitly length-prefixed per §9.5.1's uniform construction rule — closing a field-split preimage-collision class the round-3 draft left open. A later `OutletStreamOpen` with the same `request_id` but a different `caveats_binding` is rejected as `AttenuationViolation`. Matches §5.4.5 byte-for-byte.
- **Credit grant signature** over `SHA-256("SCP-OUTLET-CREDIT-V1:" || len_be32(context_id) || context_id || len_be32(outlet_id) || outlet_id || request_id || grant_be || monotonic_seq_be || stream_epoch_be || caveats_binding)` — stream-identity binding on credit grants includes `stream_epoch` (the hosting context's MLS epoch counter at `OutletStreamOpen` acceptance, pinned in the stream record) so a grant signed for epoch E cannot be replayed under epoch E+1 even under contrived `request_id` collisions across binding-eviction races. Stream-identity binding closes the cross-stream grant-replay surface; the `stream_epoch` extension closes the cross-epoch replay surface.
- **`offer_id`** over `SHA-256("SCP-OUTLET-OFFER-ID-V1:" || len_be32(context_a_id) || context_a_id || len_be32(outlet_id) || outlet_id || len_be32(context_b_id) || context_b_id || timestamp_be)` — length-prefixed and domain-separated (§6.2.0.1).
- **V1 preimage naming.** None of the four new preimages shipped under an earlier V-number; the ADR tracks them as V1 from first commit. Drafts that briefly wrote `SCP-OUTLET-CAVEAT-BIND-V2` / `SCP-OUTLET-CHUNK-SIG-V2` are erased — "V1" is the historically accurate first-ship label.
- **`chain_depth` is `u8`** to match §24.4 + ADR-043 `[0, 255]`.
- **Credit-based backpressure** with default window 32 and 30-second stall timeout; End/Error are terminal and never consume credit.
- **Chunk manifest** uses RFC 6962 tag bytes (`0x00` for leaves, `0x01` for interior) under `SCP-OUTLET-CHUNK-V1:` separator; leaf covers the full chunk including `sig`. The root `stream_manifest_hash` is the commitment. Per-chunk inclusion-proof **API** is deferred (see §6 below); the commitment itself is protocol-level.
- **Billing semantics** escrow-at-open + per-chunk accrual + receipt-at-close + refund-on-terminate + cancel-ack-sequence-bounded billing + credit-stall escrow release. Event log records `chunks_billed: u32` separately from `stream_chunk_count`.
- **One `OutletInvokedEvent` per stream**, emitted at terminal chunk, carrying `stream_chunk_count`, `chunks_billed`, `stream_manifest_hash`, `stream_terminal_status`.
- **Cross-context streaming** (§6.2.0.5): shared-member bridge re-encrypts chunks per-recipient; `chain_depth` is set at open and inherited; credit flows end-to-end.
- **Non-streaming invocation** is the degenerate two-chunk case (`Data(output)` + `End(output)`). SDKs MAY expose a `.invoke()` helper that awaits the collected `End.aggregate`, but the wire contract is always the streaming form.

SDK idioms: Python `AsyncIterator`, TypeScript `AsyncIterable`, Swift `AsyncThrowingStream`, Kotlin `Flow`. Progress chunks are surfaced (not filtered out). Each SDK also exposes `grantCredit` and `cancel`.

### 6. Deferred scope (tracked in [discussion #1698](https://github.com/limn-works/scp/discussions/1698))

The following pieces were specced but pulled before merge. They are intentionally deferred, not forgotten.

- **Query result cache (§5.4.3).** Relay-hosted operator-signed shared cache. Unresolved design questions: relay-side authz boundary for cache reads (relays are not membership-aware, the cache must be membership-gated); interaction with per-member pseudonym routing (§9.10.4), which prevents grouping hits on a single routing ID without leaking subscribership; billing semantics for a paid Query operator serving unbounded cached audience. The spec deferral stub in §5.4.3 prohibits silent cache-like optimization by implementations.
- **Per-chunk inclusion-proof API.** `outlets.inclusion_proof(invocation_id, chunk_index)` returning a Merkle path. The manifest root commitment is kept at the protocol level; the API is a convenience over that primitive and can be added without a wire break.
- **Error envelope fields `i18n_key`, `trace_id`, `related_code`.** Tags 9, 10, 7 reserved on the wire; `_unknown_fields` forward-compat ensures future re-introduction does not require a wire break.

Each deferred item carries a rationale in the discussion thread so the context isn't lost. Re-adding any of them is a future ADR, not a silent patch.

### 7. Updates to stale "done" PRDs

Several PRDs in `main.json` were marked `done` against tool-era acceptance criteria that reference `ToolRegistration`, `ToolRequest`, `ToolResponse`, `ToolInterface`, or `tool_invoke:*`. These stories (SCP-010, SCP-013, SCP-018, SCP-040, SCP-041) remain historically accurate — they describe what was built at the time — but their acceptance criteria no longer pass a codebase where those types have been renamed. The outlet PRD adds a migration-superseded story that explicitly annotates each affected story's `details` with a `superseded_by` field pointing to the gate-rename stories. The text of the original acceptance criteria stays intact (history), but the machine-verifiable status is now "superseded by SCP-OUT-NNN, kept for provenance."

## Rejected alternatives

- **Keep the word "tool".** Rejected per the terminology rationale above. Pre-1.0 is the right window; post-1.0 would require a second hard break we would regret.
- **Alternative names: "service", "operation", "endpoint", "handler".** `service` is too heavy (implies deployment, scale, long-running process); SCP outlets are stateless. `operation` is RPC vocabulary that loses the context-as-socket metaphor. `endpoint` is HTTP-centric. `handler` is a language-level implementation detail, not a protocol concept. `outlet` consistently read as the right noun in prose, API, docs, and error codes during the terminology review. See discussion #1698 for the full trade-off table.
- **`outlet+invoke_only` without classification.** Single invocation verb with runtime hints for rate/cache/amplification. Rejected because every rate, cache, and amplification decision would become a per-outlet policy knob the operator declares and the runtime hopes-is-honest — classification pushes the distinction into the type system where the runtime can enforce it structurally. Classification also gives the UCAN stem split, which is the hook that makes chain-amplification enforceable on the authorization boundary.
- **A caveat DSL.** A small expression language in `nb` for general-purpose predicates over input / context / time. Rejected. A DSL is a parser-differential attack surface, a complexity multiplier for every SDK, and a future-compatibility hazard. Fixed-field caveats with a ≤ 8-field cap keep the verifier small enough to fuzz to saturation and keep delegation semantics auditable by eye.
- **Shared relay-hosted Query result cache (first draft).** Deferred per §6 above, rejected for the initial merge because of unresolved authz / pseudonym / billing interactions. Kept as a primitive the kind semantic is compatible with.
- **Per-chunk inclusion-proof API on the SDK surface.** Deferred per §6. The manifest root is the protocol-level commitment; the proof API is a later optional convenience.
- **Error envelope with 35+ codes.** The initial draft enumerated every distinguishable runtime condition as a distinct code, running to ≥ 35 entries across the 6100-6199 sub-block. Compressed to ~15 codes (1-2 per class, ~15 total), with fine-grained distinctions carried in `slug`. Full enumeration was unmemorable; the compact taxonomy keeps the wire form legible and leaves room inside the sub-block (6180-6199 reserved).
- **`i18n_key`, `trace_id`, `related_code` on the wire.** Deferred per §6. Locale catalogs belong in SDKs; trace IDs belong in the transport layer with their own propagation conventions; cross-references are carried implicitly via `source_chain.wrapped_code`.

## Consequences

- **Pre-migration tokens, event logs, and signatures are invalid.** Any agent, relay, or stored artifact from before the rename fails verification after the migration commit. This is intentional — pre-1.0, there is no compatibility obligation.
- **The protocol wire surface breaks.** MessagePack field tags, canonical hash separators, UCAN stems, event-log discriminants, and error-envelope shape all change. Deployments must migrate atomically.
- **The SDK public surface breaks.** Every language SDK renames `Tool*` to `Outlet*`, splits invocation into `.query()` / `.call()` (or `.invoke()` with kind-inferred stem), exposes caveat helpers, and renders `OutletError` as a sealed hierarchy. Application code that used the pre-rename SDK compiles only after a rename pass.
- **The MCP boundary is preserved.** External MCP clients continue to see `tools/list` and `tools/call`; the boundary is lexical and handled by `scp-mcp`.
- **The enforcement surface expands.** New scripts (`check-handle-affinity.sh`, `check-no-bridge-globals.sh`, `check-no-fallback-registry.sh`, `check-no-default-in-tests.sh`) interact with the outlet rename because they all indexed tool-era identifiers. `bridge_ratchet_baseline.json`, `ratchet/once-lock-count.json`, and the capability matrix all update.
- **Every OutletExecutor is wrapped in `catch_unwind`.** A panic inside an executor maps to `SCP-TOOL-6130` (handler-panic) with an operator-attributable integrity-failure signal. The SDK's own bugs are not conflated with operator-originated failures.
- **Stream billing is escrow-based.** An operator who begins serving chunks against a caller whose escrow is insufficient never gets started; an operator whose stream is terminated mid-way bills only for cancel-ack-bounded billable chunks. The economic layer stays consistent across partial streams.
- **Cross-instance handle reuse across separate SCP instances is independent of this ADR.** ADR-048 handled that concern; outlets inherit the handle-affinity discipline established there.
- **Ratchet invariant (monotonicity).** Every coverage ratchet touched by this ADR — `bridge_ratchet_baseline.json`, `ratchet/once-lock-count.json`, `ffi_conformance.rs` assertion counts, `pipeline_wiring.rs` assertion counts, SDK capability matrix cell counts — is NON-INCREASING in the weakening direction. Additive expansion (new operations, new assertions) is always permitted; removal, weakening, or exemption of an existing counter requires explicit human approval per the CLAUDE.md worktree invariant. The outlet redesign is a rename + expansion: every existing mechanical enforcement count stays at or above its pre-rename value, and new entries (streaming, caveats, error envelope, classification) are layered on top. Cleaning up the one-time bookkeeping cost of the rename itself (e.g., deleting a `ToolRegistration` type and replacing it with `OutletRegistration`) counts as an identifier change, not a ratchet regression; no check count drops as a result.

### Gate-level priority reconsideration

Gates 2-5 (classification, caveats, errors, streaming) carried `P1` in the initial draft. The tightened scope (caveats and errors both substantially smaller; streaming has the deferrals carved out) makes each gate a narrower, more focused deliverable. Per the "no DOA decisions" tenet, each gate should ship as part of a coherent first cut rather than be partially deferred; the P0/P1 split has been reconsidered, with Gates 2-4 moving to P0 (the behavioral invariants they encode — classification, caveat attenuation, typed errors — are load-bearing for the rename to mean anything at runtime) and Gate 5 remaining P1 (streaming is load-bearing for SDK ergonomics, not for protocol correctness; the degenerate one-shot case is always available).

### Round 4 adjustments (April 2026)

The round-3 review surfaced additional structural flaws that round 4 closes:

- **Trail-padding actually pads.** The round-3 construction encoded the real chain length `k` into every pad entry's `hop_index` (as `k + pad_offset`) and reused a per-stream pad seed, making pad pseudonyms byte-identical across envelopes and therefore diffable against real entries. Round 4 fixes both: pad entries now use `hop_index = slot_index` (identical to the real-hop slot encoding) and derive their `context_id` from a fresh-per-envelope CSPRNG nonce via `HMAC(pad_nonce, "SCP-OUTLET-HOP-PAD-V1:" || slot_index_be)`. The error envelope gains an optional `pad_nonce: [u8; 16]` field (tag 11) so receivers can re-derive pad entries locally for verification. A protocol constant `MAX_TRAIL_PAD_DEPTH = 16` caps padded `source_chain` length regardless of `ContextParams::max_chain_depth`, keeping envelope size bounded.
- **Mixed-stem roots rejected at mint.** The round-3 "inference fails on first ambiguous delegation" escape hatch was unsound — a mixed-stem root with `origin_kind = None` could be exercised at one hop under `Query` semantics and at a downstream hop under `Action` semantics by selecting the capability at each hop. Round 4 rejects mixed-stem roots unconditionally with `SCP-TOOL-6114` slug `origin-kind-mixed-stem-root`. `caveats.origin_kind == None` is permitted at mint only when all root stems agree on a single `OutletKind`. Every non-root delegation MUST materialize `origin_kind` explicitly; a non-root with `origin_kind = None` fails `narrow()` with `AttenuationViolation::OriginKindUnspecified`. This makes inheritance of `origin_kind` explicit, not ambient.
- **`caveats_binding` preimage carries a length prefix on the JCS-bytes field.** The round-3 preimage terminated in a bare `canonical_jcs(effective_caveats)` with no length prefix, violating §9.5.1's uniform construction rule and leaving a field-split preimage-collision surface. Round 4 inserts the explicit `len_be32(canonical_jcs(effective_caveats))` prefix.
- **`hop_salt` historic verifiability via committed IKMs.** The round-3 "derive-on-demand" rule required each context to retain MLS epoch secrets indefinitely to verify historic `source_chain` entries, conflicting with forward secrecy. Round 4 commits both `ikm_a` and `ikm_b` verbatim into the `InterfaceEstablished` event metadata at accept time. Verifiers rederive `hop_salt` from the committed IKMs at any later time without needing to retain MLS epoch keys. The trade-off is disclosed in §6.2.0.1: the committed IKMs are 32-byte pseudo-random values that enter the public event log, but they do not extend membership-level pseudonym-reversal to non-members because the HMAC inputs (`raw_context_id` values) are still unknown to non-members.
- **Message HMAC on wire defeats cross-context signaling.** The round-3 catalog rule carried the catalog key in plaintext on the wire, allowing a cooperating operator running two contexts to encode a cross-context signal in the per-invocation choice of key. Round 4 wraps the catalog key in an HMAC under a per-context MLS exporter key (`"scp-outlet-message-v1"`), so the same catalog key produces different wire bytes in different contexts. The round-3 4-byte input-echo window is removed — the catalog + HMAC rule alone makes input-byte smuggling structurally impossible, and the 4-byte window false-positived on legitimate short catalog entries. A 24-hour minimum dwell-time between catalog edits removes high-frequency catalog churn as a covert channel.
- **Cross-context concurrent-stream caps tied to outermost caller.** The round-3 `max_concurrent_inbound_streams_per_invoker` counted the immediate-previous hop, letting a caller rewrite the delegation chain through intermediate agents to bypass the limit. Round 4 adds `max_concurrent_inbound_streams_per_origin_invoker` (default 16, range [1, 1024]) which is tracked against the outermost `iss` DID in the UCAN delegation chain and grouped at operator scope across every interface hosted by the same operator.
- **`OutletCancel` receive handler semantics specified.** Round 3 left the executor-side cancel flow under-specified (who records `cancel_ack_seq`, when, and how state is flushed). Round 4 specifies: the framework records `cancel_ack_seq = current emission cursor` at cancel arrival, arms `stream_cancel_ack_secs`, emits the terminal chunk within the window (or forces closure with `SCP-TOOL-6135 execution.cancel-ack-timeout`), and flushes stream state on terminal emission. The framework-side UCAN revocation re-check is likewise lifted to a framework responsibility rather than an executor-checkpoint dependency.
- **Mask-width newtypes consolidate hours/days helpers.** `HoursOfDayMask` (newtype over `u32` via `from_bits`) and `DaysOfWeekMask` (newtype over `u8`) structurally forbid high-bit values at the type level. A shared `assert_mask_widths(caveats)` helper runs at both mint and every narrow step, so the two call sites share a single implementation.
- **Interface-spam anonymity-set deterrent.** Interface establishment cost now scales quadratically in the count of active interfaces the context already holds with the same peer over a rolling 24-hour window. The quadratic escalator makes anonymity-set reduction on `hop_salt` economically irrational at low interface counts without penalizing legitimate bilateral renegotiation.

No round-4 change touches the ratchet monotonicity invariant — all additions are expansions (new assertions, new constants, new fields) or replacements of unsound rules with sound ones (the round-3 inference escape hatch, the round-3 pad encoding).

### Round 5 adjustments (April 2026)

Round 5 closes additional flaws that round-4 text introduced and discloses honest scopes for partial-visibility constructions:

- **`message_catalog` explicitly in the V2 preimage.** The round-4 catalog-plus-HMAC rule claimed catalog contents were "covered via `schema_hash`" — false, because the `schema` preimage hashes only `input`, `output`, and `aggregate_schema`. Round 5 adds a dedicated `catalog_hash = SHA-256(MessagePack(message_catalog))` term to the `SCP-OUTLET-REGISTRATION-V2` preimage and adds `message_catalog: Vec<MessageTemplate>` to the `OutletRegistration` struct definition. Every string field the operator controls at registration is now covered by the registration signature.

- **`description_hash` in the V2 preimage.** The `description` field (up to 4 KiB of operator-authored prose) sat outside the V2 preimage and was equally a covert-channel surface — an operator could edit it silently without invalidating the registration signature. Round 5 commits `description_hash = SHA-256(description_utf8_bytes)` into the preimage. Together with `catalog_hash`, this closes the operator-authored-prose covert-channel class entirely.

- **Per-outlet message HMAC key, pinned at registration acceptance.** The round-4 message HMAC used `MLS_EXPORTER("scp-outlet-message-v1", b"", 32)` evaluated AT ERROR-EMISSION TIME on the hosting context's current MLS epoch. An operator holding two concurrent memberships during the standard MLS grace window (§9.7) produced two distinct wire bytes for the same `catalog_key` — one under epoch E's exporter, one under epoch E+1's exporter — encoding one bit of covert signal per emission that straddled the grace boundary (BH5-B2). Round 5 derives the HMAC key ONCE at outlet registration acceptance (`"scp-outlet-message-v1:" || len_be32(outlet_id) || outlet_id` as the exporter label, evaluated on the then-current epoch), pins it for the outlet registration's lifetime, and rotates it only at outlet re-registration. Grace windows never touch the key; the covert channel is structurally impossible.

- **Catalog-rotation dwell-time uses event-log append time.** The round-4 dwell-time rule compared `registered_at` values — an operator-declared u64 the operator can set arbitrarily. An attacker could back-date a registration to bypass the 24h floor. Round 5 enforces the comparison against the event log's append time for each registration (a protocol-enforced, verifiably-ordered clock per §7.3.1). The operator cannot forge event-log append times.

- **Pad_nonce unconditional emission.** The round-4 envelope emitted `pad_nonce: Option<[u8; 16]>` — present when the receiver lacked full visibility, absent when they had full visibility. Absence was itself a visibility oracle: an on-wire observer could distinguish the two cases by presence-vs-absence of the tag-11 field. Round 5 makes `pad_nonce: [u8; 16]` unconditional — emitted on every envelope, ignored on decode when the receiver's `k == max_padded_trail_depth` check indicates no padding. The 16-byte fixed cost per envelope removes the oracle.

- **Partial-visibility honest disclosure (BH5-B1).** The round-4 pad construction used `HMAC(hop_salt, raw_context_id)` for real hops and `HMAC(pad_nonce, "SCP-OUTLET-HOP-PAD-V1:" || slot_index)` for pads. A receiver who was a member of any one hop could trial-HMAC their own `hop_salt` against each slot and identify that slot as "real." A cryptographic fix — re-HMACing every real-hop slot under `pad_nonce` (adding a `SCP-OUTLET-SLOT-V1:` domain separator) — was considered and rejected as disproportionate to a niche attack: the attack requires the observer to already be a hop member, who already structurally sees their own hop's existence. Round 5 updates the spec to state the partial-visibility scope honestly: the pad hides `k` (chain length) from observers who hold no `hop_salt`, does not hide it from observers who are members of at least one hop (they can identify their own slot but cannot learn `k`), and fully hides `k` from non-members of every hop. This is the design's target threat model; the spec now reads honestly rather than claiming universal opacity.

- **Origin-invoker counter increment ordering (BH5-M1).** The round-4 concurrent-stream caps did not specify WHEN the operator's counter increments relative to UCAN validation. A read of "increment on receipt, decrement on reject" would let a low-cost forged-`iss` open consume a per-origin-invoker slot against the real DID, creating a slot-burn DoS. Round 5 specifies a 5-step ordering: parse → validate UCAN fully → run three cap comparisons in lexical order → atomic increment of all three counters only on full success → atomic decrement on terminal. Rejected opens at any tier do NOT touch any counter. Slot occupancy is paid only for validated opens.

- **JCS Option serialization convention (crypto m1).** The round-4 `canonical_jcs(effective_caveats)` term left ambiguous whether absent `Option` fields serialized as omitted keys or as explicit `"field_name": null`. Two SDKs with different serde defaults would produce different byte strings and different `caveats_binding` values for the same caveat set. Round 5 pins the rule: absent `Option` fields are OMITTED (serde `skip_serializing_if = "Option::is_none"` applied before JCS canonicalization). All four SDKs must use the omit-none convention. A conformance fixture covers cross-SDK byte-for-byte match.

- **Committed IKM signing (BH5-m4).** The round-4 IKM commitments had no integrity guarantee — a Byzantine admin who controlled the MLS exporter output (by running a hostile MLS implementation) could publish a low-entropy or attacker-chosen IKM, shifting the `hop_salt` onto an attacker-controllable distribution. Round 5 requires each side's admin to sign its own IKM at accept-time under the `SCP-OUTLET-IKM-COMMITMENT-V1:` domain separator. The preimage binds context-id pair and epoch; a failed signature rejects the `InterfaceEstablished` at event-log append time with slug `authorization.ikm-signature-invalid`. A malicious admin publishing a low-entropy IKM is now cryptographically attributable and the interface establishment fails.

- **Admin-removal salt rotation (BH5-s1 elevated).** A removed admin retained knowledge of the prior `(ikm_a, ikm_b)` and could continue computing `HMAC(hop_salt, raw_context_id)` to reverse pseudonyms for hops they no longer had a right to observe. Round 5 adds an unconditional `InterfaceSaltRotated` event emitted on every active interface when an admin is removed. Both sides publish fresh IKMs; both contexts re-derive `hop_salt` from the new pair. The removed admin's HMAC computations no longer match wire pseudonyms.

- **Interface-spam cluster detection (BH5-M3).** The round-4 quadratic fee checked `hop_salt` spam against a single peer context. An attacker could spin up 100 disjoint contexts with rotated admin DIDs — no predicate in round-4 text defeated this evasion. Round 5 extends the rolling-window cluster-match count `k` to three predicates: (1) same `context_id`, (2) same `creator_did` (fixed at context creation, cannot be rotated), (3) non-empty `admin_set` intersection. Any predicate counts the prior interface toward `k`. Residual-risk disclosure: an attacker who burns fresh admin DIDs AND fresh creator DIDs bypasses the detection; the economic floor (`interface_base_cost_minimum × 1²`) must be set such that this attacker expense is economically irrational.

- **`session_id` UUIDv7 format.** The round-4 `session_id: Option<String>` left the format unspecified, creating cross-SDK divergence risk and a session-takeover surface where two callers could choose the same `session_id`. Round 5 pins UUIDv7 per RFC 9562 §5.7 with 48-bit ms timestamp + 80-bit DID-fingerprint-XOR-monotonic-counter. SDKs validate format on construction and acceptance; collisions are rejected with `protocol.session-id-conflict` at creation time. UUIDv7's ~2⁻⁴⁰ per-ms-per-caller collision rate makes reject an edge case, but specifying it closes the silent-takeover surface.

- **Paired-token kind disclosure (BH5-M2).** The round-4 `§7.3.8` claimed "no scenario where `origin_kind` is ambiguous" — overstated. A single UCAN's delegation chain is unambiguous (closed by the rule-1 mixed-stem-root rejection plus rule-4 explicit-on-non-root); an agent holding two SEPARATE rooted tokens (one Query-rooted, one Action-rooted) exercises each token as itself and presents the appropriate chain to the hop target. There is no cross-token ambiguity — each token is self-describing. Round 5 states this honestly as an expected property of the design, not a gap.

- **Error-code slug expansion.** Round-5 additions register 15 new slugs across existing class ranges (no new codes — slugs differentiate conditions under shared codes per the compact-taxonomy design): `protocol.catalog-rotation-too-frequent`, `protocol.stream-already-open`, `protocol.session-id-conflict`, `protocol.interface-spam-cost`, `authorization.credit-stream-mismatch`, `authorization.revoked-mid-stream`, `authorization.ikm-signature-invalid`, `attenuation.origin-kind-mixed-stem-root`, `attenuation.origin-kind-stem-mismatch`, `attenuation.origin-kind-unspecified`, `attenuation.mask-width-violation`, `transport.concurrent-streams-per-invoker`, `transport.concurrent-streams-per-origin-invoker`, `transport.concurrent-streams-per-outlet`, `execution.cancel-ack-timeout` (the last one shipped in round 4 but had not been registered in the §5.4.4 slug table).

No round-5 change touches the ratchet monotonicity invariant — all additions are expansions (new assertions, new constants, new fields, new slugs under existing codes) or replacements of unsound rules with sound ones (the round-4 emission-time HMAC key, the round-4 operator-declared dwell clock, the round-4 presence-based visibility oracle, the round-4 single-predicate cluster check). Pre-1.0 hard breaks remain hard breaks: pre-rename event logs fail verification, pre-migration UCAN tokens are rejected, pre-round-4 / pre-round-5 preimages are rejected.

### Round 6 adjustments (April 2026)

Round 6 closes BLOCKER and MAJOR items raised by the api-design, security, and black-hat reviewers after round-5 merge. Cryptographer, simplifier, alignment, and architecture reached double-zero on their round-5 finding sets.

- **`session_id` pure CSPRNG (BLOCKER-1).** Round 5's UUIDv7 construction specified the 80-bit tail as `(first 10 bytes of SHA-256(did_string)) XOR (process-local monotonic 80-bit counter)`. This was wrong on two counts: (a) it violates RFC 9562 §5.7, which requires `rand_b` to be CSPRNG-sampled (not deterministically derived), and (b) it creates a trivial linkability oracle — any observer who knows a DID can compute the fingerprint and match it against the first sessions an SDK process ever emits (where the counter is zero), AND creates a process-restart collision surface where two independent processes with the same DID can produce identical `session_id` values within the same millisecond. Round 6 replaces the tail with a pure CSPRNG `rand_b` sample of 74 bits (accounting for the 4-bit version and 2-bit variant fields that occupy 6 of the 80 trailing bits per RFC 9562). Session authenticity is carried by the MLS envelope signatures on `OutletStreamOpen` that references the session; `session_id` does NOT need to encode caller identity, and binding it to the DID actively harmed both the linkability property and the collision-reject property. The per-millisecond per-caller collision probability moves from ~2⁻⁴⁰ (round 5, DID-keyed) to ~2⁻³⁷ (round 6, 74-bit CSPRNG birthday bound at ~2¹⁸·⁵ concurrent opens/ms), still negligible.

- **`InterfaceSaltRotated` preimage + removal-event binding (BLOCKER-2).** Round 5's `InterfaceSaltRotated` event carried `new_ikm_local_sig: Ed25519Signature` with no registered preimage and no cryptographic link between the rotation and a qualifying admin-removal event. Consequences: (i) a current admin could fire rotations at any time, producing a covert churn channel (rotation cadence encodes signal); (ii) a signature under the accept-time `SCP-OUTLET-IKM-COMMITMENT-V1:` preimage could be replayed as a rotation signature since no preimage pinned the rotation context; (iii) no binding to `interface_id` meant a signature for one interface could be reused for another. Round 6 registers `SCP-OUTLET-IKM-ROTATE-V1:` in §9.18.2 with a preimage that binds `interface_id`, the ordered context pair, `epoch_local`, `new_ikm_local`, `trigger_removal_did`, and the new `removal_event_id: [u8; 32]` field on `InterfaceSaltRotated`. The verifier rejects a rotation whose `removal_event_id` does not reference a prior, valid admin-removal event (targeting `trigger_removal_did`, within the same or prior epoch) OR whose `removal_event_id` has already been cited by a prior rotation on the same interface. New slug `authorization.salt-rotation-unjustified` (`SCP-TOOL-6115`) carries the rejection. The separate domain separator from `SCP-OUTLET-IKM-COMMITMENT-V1:` prevents cross-preimage replay between accept-time and rotation-time signatures.

- **Admin-removal rotation TOCTOU closure (MAJOR-3).** Round 5's rotation semantics stated "rotated IKMs take effect at the next `OutletError` envelope emitted by either side" and "until both sides have rotated, the interface operates under the prior `hop_salt`." That admitted a race: between `RemoveMember` commit and the next error emission, the local side could emit an `OutletError` whose `source_chain` was still pseudonymized under the pre-rotation `hop_salt`, and the removed admin — who retains knowledge of the prior `(ikm_a, ikm_b)` — could deanonymize the hop. Round 6 makes removal+rotation atomic on the local side: `RemoveMember` carries a required `induced_rotations: Vec<InterfaceSaltRotated>` field, governance commits the rotations as sibling entries in the same MLS commit batch, and the `hop_salt` state machine transitions `PreRotation → Frozen → PostRotation` with no envelope emission permitted in the `Frozen` window. Buffered envelopes exceeding `ContextParams::outlet_error_buffer_max_secs` (new §9.18.B param, default 30s, range [5, 300]) are dropped with `governance.remove-member-buffer-overflow` audit, and the governance-removal timeout escalates. Peer-side `Frozen` starts on shared-member-bridged receipt and ends at the peer's own reciprocal rotation commit. `pipeline_wiring.rs` forbids a `RemoveMember`-admin handler from terminating without the induced rotations.

- **Per-outlet HMAC key orphans in-flight errors at re-registration (MAJOR-4).** Round 5 pinned `outlet_message_key` at registration acceptance, rotating it only at re-registration. The unstated consequence: in-flight `OutletError` envelopes signed under the prior registration's key fail `UnregisteredMessageKey` lookup at receivers after re-registration — a DoS surface and a correctness gap for cross-context error propagation that straddles a re-registration. Round 6 adds `registration_event_id: [u8; 32]` at tag 12 on every `OutletError` envelope (emitted unconditionally, no Option wrapper — same presence-oracle-closing rationale as `pad_nonce`). Receivers maintain a per-outlet bounded LRU (`registration_event_id → outlet_message_key`) with `MESSAGE_KEY_LRU_CAPACITY = 4` entries (new §9.18.A protocol invariant), oldest-first eviction on new registrations. Envelopes reference the registration under which they were signed; the receiver looks up the matching key in the LRU. Four entries × the 24h catalog-rotation dwell = 96h, which comfortably covers realistic cross-context propagation windows. Reserved tags for future extensions shift from 12+ to 13+.

- **Cluster detection 4th predicate + population-weighted floor (MAJOR-5).** Round 5's cluster-match count `k` used three predicates (context_id, creator_did, admin_set intersection). Round-5 text acknowledged residual risk: an attacker willing to burn fresh creator_did + fresh admin_set per peer context evaded detection. Round 6 adds predicate 4 — `capability_holder_set` intersection over the DIDs holding `outlet:offer:*`, `outlet:query:*`, or `outlet:call:*` at interface-acceptance time. An attacker who IS the cross-context invoker — natural for anonymity-set-reduction attacks, since the attacker is the one exercising the cross-context capability — is caught by predicate 4 even when creator and admin DIDs are rotated per context. Round 6 also replaces the round-5 flat `interface_base_cost_minimum` (currency-atomic-unit) with a population-weighted floor: `interface_base_cost_floor(ctx) = max(currency_atomic_unit, ceil(log2(ctx.member_count + 1)) × base_cost_scale)`. `base_cost_scale` is a new §9.18.B ContextParam (default: currency-dependent minimum meaningful fee, range [currency_atomic_unit, 1000 × currency_atomic_unit]). A 500-member context (upper MLS writer bound) pays 9 × scale per spam interface vs 1 × scale for a 1-member sybil — proportional to the anonymity-set-reduction potential. Residual risk shifts from "creator+admin DID churn" to "creator+admin+capability-holder DID churn," which costs more across three DID classes and is subject to the population-weighted escalator on the first same-cluster interface.

- **API MINOR fixes (api-design round 6).** `OutletError::new` adopts an options-object / keyword-only constructor across Python/TS/Kotlin (Swift retains labeled args); Python `OutletError` subclass is renamed `OutletProtocolError` to avoid colliding with MLS `ProtocolError`; `Credit` newtype across all four SDKs with a uniform `InvalidGrant` class under `OutletError` (replacing the per-language `ValueError`/`RangeError`/`IllegalArgumentException`/`OutletError.invalidGrant`); `CatalogKey` newtype shared between `MessageTemplate::try_new` and `OutletError::new`; `IkmCommitment` struct encapsulation replacing the loose `(context_a_id, context_b_id, epoch, ikm)` function-argument bundle. These are packaged into OUT-031 and the OUT-041/OUT-042 splits below.

- **OUT-041 / OUT-042 story splits (architecture + simplifier + alignment concurrence).** OUT-041 (13 files, 21 ACs) and OUT-042 (8 files, 21 ACs) each exceeded the `.docs/standards/prd.md` single-agent-single-iteration scope. Round 6 splits them into forward-only chains: OUT-041a (runtime key derivation + persistence), OUT-041b (constructor + UnregisteredMessageKey + LRU), OUT-041c (CatalogRotationTooFrequent validator), OUT-041d (bridges + SDKs + conformance + ratchet); OUT-042a (event struct fields), OUT-042b (crypto + domain separators SCP-OUTLET-IKM-COMMITMENT-V1 + SCP-OUTLET-IKM-ROTATE-V1), OUT-042c (admin-removal governance + atomic rotation + Frozen state + pipeline_wiring), OUT-042d (base_cost_scale + ContextParam + 4-predicate cluster detection + quadratic fee + interface-spam slug). Dependencies are forward-only; the 4-way splits preserve the completeness invariant (every round-6 acceptance criterion lands in exactly one sub-story).

No round-6 change touches the ratchet monotonicity invariant. All additions are expansions (new slugs under existing codes, new protocol invariants, new ContextParams, new event fields, new story splits) or replacements of unsound rules with sound ones (the round-5 DID-keyed session_id tail, the round-5 unregistered rotation signature preimage, the round-5 best-effort rotation timing, the round-5 registration-key-orphaning lookup rule, the round-5 3-predicate cluster-detection coverage, the round-5 flat cost floor). Pre-1.0 hard breaks remain hard breaks: pre-rename event logs fail verification, pre-migration UCAN tokens are rejected, pre-round-4 / pre-round-5 / pre-round-6 preimages are rejected.

### Round 7 adjustments (May 2026)

Round 7 closes a CRITICAL gap surfaced during the SCP-OUT-037 production-hardening review on top of the round-6 baseline.

- **Streaming `OutletCancel` MUST be Ed25519-signed by the invoker (CRITICAL).** Round 6's cancel handling specified the cancel-ack timer, the `cancel_ack_seq` recording, and the billing boundary, but did NOT require the cancel message itself to carry an authenticator. Consequence: any party who learned a stream's `request_id` (a 16-byte value visible to every relay hop and every shared-member observer) could forge an `OutletCancel` and force-terminate streams the invoker did not authorize — a low-cost, untraceable DoS on every active stream. Round 7 registers `SCP-OUTLET-CANCEL-V1:` in §9.18.2 with a preimage that binds `(context_id, outlet_id, request_id, next_seq, caveats_binding)`, requires the invoker's signature in `OutletStreamCancel.sig`, and routes verification failures to `OutletErrorClass::Authorization::AuthorizationFailed`. The runtime rejects an unsigned or wrongly-signed cancel before mutating any stream state — neither the cancel-ack timer arms nor `cancel_ack_seq` is recorded. Binding stream identity into the preimage closes cross-stream replay (a cancel signed for stream A cannot be replayed against stream B). The cancel uses the same pinned `invoker_pk` as credit grants — no new key material crosses the bridge boundary. The new `OutletStreamCancel` wire type is scoped to `crates/scp-protocol/src/context/outlets/stream.rs` (alongside `OutletStreamCredit`); the legacy `OutletCancel` lifecycle struct in `lifecycle.rs` is unchanged for non-streaming callers. No ratchet movement: this is a new authenticator on a previously-unauthenticated message, sound by addition.

- **Framework-emitted terminal chunks MUST be operator-signed (CRITICAL companion).** The dispatch pump's cancel-ack-timeout and credit-stall paths emitted `Error{terminal:true}` chunks with `sig: [0u8; 64]` placeholders, and `wrap_chunk` in the local-context invoke pipeline produced unsigned chunks. Per §5.4.5 every `OutletStreamChunk` reaching a wire boundary MUST verify under the per-context operator key — without this, a member receiving a synthetic terminal chunk has no cryptographic basis for the equivocation guarantee the round-3 chunk-signing rule was designed to provide. Round 7 wires the operator signing key through `OpenStreamParams` and `wrap_chunk`, and the dispatch pump signs every framework-emitted terminal chunk under the same `SCP-OUTLET-CHUNK-SIG-V1:` preimage as executor-emitted chunks. WASM keeps invoker-as-operator per ADR-034 §1 (single-process bridge); native bridges pass the operator key explicitly. No spec change to §5.4.5's signing rule — round 7 is the implementation closure of a rule that was already on the books.

Round 7 does not move the ratchet. Both changes are sound-by-addition fixes on top of round-6 invariants.

### Round 8 adjustments (June 2026)

Round 8 closes gaps surfaced during the SCP-OUT-037/038/039 streaming-remediation review on top of the round-7 baseline. All four changes are sound-by-addition refinements — no existing invariant is weakened.

- **Streaming signing is custody-injected and async (`StreamSigner` trait).** The round-7 closure threaded an `Arc<ed25519_dalek::SigningKey>` through `OpenStreamParams`, `SharedSessionState`, and the dispatch + invoke pumps. Holding the raw operator private key in runtime structs and signing synchronously is incompatible with the platform `KeyCustody` abstraction (ADR-006: private keys never cross the FFI boundary; custody signing is `async` / RPITIT and not object-safe). Round 8 introduces a `StreamSigner` trait (`async fn sign(&self, preimage) -> [u8; 64]` + `fn verifying_key()`) in `scp-runtime`, replaces every `Arc<SigningKey>` streaming field with `Arc<dyn StreamSigner>`, and makes the per-chunk signing path `async` end-to-end. The runtime composes the §5.4.5 preimage synchronously and awaits the signer for the signature only. An `InProcessStreamSigner` (test/WASM, operator==invoker per ADR-034) and custody-backed adapters (native bridges) both implement the trait. No preimage or wire change — the bytes signed are byte-identical to round 7; only the signing *mechanism* is abstracted. Sound by addition.

- **`protocol.context-closed-mid-stream` Protocol-class terminal cause (new closed-enum variant).** A context evict/leave race during an active stream previously had no distinct terminal cause; the framework re-check loop conflated it with `RevokedMidStream` (Authorization class). That writes a false audit signal (the invoker's credential was never revoked) and hands an adversary a DoS lever (an operator able to trigger teardown could synthesize a revocation-class behavioral record against an arbitrary in-flight invoker). Round 8 adds a new closed `TerminateReason::ContextClosedMidStream` variant → slug `protocol.context-closed-mid-stream` → code `SCP-TOOL-6101` (`CODE_PROTOCOL_SESSION`, Protocol band). Context teardown takes precedence over revocation when both are observable in the same re-check tick. New slug under an existing code band; new variant in an already-closed enum. Sound by addition.

- **`protocol.stream-already-closed` Protocol-class control-plane lifecycle guard.** A control-plane call (`grant_credit` / `cancel` / `terminate`) invoked after the target stream has already reached its terminal chunk previously had no distinct rejection cause; without a dedicated slug it would naturally collapse onto the Authorization-class `SCP-TOOL-6110`, writing a false authorization-denial audit signal for what is actually a session-lifecycle violation (the stream session no longer exists to act upon). Round 8 maps this condition to slug `protocol.stream-already-closed` → code `SCP-TOOL-6101` (`CODE_PROTOCOL_SESSION`, Protocol band), sharing the band with `protocol.unknown-session` and `protocol.context-closed-mid-stream` — all three are Protocol-class session-lifecycle conditions keyed on the absence/terminal-state of a stream session, not on the invoker's authorization. It MUST NOT collapse onto the Authorization class (`SCP-TOOL-6110`): a post-terminal control-plane call is a lifecycle error regardless of whether the caller's credential is valid. The SDK lifecycle-guard surface (`StreamAlreadyClosed`) maps to this slug. New slug under an existing code band. Sound by addition.

- **Node-level concurrent-pump ceiling (per-instance, ADR-048).** The three round-4 per-context admission caps bound a single context's fan-in but place no aggregate bound on a node's total concurrent pump count across many contexts. Round 8 adds a per-instance `outlet_stream_pump_semaphore` (`tokio::sync::Semaphore`) on the `ContextManager`, sized from a new `max_concurrent_outlet_stream_pumps` builder/config field (default 4096, range [1, 65536]). It is per-instance state (NOT a static/global — `check-no-mutable-globals` would catch a global), acquired AFTER all per-context gates pass, and held for the exact lifetime of the pump task (released on normal close, terminal, cancel-ack, or panic). On saturation the open is hard-rejected with `OutletErrorClass::Execution::StreamCapExhausted` → slug `execution.stream-cap-exhausted` → code `SCP-TOOL-6131` (`CODE_EXECUTION_CREDIT`, shared Execution resource-exhaustion band). New per-instance state + new slug under an existing code band. Sound by addition.

Round 8 does not move the ratchet. All four changes are sound-by-addition refinements (new trait abstraction over an unchanged preimage, new closed-enum variant + new slugs under existing code bands, new per-instance ceiling) on top of round-7 invariants. Pre-1.0 hard breaks remain hard breaks.
